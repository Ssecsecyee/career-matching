# React 로컬 화면

2026-10-28. 화면 구현과 정적 빌드가 완료됐다. 프론트 요청/링크 테스트 2개 및 로컬 HTTP 화면 제공·API 프록시·401 인증 차단 확인을 통과했다. 이 검증에서 Bedrock 호출·DB 쓰기는 없었다. AWS에 업로드한 상태는 아니다.

## 실행

MySQL은 기존 compose.dev.yaml로 실행 중이어야 한다. 터미널 두 개를 사용한다.

### CMD 1: API

```cmd
conda activate AWS_project
cd /d C:\AWS_project\career_matching\app\backend
python dev.py
```

### CMD 2: React

```cmd
cd /d C:\AWS_project\career_matching\app\frontend
npm run dev
```

브라우저: http://127.0.0.1:5173

첫 화면에 넣을 테스트 접속 코드는 app/backend/.env의 CHAT_API_TOKEN 값이다. AWS 키나 DB 비밀번호가 아니다. 프론트 소스·VITE 환경변수에 넣지 않는다. 화면에서 입력한 코드는 메모리에만 있으며 새로고침하면 다시 입력한다. 클라이언트 식별 토큰도 탭의 메모리에 두므로 새로고침 이후 기존 대화 자동 재개는 아직 제공하지 않는다.

## 시나리오

1. 접속 코드 입력 → 기술스택 MySQL로 검색.
2. 공고 하나 선택 → 원문 자격요건과 Bedrock 질문 확인.
3. 모름 → 자격요건 질문 유지, 미충족 → 보완 조건 표시, 충족 → 우대조건으로 이동.
4. 우대조건 답변 → 원문 근거와 사용자 진술 기반 결과 확인.
5. 문장으로 검색 탭은 Bedrock 검색 계획 호출도 사용한다.

DB 검색 자체는 모델을 호출하지 않지만 공고 선택·다음 질문 생성과 자연어 검색에는 실제 Bedrock 비용이 발생한다. 503은 10초 후 사용자가 다시 확인 버튼을 선택해야 재시도한다. 통신 실패 시 같은 request_id로 결과를 다시 확인하고, 명확히 실패한 모델 호출의 재시도는 새 request_id로 구분한다.

상태 unknown 공고를 검증용으로 표시하며 모집 중으로 단정하지 않는다. 보충 설명은 사용자 진술로 기록된다. 보충 설명에 대한 자유 대화형 학습 안내, 조건 항목별 판정, 교육 추천은 아직 없다. 현재 질문은 자격요건/우대조건 원문 목록 항목 단위이며 AND/OR 관계는 보존한다. API는 개발용 공유 토큰 인증이며 정식 사용자 계정 인증을 대체하지 않는다.

## 빌드

```cmd
npm test
npm run build
```

산출물은 dist/이다. AWS에는 이 폴더만 정적 파일로 올리고, 백엔드 .env와 원본 데이터는 포함하지 않는다. 배포 시 /api/*를 API Gateway로 전달하는 CloudFront 구성을 별도로 연결해야 한다. 현재 vite proxy는 로컬 개발 전용이다.

## 모델 일시 오류와 명시적 재시도

Haiku가 503을 반환하면 같은 모델 재시도와 Sonnet 재시도 버튼을 표시한다. Sonnet은 사용자 선택 시에만 model_tier=main으로 요청하며 backend/.env의 MODEL_ID를 사용한다. 기본은 FAST_MODEL_ID이다. 임의 모델 ID를 클라이언트에서 받지 않는다. Sonnet 선택 후 같은 페이지의 후속 요청도 해당 모델을 사용하며 비용 차이를 표시한다. 자동 모델 전환은 하지 않는다. 백엔드를 python dev.py로 실행하면 src의 Python 코드와 .env 저장 시 자동으로 재시작된다. 파비콘도 추가했다. 이번 수정에서 실제 모델 호출은 없었다.



현재 화면: 자연어 입력으로 검색을 시작하고 대화 안의 공고 카드와 조건 답변 버튼으로 이어집니다. Sonnet만 사용하며 모델 선택 메뉴는 없습니다. Enter는 검색 전송, Shift+Enter는 줄바꿈입니다. 조건 확인 중 입력한 설명은 답변 버튼을 누를 때 함께 저장합니다. 새 대화는 화면 상태를 초기화하며 기존 DB 기록을 삭제하지 않습니다.

동일 대화 내 재검색은 서버의 사용자 기억을 유지한다. 기억한 경험 수정으로 정정하면 이전 조건 답변을 무효화하고 다시 확인한다. 입력창 위에서 원문 발언을 근거로 정리한 기억을 열어볼 수 있다. 미확인 답변은 다음 항목으로 넘어간다. 새 대화와 새로고침 후 자동 기억 재개는 구분한다.
