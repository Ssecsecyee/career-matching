# AWS 동일 EC2 내부 검색 배포 준비

## 2026-10-29 확인 상태

현재 EC2는 t4g.small/arm64, OS 보고 메모리 1840MiB, 사용 가능 992MiB, swap 0이다. /opt/career 디스크 여유는 약 27003MiB, MySQL 컨테이너 사용은 약 309MiB, career-worker는 active다. Elasticsearch 공식 9.5.5 이미지의 linux/arm64 지원도 확인했다. 측정 시점 값이며 계속 변할 수 있다.

2GiB 메모리 한도의 Elasticsearch를 현재 여유에 추가하는 배포는 보류했다. 서버 확장이나 서비스 중단은 실행하지 않았다. 읽기 전용 SSM 점검만 실행했다.

## 확정한 연결 구조

같은 EC2의 백엔드/색인 작업자 → 127.0.0.1:19200 → Docker Elasticsearch. 외부 검색 포트·보안 그룹 inbound 규칙은 추가하지 않는다. 초기에는 사용자 합의대로 엔진 인증을 생략한다. 내부 접근 가능한 프로그램은 엔진을 수정할 수 있다는 한계가 있으며, 향후 서버 분리 시 인증·HTTPS를 추가한다. Elastic Cloud 가입과 새로운 AWS 액세스 키는 필요하지 않다.

compose.aws.internal.yaml은 AWS 단일 호스트용 준비 파일이다. 루프백 바인딩, Nori, 별도 영속 볼륨, 2GiB 메모리 제한/512MiB 힙, 재시작 정책과 로그 용량 제한을 포함한다. 인증 생략 구성의 사용 범위를 외부 서버로 확대하지 않는다. node.store.allow_mmap=false로 mmap 대신 사용하는 초기 구성이라 sysctl을 자동 변경하지 않는다. ARM에서 이미지를 실제 빌드하고 검사하는 단계는 배포 시 필요하다.

## 배포 전 남은 조건

1. 기존 EC2를 최소 4GB급으로 확장하는 후보의 차액·점검 시간 확인. 확장 시 서버 중지/재시작과 IaC 일치가 필요하다. EC2 교체나 기존 MySQL 볼륨 삭제를 하지 않는다.
2. DB 백업과 복구 경로·대화 작업자 중단/재개 계획 준비.
3. 대상 호스트에서 host_preflight.py의 메모리·디스크 게이트 통과. 이는 보수적 시작 기준이며 부하 검증 통과가 아니다. 4GB급도 여유 부족이면 재검토한다.
4. 엔진 설치·재시작·Nori 확인 후 서버의 실제 MySQL 803건/교육 데이터를 읽어 별도 색인을 구성한다. 실제 건수는 배포 당시 다시 확인한다.
5. 소량 검색·DB 확인·실패 시 MySQL 복귀 시험 후 백엔드 검색 선택을 변경한다. 엔진이 준비되기 전에 선택 설정을 바꾸지 않는다. Outbox 자동 소비자는 아직 별도 구현이 필요하다.

## 비용 조회 제한

교육 계정의 Organizations SCP가 pricing:GetProducts를 명시적으로 거부해 Price List API로 서울 t4g.small/medium/large 가격을 검증하지 못했다. 이를 EC2 변경 권한도 없다는 뜻으로 해석하지 않는다. AWS Pricing Calculator/관리자 확인 등 별도 경로로 확장 차액을 확인해야 한다. 검증하지 않은 월 금액을 확정 견적으로 기록하지 않는다.

이번 준비로 새 EC2·디스크·검색엔진을 운영에 생성하거나 실행하지 않았다. 대규모 부하 시험은 합의대로 고용24 파이프라인 단계에 진행한다.
