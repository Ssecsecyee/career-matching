# 코드 업데이트

기존 EC2/MySQL과 대화 데이터를 보존하고 코드만 교체합니다. 스키마 변경에는 사용하지 않습니다.
현재 배포 정보는 로컬 `infra/.build/backend-state.json`에서 읽습니다.

## 이번 변경
- 입력마다 Sonnet이 일반 대화 또는 공고 검색을 한 번의 호출로 구분합니다.
- 새로 선택한 공고는 자격요건 전체, 우대사항 전체를 각각 원문 체크리스트로 제공합니다.
- 조건 확인과 다음 조건 표시에는 모델 호출이 없습니다. 미선택은 미확인으로 저장됩니다.
- 원문 조건은 삭제하거나 의미를 변경하지 않습니다. 일반 대화는 진행 중인 체크리스트를 유지합니다.
- 대화당 모델 호출 상한 12회와 기존 세션 제한은 유지합니다. 이전 버전의 한도 소진 세션은 새 대화로 시작하세요.
- 자유 서술을 여러 조건의 충족 여부로 자동 판정하는 기능은 이번 변경에 포함하지 않습니다.

## 사용자가 CMD에서 실행
다른 사용자의 대화가 없는 시간에 진행하세요. 작업 프로그램이 잠시 재시작됩니다.

```cmd
cd /d C:\AWS_project\career_matching
python infra\update_backend.py build
python infra\update_backend.py apply --confirm-maintenance
python infra\update_backend.py result
```

result가 InProgress면 잠시 후 result만 다시 실행합니다. apply는 재실행하지 않습니다.
Success 및 worker_updated 확인 후:

```cmd
python infra\backend.py inspect
python infra\backend.py inspect-result
python infra\hosting.py publish
```

웹을 Ctrl+F5로 새로고침하고 새 대화에서 인사 → 공고 검색 → 공고 선택 → 필수조건 일괄 저장 → 우대조건 저장을 확인하세요.

## 보존과 복구
- DB SQL, 데이터 디렉터리, 시크릿과 네트워크는 변경하지 않습니다.
- S3에는 별도 code-releases 경로를 사용해 최초 설치 파일을 보존합니다.
- 인스턴스는 15분 유효 서명 URL로 코드 ZIP을 내려받습니다. 해당 링크는 출력하지 않습니다.
- 코드 해시와 파일 경로를 검사하고 컴파일한 다음 교체합니다.
- 이전 코드가 /opt/career/releases/<시각>/previous-app에 남습니다. 재시작 실패 시 이전 코드 복원을 시도합니다.
- Lambda는 새 요청 검증을 위해 먼저 갱신하며 이전 ZIP은 로컬 빌드 폴더의 previous-api.zip에 보관합니다. 작업 서버 실패 시 Lambda는 새 검증 코드로 남지만 기존 요청도 허용합니다.
- 프로세스 기동 검사만 자동 수행합니다. Bedrock 호출 및 실제 웹 동작은 배포 후 사람이 확인합니다.
- 중단된 요청은 큐 재처리 대상이 될 수 있으므로 진행 중 대화가 없는 시간에 업데이트하세요.


## 상담 근거 보완 (2026-10-28)
- 상담에는 선택 공고, 전체 조건별 자기 평가, 필수/우대별 충족·미충족·미확인 집계를 전달합니다.
- 사용자의 원문 발언은 체크리스트 및 AI 발언과 별도로 최근 40개/12,000자 범위에서 보존합니다. 발언별 모델 입력은 최대 1,200자이며 원본 메시지는 DB에 남습니다.
- 이전 버전의 세션은 같은 세션의 최근 사용자 요청 80개에서 원문을 읽어 기억 형식을 보완합니다. 다른 사용자·새 세션의 기록을 섞지 않습니다.
- 입력이 길면 조건 텍스트와 보충 설명을 줄이고 모든 평가 항목·구분·상태와 집계는 유지합니다. 전체 상담 입력은 60,000자 상한을 적용합니다. 무제한 전체 대화 복원 기능은 아닙니다.
- 모순된 기술 경험과 자기 평가를 함께 보여주고 모델이 확인 질문하도록 지시합니다. 자동으로 어느 한쪽을 사실로 확정하지 않습니다.
- 일반 대화 응답은 이전 검색 실패/공고 목록 표시 상태와 분리합니다. 진행 중 조건 확인은 유지합니다.
- 자연어 입력의 대기 문구는 ‘답변을 준비하고 있어요’로 통일하고 공고 선택·답변 저장은 해당 작업을 표시합니다.
- 기존 비용 상한과 DB 구조는 변경하지 않습니다. 모델의 최종 문장 품질은 실제 웹 재시험이 필요합니다.

재시험: 신입·React 기초 경험 말하기 → 공고 선택 → 필수 일부 미충족 및 우대 응답 → ‘지금까지 뭐가 부족한지 정리해줘’ → 필수조건과 초기 경험을 함께 언급하는지 확인 → ‘React는 가능하다고 했잖아’로 모순 확인 → 검색 실패 후 인사 시 검색 실패 문구가 반복되지 않는지 확인.
