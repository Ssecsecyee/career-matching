# 관리자 문맥·의도 기록 조회 계획

기준일: 2026-11-02. 구현 전 계획. 이 문서를 먼저 커밋·푸시하고 이후 코드를 별도 커밋한다.

## 목적과 사유

intent_decisions는 저장되지만 현재 관리자 화면에서는 조회할 수 없다. 관리자가 요청별로 당시 문맥 → 모델 판단 → 검증 결과 → 실제 실행·오류 → 모델 호출을 연결해 분류 오류와 실행 오류를 구분하도록 한다. 기존 관리자 토큰 인증을 사용하고 일반 사용자 토큰은 DB 접근 전에 거부한다. SQL 실행·수정·삭제 기능은 추가하지 않는다.

## 화면

관리자 페이지에 ‘문맥·의도 기록’ 전용 구역을 추가한다. 최초에는 조회 버튼으로 목록을 연다. 세션 ID·요청 ID·검증 상태·실행 상태로 필터하고 25건 단위로 탐색한다. 생성 시각·대상/행동·직접 버튼/모델·성공/실패·오류·정책 버전을 목록에 표시한다. 모델 이름·상태·입출력 토큰·지연은 기존 model_invocations와 연결한다.

목록은 원본 출력과 문맥을 포함하지 않는다. 선택한 1건의 상세를 별도 조회해 문맥/검증된 판단/실행 결과를 보여준다. 분류 원문은 별도 ‘원문 보기’ 요청에서만 조회한다. JSON은 텍스트로 렌더링하고 잘린 필드는 명시하며 HTML로 실행하지 않는다. 조회하는 동안 필터·페이지·선택이 혼동되지 않도록 적용된 조건과 선택한 기록을 구분한다.

## API·DB

기존 관리자 action에 intent_rows / intent_detail 읽기 작업을 추가한다. ID·상태·offset·원문 포함 여부를 허용 목록과 타입으로 검증하고 값은 SQL 매개변수로 전달한다. 임의 테이블명·컬럼명·SQL 입력은 받지 않는다. 만료되지 않은 기록만 조회하고 원문에는 기본 마스킹을 다시 적용한다. 상세는 응답 크기를 제한하며 생략/잘림을 표시한다.

기존 관리자 요약과 일반 테이블 탐색은 변경하지 않아 새 테이블 권한이 없더라도 기존 로그인·요약을 깨뜨리지 않는다. 새 화면 배포 전 관리자 DB 계정의 intent_decisions SELECT 권한을 확인해야 한다. runtime 계정의 쓰기 권한을 관리자 화면에 전달하지 않는다. DB 컬럼 변경·새 테이블 추가는 필요 없다.

## 검증

- 일반 접속 코드로 새 조회 작업을 요청하면 DB 접근/큐 등록 전에 403.
- 잘못된 UUID·상태·offset·include_raw와 임의 SQL/필드 거부.
- 목록에는 raw_output/context_snapshot 미포함. 원문은 명시 요청에서만 반환.
- 목록 필터·페이지·정렬 및 세션/요청·모델 호출 연결 검증.
- 상세 없는 ID/만료 기록은 404. 마스킹·응답 크기·잘림 표시 검증.
- 프론트 필터 계약·목록/상세 표시·텍스트 이스케이프 검사 및 빌드.
- 기존 관리자 숨김/복구·요약 및 대화 기능 회귀 검사.

이번 요청은 계획 MD 푸시 → 구현/로컬 검증 → 구현 푸시까지다. AWS 배포·관리자 DB 권한 변경은 별도 단계로 기록한다.
