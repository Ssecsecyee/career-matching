# 운영 기준

수정일: 2026-10-28. 제안 주기·예산은 운영 전 확정해야 한다.

## 최초 수집과 보강

기존 상세 원본 재사용 가능성을 먼저 점검한다. 빠진 섹션만 재수집하고 필드별 누락 사유를 남긴다. 최초 전체 적재 후 변경분 수집으로 전환한다. 허용 범위·요청 제한·재시도 간격을 출처별 설정으로 관리한다.

## 주기적 동기화

원본 출처가 웹훅을 제공하지 않으면 실시간 감지를 보장하지 않는다. 초기 제안은 몇 시간 간격의 목록 확인과 하루 한 번 전체 대조이며, 출처 허용 범위와 데이터량으로 확정한다.

목록 → 신규/변경 후보 → 상세 확인 → S3 원본 → 검증 → DB upsert와 Outbox 기록 → 전달 → Elasticsearch 갱신.

목록에 수정 시각이 없으면 알려진 활성 공고 상세도 순환 확인한다. 목록에서 한 번 누락됐다는 이유로 삭제하지 않는다. 명시적 마감, 마감일, 반복 확인 결과를 구분한다. 수집 실패를 전체 마감으로 처리하지 않는다.

## DB와 색인 일관성

DB를 기준으로 삼는다. 안정적 ID, 멱등 처리, 단조 증가 버전, 역순 이벤트 방지, 항목별 실패 재시도와 DLQ를 둔다. Bulk 요청은 HTTP 성공만 보지 않고 문서별 실패를 검사한다. 전송 성공과 검색 노출 완료를 구분한다. 전체 재색인과 불일치 대조 절차를 마련한다.

## 모델 비용

고정 2회 호출을 보장하지 않는다. 검색 계획, 추가 질문, 답변 해석, 최종 설명별 입력·출력 토큰과 지연을 기록한다. 턴별·세션별 호출 수, 누적 토큰, 출력 상한, 수정 재시도를 제한한다. 선택 공고와 필요한 섹션·프로필 요약만 전달한다. 후보 선택을 통한 입력 절감 효과를 실제 측정한다.

## 관측과 복구

수집 성공률, 항목 완전성, 마지막 성공 수집 시각, DB 버전, 색인 버전, 갱신 지연, 실패 큐, 모델 비용을 기록한다. 검색엔진 장애와 결과 없음을 구분한다. 모델 실패 시 근거 없는 설명을 생성하지 않는다. 저장된 세션으로 재개하고 질문 중복을 막는다.

## 보안·보존

개인정보와 사용자 답변을 최소 저장한다. 세션 소유권·만료·삭제 정책을 정한다. 문서 내부 지시문은 데이터로 취급한다. 원본과 파생 데이터의 보존·재배포 범위를 출처별로 기록한다. 로컬 .env를 문서·로그·공유 저장소에 복사하지 않는다.

## 현재 로컬 환경

기존 Docker 프로젝트명과 볼륨은 유지한다. 기존 경로와 새 workspace 경로를 junction으로 연결해 호환한다. 임시 Cloudflare 주소의 재시작 후 유효성은 재점검해야 한다. 로컬 DB/API의 과거 성공 기록은 현재 실행 보장이 아니다.


## 대화·근거·캐시 저장 보완 (2026-10-28)

DB에 대화·사용자 진술·판정 근거·실제 모델 호출 기록과 만료형 응답 캐시를 분리한다. 만료 기간은 미정이며 운영 전 결정한다. 만료 조회 제외와 별도 삭제 작업을 함께 구현한다. 캐시 적중 시 모델 비용 중복 집계 금지. 개인정보는 사용자 범위로 격리하고 세션 삭제 시 종속 기록도 삭제한다. Bedrock 캐시 사용량이 미제공이면 NULL로 기록한다. 보존 정책 없는 S3 장기 복사를 자동 실행하지 않는다.

## 로컬 MySQL 대화 검증

세션 임대 잠금·사용자 격리·만료 조회 차단·실패 호출 기록·원문 근거 저장·응답 재전송 캐시를 구현했다. 현재 캐시는 동일 요청 재전송용이며 새 질문에 대한 의미 캐시는 아니다. 세션별 12회 모델 호출 예산을 적용한다. 로컬 준비 도구의 24시간 보존 설정은 운영 전 확정해야 한다. 만료 삭제는 cleanup_chat.py 별도 실행 또는 스케줄이 필요하다.


## 2026-10-28 로컬 대화 기억 구현

메모리 입력은 최근 발언 6개/6,000자, 사용자 정보 16개, 최근 조건 답변 4개로 제한한다. 질문 호출 출력 상한은 1,024토큰이며 세션 모델 호출 제한 12회는 변경하지 않았다. 모델의 사용자 정보 인용은 실제 발언과 대조한다. Bedrock 프롬프트 캐시는 미적용이다. 경험 정정은 현재 확인 결과를 무효화하며 공고 버전이 다르면 기존 확인을 재사용하지 않는다.


## 체크리스트 및 일반 대화 업데이트
새 웹은 공고 선택에 `grouped: true`를 보내고 `answer_batch`로 조건별 명시적 답변을 저장합니다. 일반 대화와 검색은 Sonnet 라우터에서 구분합니다. 기존 모델 호출 상한은 유지하며 상세 배포·제한사항은 [코드 업데이트 안내](../infra/UPDATE.md)를 참고합니다.
