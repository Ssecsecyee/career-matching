# AI 공고 조건 구조화·질문 선정·검색 반영

상태: condition-review-v2 구현·AWS 표본 반영 완료 / 사용자 질문 선정·순위 보강은 비활성
기준일: 2026-11-03

## 데이터 경계

job_postings는 원문 기준 데이터다. 원문이 있는 SQL을 AI 결과로 덮어쓰지 않는다. Bedrock 후보는 job_condition_review_drafts에 격리하고, 원문·의미 검토를 거쳐 승인된 결과만 job_condition_reviews와 search_outbox에 기록한다. ES는 승인 분류의 검색 사본이며 원본이나 사용자 역량 판정 기준 DB를 대체하지 않는다.

## 추출 계약

서버가 조건 ID와 줄/위치별 part_id를 생성하고 모델은 모든 ID를 한 번씩 반환한다. 원문 조각의 start/end와 quote는 서버가 재구성하며 조각을 합치면 원문과 같아야 한다. 각 조각의 terms는 해당 조각에 연속으로 존재하는 정확한 발췌다. 논리 트리의 atom/all/any/unresolved와 평면 terms를 분리해 긴 기술 목록이 트리 자식 수 때문에 누락되지 않도록 한다.

Bedrock Converse의 강제 도구 입력을 사용한다. 공고당 조건 수에 따라 여러 묶음으로 호출하고 각 호출에 4096 출력 토큰 상한을 둔다. 모든 묶음의 형식·ID·원문 연결 검증이 성공해야 전체 결과를 반환한다. 한 묶음 실패를 빈 조건이나 부분 성공으로 변환하지 않는다. 실패까지 사용량을 집계한다.

reference는 질문 대신 안내할 원문이며 사용자 충족 판정이 아니다. ask/review는 질문 대상이다. 주관적 성향이라는 이유로 기술 요건을 숨기는 모순을 차단한다. 쉼표·슬래시·예시 나열을 자동으로 AND/OR로 확정하지 않는다. 학위·경력·면허를 교육 수료로 대체하지 않는다. 서버 계약 검증이 의미 정확도 검증을 대신하지 않는다.

## 대상 선정과 재사용

MySQL의 모집 상태·마감일로 노출 가능한 공고만 실제 모델 대상이며 호출 직전에 다시 확인한다. ES에 없다는 이유만으로 마감이라고 판단하지 않는다. 마감 표본 재현은 오프라인 테스트로 한다. 조건 해시와 현재 정책/파서가 같은 승인 결과는 재사용하고 조건/정책 변경 시 새 후보를 만든다. 과거 분류와 세션 답변은 유지한다. 자동 대량 재분류 스케줄은 설치하지 않았다.

## 승인과 ES 동기화

승인은 후보 해시와 모든 조건에 대한 원문 완전성·논리 보존·라벨 확인 메모에 결합된다. 검증 대기 상태에서는 이벤트가 없다. 승인 결과와 r:<review_id> 이벤트를 같은 트랜잭션으로 저장하고, 소비자는 최신 원본과 같은 조건 해시·정책의 분류만 색인한다. 원문 source_version을 분류 때문에 올리지 않는다. 마감 공고는 승인 이력이 존재하더라도 검색에 다시 노출하지 않는다.

ES에는 필수/우대·분류·이유·원문·평면 atoms·원문 조각·논리를 보관한다. source_parts와 logic은 실행하지 않는 보존용 객체다. 기술 terms는 관련성 보강 힌트이며 자격 충족 필터나 자동 합격 판단이 아니다. 미분류 자료도 기존 태그·본문 검색을 유지한다.

## 현재 운영과 한계

검토한 공고 3개·조건 32개가 승인 저장됐다. 노출 가능한 2건·조건 22개는 ES 대조를 통과했고 1건은 마감으로 제외됐다. 이 표본은 에이전트 원문 대조와 4개 항목 보정을 포함한다. 독립적인 사람 정답 기반 정확도나 전체 자동 추출의 무오류를 입증하지 않는다. 질문 선정과 순위 보강은 false를 유지한다.
