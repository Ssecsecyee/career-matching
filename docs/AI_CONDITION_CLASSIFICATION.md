# 공고 조건과 질문 정리의 역할

현재 방향: SQL 기준 공고 선택 시 처리 / 로컬 구현·검증 완료, AWS 미배포
기준일: 2026-11-03

## 현재 서비스 경로

신규 공고는 기존 검증 → MySQL 원문/버전 저장 → Outbox → ES 본문 검색으로 처리한다. 수집 때 전 공고를 AI로 미리 분류하지 않는다. 사용자가 ES 검색 결과에서 공고를 선택하면 MySQL 최신 상세를 읽고 서버 코드가 조건 항목과 위치를 파싱한다.

ENABLE_ON_DEMAND_CONDITIONS=true일 때만 질문 정리를 추가한다. 승인된 동일 원문 분류가 있으면 재사용하고, 없으면 질문 전용 SQL 캐시를 읽는다. 캐시가 없을 때만 선택 공고의 질문 분류/이유를 모델에 요청한다. 원문·기술 목록·논리를 모델이 새로 추출하는 작업은 이 경로에서 요청하지 않는다.

## 데이터와 검증 경계

job_postings는 기준 원문이다. job_condition_question_cache는 공고 ID·조건 해시·질문 정책별 공유 캐시이며 개인 경험이나 조건 답변을 보관하지 않는다. 원문 구간은 서버가 재구성하고 AI는 ask/reference/review와 짧은 이유만 반환한다. source_contract_only는 구조/ID/원문 연결 검증 수준이며 독립적인 사람 의미 검증이나 합격 판단을 뜻하지 않는다.

대기 테이블 job_condition_review_drafts는 별도 오프라인 검토 영역이다. pending 후보를 자동 승인하거나 선택 캐시로 쓰지 않는다. 승인 테이블 job_condition_reviews와 기존 r: Outbox는 검토된 검색용 분류의 이력이다. 과거 표본은 보존하지만 새 질문 캐시 저장은 승인 테이블이나 ES를 갱신하지 않는다.

## 비용과 실패 처리

작은 공고는 한 묶음으로 처리하고 긴 공고만 제한적으로 분할한다. 실제 호출마다 기존 model_invocations 기록과 세션 호출 한도를 적용한다. 동일 공고 동시 선택은 이름 잠금으로 중복 호출을 막는다. 같은 조건/정책의 결과는 다른 사용자도 재사용하며, 조건이 바뀌면 새로 처리한다.

마감·원문 변경을 호출 전후/저장 시 확인한다. 형식 오류·누락·캐시 실패·잠금 사용 중·시간/호출 예산 소진은 원문 문답으로 복귀한다. 원문이 바뀐 선택은 재선택을 요구한다. 기존 사용자 답변은 재분류하지 않고 질문 중단 선호를 지킨다.

현재 전량 백필은 보류 상태다. 운영의 선택 시 생성·질문 생략과 ES 순위 보강은 아직 켜지 않았다. [선택 시 처리 계약](ON_DEMAND_CONDITION_REVIEW.md), [운영 절차](AI_CONDITION_RUNBOOK.md)를 따른다. 과거 전량 추출 방식의 표본·보정·비용은 [v2 검증 기록](AI_CONDITION_V2_VERIFICATION_20261103.md)에 남긴다.
