# 저장 답변 조회·선택 수정 개선

기준일 2026-11-02. 기존 ‘기억한 경험 수정’은 이전 답변을 보여주지 않고 정정 문장만 입력받으며 현재 조건 답변 전체를 초기화한다. 사용자가 무엇을 고치는지 확인하기 어려워 현재 대화의 저장 내용을 먼저 조회하고 조건 1개만 정정하는 경로를 추가한다.

## 범위

- 현재 소유자의 유효한 세션에서 직접 말한 내용과 현재 선택 공고의 저장 조건 답변·보충 설명을 조회한다. 다른 세션이나 이전에 선택했던 모든 공고의 전체 이력 탐색은 이번 범위가 아니다.
- 조건은 10개씩 페이지 조회하며 원문·필수/우대·충족/미충족/모름·미답변을 구분한다. 미답변은 수정 대상으로 취급하지 않는다.
- 선택 수정은 condition_id와 저장 상태 해시를 검증해 오래된 화면의 덮어쓰기를 막고, 서버에 저장된 원문·버전만 사용한다. 다른 답변은 유지한다.
- 원래 대화·근거는 삭제하지 않고 정정 전후 값은 새 응답 기록 및 근거 기록으로 추가한다. 최신 세션 상태·요약·재사용 기억만 갱신한다. 모름으로 바꾸면 해당 조건의 재사용 확정을 해제한다.
- 조회·선택 수정은 모델을 호출하지 않는다. 기존 세션 소유자·만료·요청 ID 재사용·감사 기록 경로를 유지한다. DB 컬럼/테이블 추가 없음.
- 기존 경험 전체 정정은 별도 화면에서 ‘이전 조건 답변 재확인’ 안내를 명시한다.

## 검증

조회의 모델/검색 호출 0회, 타 소유자 접근 거부, 선택 1개만 변경, 원문·다른 답변 보존, stale 해시 409, unknown 기억 해제, 정정 이력·근거 append, 현재 문답 진행 유지, 프론트 조회·페이지·수정 입력·경고·텍스트 렌더링·응답 재사용을 확인한다. AWS 배포와 운영 데이터 변경은 별도다.

## 로컬 구현 결과

‘내 답변 보기·수정’ 패널을 추가해 현재 공고의 원문 조건·자기평가·보충 설명을 10개씩 조회한다. 최근 직접 발언도 별도로 확인할 수 있다. 현재 대화·선택 공고 범위를 명시하며 다른 세션의 전체 기록이나 이전 모든 공고의 문답 복원 기능은 아니다.

review_answers와 revise_answer는 소유자/만료가 검증된 기존 세션에서 직접 실행하며 모델 호출이 없다. 수정 요청에 원문·공고 ID를 받지 않고 condition_id와 저장 상태 해시로 검증한다. 선택한 답변만 바꾸고 다른 답변·질문 진행·원문 묶음 안내를 유지한다. 미답변/레거시 연결 불가 항목은 임의로 수정하지 않는다. 수정 중 페이지 이동은 입력 취소·저장 후 가능하다.

최신 checks·요약·확정 재사용 정보는 갱신하고 파생 facts 캐시는 무효화한다. 원래 chat_messages와 recommendation_evidence는 덮어쓰지 않으며, 정정 전후 값은 새 응답 기록에, 수정된 자기평가는 새 근거 기록에 추가한다. unknown으로 변경하면 해당 조건의 재사용 확정을 해제한다. 과거 답변을 수정하더라도 당시 공고 버전 기준이며 현재 모집 상태를 새로 검증한 것은 아니다.

경험 전체를 문장으로 정정하는 기능은 별도 접힘 구역으로 분리했고, 현재 공고 답변을 초기화하고 재확인한다는 안내를 제출 버튼 앞에 표시한다.

실제 로컬 독립 MySQL(13339)에서 전체 335개 중 333개 통과·다른 환경 의존 2개 제외. 정정 전후 근거 append, 원문 일치, 요청 재전송 시 중복 미생성, 타 사용자 조회 차단, 모델 호출 0회를 확인했다. 프론트는 35개 통과·빌드 성공. 운영 DB 변경·AWS 배포·유료 모델 호출·Git 커밋/푸시는 수행하지 않았다.
