필수 이후 선택은 새 웹이 select.assessment_checkpoint=true를 보낼 때 활성화해 기존 열린 세션·구형 클라이언트의 진행을 보존한다. 실제 원문 조건·자기평가를 삭제하지 않는다. 교육 선호는 확인된 선호와 저장 과정의 delivery_mode에만 적용하며 미확인 방식을 온라인으로 추정하지 않는다. 외부 과정의 현재 모집·요금은 보장하지 않는다.

## 이번 로컬 구현·검증 결과

- 응답 active_job에 선택 공고 ID·회사·제목·버전을 넣고 웹 상단에 현재 상담 대상을 표시한다. 다음 목록을 조회해도 이전 문답 대상임을 설명한다.
- 새 웹의 공고 선택 요청이 중간 분기를 활성화한다. 필수조건을 모두 답한 뒤 우대 문답 전 멈추며 우대 계속/현재 답변 상담/다른 공고 선택을 제공한다. 상담 버튼은 저장된 필수 답변과 미답변 우대조건을 구분해 전달한다.
- ROS 2·센서 보정을 교육 주제로 인식하고, 빈 결과 후에도 주제·온라인 선호를 유지한다. 수강 방식이 바뀌면 재조회하며 미확인 방식은 원하는 방식으로 추정하지 않는다. 단순 과정 비교는 기존 표시 목록을 유지한다.
- 상담 문맥에 자기평가 근거 수준·합격/탈락 단정 금지 정책을 명시했다. 실제 모델의 전수 준수 여부는 별도 QA가 필요하다.
- 백엔드 287개 중 278개 통과·환경 의존 9개 제외. 프론트 26개 통과, Vite 빌드 성공. 새 테스트는 필수→중간 선택→우대 진행·기존 답변 보존, ROS 2 교육 문맥과 명시 채용 전환, 온라인→오프라인 재조회를 검증한다.
- 실제 AWS 배포·유료 모델 검증·DB 스키마 변경·커밋·푸시는 이번 작업에서 수행하지 않았다.

남은 작업: 교육 다음 목록의 중복 제외, 모델 예산 소진 뒤 비모델 조회 허용 범위, 모호한 대상 확인의 체계화, 원문 제목의 독립 조건 제외는 별도 설계·회귀 검증 후 진행한다. 이번 수정으로 모두 해결됐다고 간주하지 않는다.
