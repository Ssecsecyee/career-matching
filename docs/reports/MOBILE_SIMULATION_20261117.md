## 테스트 중 발견하고 수정한 문제

### 1. 키보드 표시 시 대화 영역이 지나치게 좁아짐

360px 너비에서 보이는 화면 높이를 440px로 줄이자 초기 대화 영역이 약 73px까지 감소했다.
낮은 화면에서는 상단 브랜드를 접고 입력창을 한 줄 배치로 압축했다. 키보드로 화면이 줄어든 것으로 판단될 때는 하단 탭을 숨기고, 닫히면 다시 보여준다.
같은 조건의 최종 대화 영역은 235px, 입력창 하단은 430px로 측정되었다. 픽셀 수치는 해당 합성 화면과 조건의 측정값이다.
역량 문답 창도 보이는 화면 높이에 맞추어 설명 입력이 가려지지 않도록 수정했다.

### 2. 휴대폰 가로 화면에서 모바일 탭이 사라짐

처음에는 너비 767px 이하만 모바일로 판단해 가로 844px 화면에서 PC/태블릿 배치로 바뀌었다.
터치 입력 장치에서는 1000px 이하까지 모바일 구성을 유지하도록 수정했다. 일반 PC의 기존 배치는 유지한다.
가로 화면의 최종 대화 영역은 138.5px로 측정했고 상담·검색 결과·내 페이지 탭이 노출되는 것을 확인했다.

### 보완

초기 백그라운드 공고 조회만으로 모바일 안내가 자동으로 아래로 스크롤되지 않도록 조정했다.
교육 검색은 이전 화면과 응답에 따라 검색 기준 확인 버튼이 표시될 수 있어 모의 사용자도 해당 확인 단계를 누른 뒤 결과를 보도록 구성했다. 이것은 오류 수정이 아니라 테스트 시나리오 보완이다.

## 남은 실제 기기 확인

- 실제 iPhone Safari / Android Chrome에서 키보드 열기·닫기, 주소창 변화, 화면 회전.
- 실제 파일 선택과 키보드 입력기 조합, 백그라운드 복귀.
- 운영 API 지연·세션 만료·실제 추천 결과를 포함하는 전체 테스트.

키보드는 visualViewport 높이 변화를 모의로 발생시킨 검증이다. 물리 기기의 소프트웨어 키보드를 직접 실행했다고 주장하지 않는다.
운영 배포·실제 모델 호출·추가 비용 발생 작업은 하지 않았다.
