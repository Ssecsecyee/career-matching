# 대화 테스트 기반 검색·응답 개선 — 발표 1페이지 준비

작성일: 2026-11-17. 11/18(수)~11/19(목) 추가 테스트 후 최종 PPT에 반영할 초안.
현재는 MD 정리만 완료했으며 PPT는 수정하지 않았다.

## 1. PPT 한 페이지에 사용할 내용

### 제목
실제 대화 기록에서 찾은 문제를 검색·응답 개선으로 연결

### 핵심 문장
오류 없이 응답하더라도 사용자 의도와 검색 조건이 달라질 수 있어, 대화·판정·검색 결과를 함께 확인했다.

| 발견한 문제 | 수정 내용 | 현재 확인한 범위 |
|---|---|---|
| “마케팅도 좋아”를 기존 조건에 추가해 검색이 더 좁아짐 | 주제의 추가·교체·대안 선택을 구분하도록 AI 지침 보완 | 교체된 주제가 검색 확인·다음 목록에서도 유지되는 실행 경로 검증 |
| “도메인” 설명어와 기초·심화 난이도의 처리 불일치 | 검색 주제와 학습 목적 구분, 난이도 처리 규칙 보완 | 실제 AI 해석 변화는 수·목 추가 확인 예정 |
| 교육 검색에도 공고 참고사항 반복 표시 | 교육·일반 대화의 공고 참고 블록 제거, 평가 근거는 보존 | 서버 회귀 테스트 및 데스크톱·모바일 화면 확인 |
| 교육 검색 결과에 공고용 필드가 섞여 처리 실패 | 행동별 출력 규칙 보완, 형식 오류에 한해 1회 재해석 | 저장된 오류 형태로 재생, 2번째 실패·호출 한도·네트워크 오류 시 중단 확인 |
| 검색 결과에 AND·보정·내부 순위 문구 노출 | 실제 검색어·적용 조건만 기본 표시, 내부 처리 설명 숨김 | 검색 완료 화면과 과거 형식 응답의 화면 표시 확인 |

### 대표 사례 — 작은 흐름 그림으로 옮길 내용
비즈니스 역량 보완 교육 요청
→ AI가 커머스·SCM을 동시에 필수로 검색: 0회차
→ “마케팅도 좋아”도 추가 조건으로 처리: 0회차
→ 마케팅 단독으로 다시 요청: 당시 후보 3,143회차

발표 멘트: “교육이 없었던 것이 아니라, 사용자가 요구하지 않은 조건까지 AI가 필수로 만든 문제였습니다. 검색 연산 자체를 느슨하게 바꾸기보다 사용자 의도를 검색 조건으로 바꾸는 규칙을 보완했습니다.”

### 하단 검증 표시
자동 검증: 백엔드 523개 통과 / 31개 생략, 프런트엔드 79개 통과. 배포용 빌드와 데스크톱·모바일 합성 응답 화면 확인 완료.

**상태 표시:** 로컬 수정·검증 완료 / 실제 모델 재평가·운영 배포는 아직.

## 2. 발표자 메모 — 수치와 표현의 경계

- 조사 시점: 2026-11-14 14:19:08~2026-11-17 14:19:08 KST, 종료 시각 미만.
- 최근 72시간 DB 기록: 세션 106개, 요청 383건, 도우미 응답 382건, 의도 처리 실패 1건.
- 세션은 사람 수가 아니다. 테스트·일반 이용 기록이 섞여 있어 “실사용자 106명”이라고 발표하지 않는다.
- 자유 입력 message가 있는 요청·응답·판정 71개를 대조했다. 이 중 교육 판정 26개, 교육 0건 응답 10개, 공고 참고사항이 포함된 교육 응답 18개를 확인했다.
- 위 비율은 검색 정확도나 추천 품질 점수가 아니다. 0건 자체가 오류라는 뜻도 아니다. 잘못 만든 조건·불필요한 출력 등 개별 근거로 판단했다.
- 3,143은 11/16 해당 요청 시점에 기록된 Elasticsearch 후보 회차 수다. 현재 모집 중인 서로 다른 과정 수 또는 정답 과정 수가 아니다.
- 백엔드 554개 중 523개 통과·31개 생략이다. 프런트엔드는 79개 통과했다. 생략한 환경·통합 검증을 통과했다고 쓰지 않는다.
- AI가 적절한 교체 판단을 내린 것으로 가정한 제어 테스트는 실행 로직 검증이다. 실제 AI가 자연어를 더 잘 해석하게 됐다는 효과 측정과 구분한다.
- 브라우저 확인은 실제 빌드에 합성 API 응답을 연결한 검증이며 실제 Bedrock 호출·운영 서비스의 전체 흐름 검증은 아니다.
- 1회 재해석도 모델 호출에 포함된다. 기존 12회 호출 한도와 호출별 기록 체계를 유지한다. 출력 잘림·네트워크·호출 한도 오류는 추가 재해석하지 않는다.
- 선택한 공고·자기평가·원문 근거를 삭제한 것이 아니라, 교육 응답 화면에 반복 출력하지 않게 했다.

## 3. 수요일·목요일 추가 확인 계획

실제 체험은 자유롭게 진행하고, 발견한 문제는 고정된 재검증 사례로 남긴다. 발표용 성공 사례만 골라 성공률을 만들지 않는다.

| 사례 | 기대 동작 | 추가 확인 결과 |
|---|---|---|
| 부족 역량에 커머스·마케팅·재무·SCM이 함께 있음 | 예시 분야 전부를 자동 필수화하지 않고 우선 주제를 좁힘 | 미측정 |
| 0건 뒤 “마케팅도 좋아” | 대안 선택과 조건 추가를 구분. 필요하면 한 번 확인 | 미측정 |
| “마케팅과 SCM을 모두 포함” | 명시한 동시 조건은 유지. 0건이어도 임의로 풀지 않음 | 미측정 |
| “그냥 비즈니스”, “도메인 빼고” | 제거·교체 요구를 반영 | 미측정 |
| AWS 기초 / 심화 말고 기초 | 난이도를 일관되게 반영. 실제 교육 적합성 미확인 시 명시 | 미측정 |
| 공고 평가 후 교육 검색 | 공고 참고사항 반복 없음. 기존 답변 보존 | 로컬 통과, 운영 미확인 |
| 교육 검색에 잘못된 changes.regions=null 출력 | 원문 유지하여 한 번만 재해석. 계속 실패하면 안전하게 종료 | 로컬 통과, 운영 미확인 |
| 정상 검색·0건·유사 검색·검색 완료 화면 | 실제 검색 조건 표시. 내부 AND·보정 문구 없음 | 합성 화면 통과, 운영 미확인 |

기록 항목: 익명 사례 ID, 입력과 직전 문맥, 원문·색인 버전/조회 시점, 실제 검색 조건, 기대 조건, 검색 결과·후속 동작, 모델·프롬프트 버전, 호출 수, 대기시간, 판정 근거.

비교할 때는 가능하면 같은 모델·데이터·질문을 사용한다. 수집 업데이트로 결과가 변하면 해당 사실을 남긴다. 검색어·조건 해석의 성공 여부와 검색 후보의 관련성을 따로 평가한다.

## 4. 최종 PPT 반영 전 체크

- [ ] 실제 모델의 주제 교체·난이도 해석 결과를 확인하고 수치가 있으면 근거와 함께 기재
- [ ] 운영 적용 여부와 적용 버전 기재
- [ ] 추가 자유 테스트에서 발견한 실패 사례도 기록
- [ ] 개선 전후 숫자는 동일 기준으로 산출한 경우에만 비교
- [ ] 사용자 개인정보·세션 원본 ID·대화 전문은 PPT에 넣지 않음
- [ ] 한 페이지 본문은 1절을 중심으로 줄이고, 2~3절은 발표 노트와 근거로 사용
