# 검색·후속 상담 분리 구현 기록

기준일: 2026-11-02. **AWS 배포 및 실제 Sonnet 상담 2건 검증 완료**. [배포·검증 결과](CONSULTATION_PATH_DEPLOYMENT_20261102.md). 새 인프라와 DB 스키마 변경은 없으며, 합성 QA 세션과 호출 기록은 기존 DB에 저장했다. 앞서 배포한 route 4,096토큰 확대와 이번 상담 전용 경로 도입은 별도 변경이다.

## 1. 요청·모델·화면 분리

- 기존 POST /api/chat 안에 `action=consult`, task, message, 선택적 summary_id 계약을 추가했다. 새 HTTP 엔드포인트나 DB 테이블은 만들지 않는다.
- task는 prepare/interview/learning_plan/explain_unknown/defer/general 허용 목록으로 검증한다. 세션이 필수이고 임의 search_plan/profile 필드를 섞을 수 없다.
- 새 요약 버튼은 실제 task ID와 요약 ID를 전달한다. ‘다른 공고 찾기’만 search로 남긴다.
- 상담은 BedrockPlanner.consult를 호출해 **모델 자연어 → 서버 JSON 응답**으로 처리한다. BedrockPlanner.route의 검색/상담 재분류와 모델 생성 JSON 검사를 거치지 않는다.
- 기존 search 요청의 검색 JSON·Pydantic 검증과 후보 최신성/확인 흐름은 유지한다.

## 2. 상담 근거와 조회 범위

같은 소유자의 유효한 저장 세션에서 선택 공고 버전, 조건별 선택·보충 설명, 원문 인용/묶음 안내, 사용자 발언과 요약을 전달한다. 상담 중 새로운 jobs.search/jobs.get/training.search를 호출하지 않고 당시 스냅샷을 사용한다. 선택 공고가 없으면 모델 호출 전 차단하고, 전달한 summary_id가 현재 요약과 다르면 최신 요약 재확인을 안내한다.

응답의 초점은 필수 자격요건·우대조건에 대한 사용자 자기평가다. 일반 설명·준비 방법은 모델 지식을 활용하되 실제 경력·성과·교육 과정·모집 일정은 만들어내지 않게 한다. 미확인/미답변과 미충족, 개별 조건과 여러 기술의 묶음 답변을 구분한다. 질문 중단 정책은 최종 응답에도 적용한다.

아직 답하지 않은 조건은 별도 문맥으로 최대 20개, 인용 최대 600자로 제한하고 생략/축약 여부를 표시한다. 전체 상담 문맥 60,000자 보호를 유지한다. 이전에 실제 표시한 교육이 있으면 보완 상담에 그 사실 자료를 제한적으로 전달할 수 있으나 새 교육 조회를 하지 않는다.

## 3. 교육 안내와 문답 상태

- 문답 종료 시 ‘미충족이 하나라도 있다’는 이유만으로 교육을 자동 조회하던 코드를 제거했다. 새 문답 종료에서 근거 없는 need_topic 교육 카드가 자동 표시되지 않는다.
- ‘경력과 학위를 교육 수료로 대체하지 마’ 같은 제한 문구는 보완 상담 경로로 처리한다. 실제 과정을 찾아달라는 명시적 요청은 기존 교육 조회 경로에 남긴다.
- defer는 모델 없이 기존 요약으로 처리하고 문답을 자동 재개하지 않는다. 새 consult/defer 요청은 모델 호출 예산 소진 후에도 저장 요약 안내를 처리할 수 있지만 실제 모델 호출의 12회 제한은 유지한다.
- 상담 후 선택 공고·conditions/checks·보충 설명은 보존하고 stage=conversation으로 전환한다. 상담 자체로 새로운 역량 질문을 시작하지 않는다.

## 4. 스트리밍·검증·저장

- converse_response에 서버 지정 response_mode=text를 추가해 상담 자연어를 JSON reply 추출 없이 중간 전달한다. 검색은 기본 json 모드를 유지해 검색 계획이 사용자 초안으로 노출되지 않는다.
- 질문 거절 설정 시 검사 전 역량 질문이 스트림으로 노출되지 않도록 상담 초안 스트리밍을 제한하고 최종 정책 필터를 적용한다.
- 출력 상한 4,096토큰, 최종 텍스트 4,000자, 원시 스트림 20,000자/65초 보호를 유지한다. 빈/너무 긴/지원하지 않는 콘텐츠·비정상 종료·max_tokens를 정상 완료로 저장하지 않는다.
- model_invocations purpose=consultation, prompt_version=consultation-text-v1로 기록한다. 사용 모델·리전·토큰·오류도 기존 감사 경로를 활용한다.
- 기존 세션 소유자/만료·요청 ID·트랜잭션·응답 캐시·실패 abort 정책을 재사용한다. 새 기능 때문에 다른 사용자의 대화나 과거 답변을 덮어쓰지 않는다.

## 5. 구형 화면과 자유 입력 호환

기존 화면이 보낸 정확한 요약 버튼 문장은 선택 공고가 있는 경우 상담으로 연결한다. 자유 입력의 이력서/면접/보완 방향/미확인 설명과 상담 후 ‘더 구체적인 예시’ 같은 후속도 제한된 규칙으로 연결한다. 실제 새 공고/교육 검색을 명시한 요청은 상담 단어가 섞여 있어도 가로채지 않는다.

이 호환 규칙은 모든 복합 의도를 이해하는 NLU가 아니다. 규칙에 해당하지 않는 일반 대화/교육 검색은 기존 route 경로를 사용하므로 그 경로의 JSON 형식 문제가 모두 사라졌다고 주장하지 않는다. 기존 실제 교육 조회·검색은 유지하고 ‘왜 추천했어?’의 상세 근거 writer/과거 검색 조회는 여전히 별도 과제다.

## 6. 검증 결과

- 백엔드 277개 검사 중 268개 통과, 실제 환경 의존 9개 제외. 신규 상담 검사 17개: 검색/교육 조회 미호출, 전체 답변 문맥, stale 요약·선택 없음 차단, 질문 거절, 구형 버튼·자유 후속 호환, plain text/stream, 길이·잘림·opt-in, 요청 계약, 호출 감사 버전과 실패 시 세션 보존.
- 프론트 26개 검사 통과. task별 consult 요청, similar_jobs 검색 유지, 잘못된 요약 참조/태스크 차단을 추가했다.
- 프로덕션 빌드 성공: `index-31cxnq0l.js`.
- 테스트는 모의 모델과 저장소를 사용했다. 실제 Sonnet의 상담 품질·AWS 소유자/캐시·DB 저장까지 이번에 새로 검증한 것은 아니다.

## 7. 후속 배포·실제 QA

1. 구형 버튼 호환을 포함한 API/worker를 먼저 반영하고 consult 응답을 확인한다.
2. 새 요약 버튼을 포함한 웹을 반영한다. 복귀 시 새 consult 요청을 모르는 구형 API와 새 웹이 남지 않도록 두 버전을 함께 관리한다.
3. 별도 QA 세션에서 이력서 연결·보완 방향을 각각 실행하고 상담 purpose, 모델 호출 1회, 검색/새 교육 조회 0회, 정상 스트림·최종 저장·토큰·지연을 확인한다.
4. 기존 1,024토큰 상한 실패와 end_turn/JSON 형식 실패 사례를 회귀 대상으로 재현하되, HTTP 200만으로 답변의 사실 정확성이 검증됐다고 하지 않는다.
