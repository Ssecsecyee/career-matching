# 대화 문맥 판단 단일화

상태: 구현·로컬 검증 완료 / AWS 미배포 · 기준일: 2026-11-02

## 결정과 범위

자유 입력은 Bedrock 문맥 분류 → Pydantic IntentDecision 검증 → 서버 실행 검증 한 경로로 처리한다. 기존 표현별 의도 정규식·키워드·버튼 문장 비교 경로를 제거한다. 공고 조건의 질문 필요성 AI 검토와 임베딩 도입은 별도 과업이다.

## 계약

기존 chat/search/refine_search/next_results/consult/assessment_control/clarify/confirm_search/summary를 유지하고 사용자 경험 정정은 remember 행동으로 추가한다. 정정은 명시적 전체 답변 초기화 승인이 있을 때만 기존 전체 정정 기능으로 연결한다. 단순 정정 발언은 자동 초기화하지 않고 확인을 요청한다. ask_assessment 선택 필드로 다른 행동과 함께 전달된 질문 중단/허용 선호를 표현한다. 누락은 기존 선호 유지다. resume/preferred 행동과 모순되는 필드는 거부한다.

## 서버에 남기는 검사

사용자 소유권·만료·요청 중복·호출 예산·검색/선택 존재·공고 버전·조건 ID·출력 형식·필수 문답 완료 여부는 서버가 검증한다. AI는 SQL/DSL이나 실행 권한을 만들지 않는다. 의도 분류 실패를 기존 키워드 검색으로 복귀시키지 않는다. 기존 환경 플래그로 구형 라우팅을 다시 활성화하지 않는다. 기록 DB가 준비되지 않았으면 실패를 명확히 반환한다.

## 직접 행동

버튼은 문구가 아닌 안정적인 행동 ID를 보낸다. 조건 답변·선택·검색 확인·다음 결과·저장 답변 조회/개별 수정·승인된 전체 정정은 추가 의도 모델 호출 없이 실행한다. 자유 입력으로 감지한 정정은 확인 후 실행한다.

## 교육 문맥

교육 새 검색·조건 변경·다음 결과는 분류된 topics/delivery_mode와 저장된 탐색 상태를 사용한다. 비교·설명은 표시된 교육 스냅샷을 전달하며 재검색하지 않는다. 단어로 교육 요청 여부·지칭 대상을 추측하는 retrieve는 제거한다. 기술 별칭 추출은 표시/자료 처리용으로 남기되 의도 판단에 사용하지 않는다.

## 상태·행동 전이

| 상태/조건 | 행동 | 처리 |
|---|---|---|
| 어느 상태 | chat / clarify | 대화·확인만, 보류 중 조건/검색 유지 |
| 어느 상태 | search | 검증된 새 검색, 결과 확인 단계 |
| 검색 있음 | refine_search | 명시 변경만 병합, 재확인 |
| 확인 대기 | confirm_search | 해당 검색 결과 표시 |
| 검색/교육 목록 있음 | next_results | 같은 조건, 이미 표시한 ID 제외 |
| 선택 공고 있음 | consult / summary | 저장 원문·답변에 근거, 새 검색 없음 |
| 어느 상태 | assessment_control stop | 질문 중단 선호 보존 |
| 선택 공고 있음 | resume / preferred | 버전·필수 답변 검증 후 재개 |
| 자유 입력 경험 정정 | remember | 확인 요청, 즉시 전체 답변 초기화 금지 |
| 사용자 확인한 전체 정정 | 직접 remember | 기존 명시적 전체 정정 처리 |
| 누락된 실행 전제 | 모든 실행 행동 | 확인 질문 또는 기존 명시적 오류, 임의 실행 금지 |

## 평가·배포

40개 이상 고정 합성 시나리오로 대상·행동 계약, 모호성·부정문·중단/재개·검색 확인·교육 전환·요약·상담·정정을 검증한다. 모의 분류 결과를 이용한 실행 회귀 평가와 실제 모델 분류 정확도 평가는 구분한다. 기본 테스트는 AWS/유료 모델 호출 없이 진행한다. 실제 모델 정확도·p95·비용은 실행 전까지 미측정으로 표시한다. 코드 완료가 AWS 배포를 뜻하지 않는다. 이번 요청에는 운영 배포를 포함하지 않는다.

## 구현과 검증 결과

- IntentDecision 버전 context-intent-v3. 기존 행동 계약에 remember와 ask_assessment를 추가했다. 단순 정정 발언은 확인 안내만 하며 기존 선택·답변을 초기화하지 않는다.
- 모든 자유 입력은 ContextRouter를 거친다. DialogueFlow는 명시적 실행을 담당한다. legacy_intent.py, learning.retrieve/requested, BedrockPlanner.route와 구형 혼합 프롬프트를 제거했다.
- CONTEXT_ROUTING_ENABLED로 구형 경로를 복구할 수 없다. INTENT_AUDIT_ENABLED는 기록 활성 설정이고, 이전 배포 설정의 CONTEXT_ROUTING_ENABLED 값은 기록 설정의 호환 기본값으로만 읽는다. 운영에서는 기록을 켜고 intent_decisions 준비 상태를 확인한다. 기록 활성 상태에서 기록 실패는 정상 실행으로 숨기지 않는다.
- UI 버튼은 assessment_stop/resume/preferred, next_jobs/training, consult_gaps ID로 연결한다. 표시 문장 변경이 실행 행동을 바꾸지 않는다.
- 모델 JSON과 응답 텍스트를 분리했다. 분류 JSON은 스트리밍하지 않고, 자연어 응답의 스트리밍·토큰 상한·잘림 오류 처리는 유지한다. 기본 모델을 변경하거나 임베딩·추가 DB 테이블을 도입하지 않았다.
- 원문 위치·권한·상태·검색 확인·공고 버전·중복·예산 검증은 유지했다. 질문 중단 후처리 등 나머지 정규식 32개는 유지했다.
- 중단 상태에서 선택한 공고를 재개할 때 원문 조건을 복원하고, 필수 답변 없이 우대로 건너뛰지 못하도록 검증했다.
- 고정 합성 사례 48개와 추가 안전성 회귀 테스트를 포함해 backend 383건 중 381건 통과, 외부 환경 조건 2건 건너뜀. 기존 개발 DB와 분리한 임시 MySQL에서 기록·소유권·중복 요청 통합 테스트도 실행했다. 임시 컨테이너는 종료했고 기존 개발 컨테이너는 유지했다.
- frontend 35건 통과, Vite production build 성공. 실제 AWS/유료 모델 호출은 수행하지 않았다. 48개 정답을 모의 모델 출력으로 주입한 실행 테스트이며 Sonnet 분류 정확도·실사용 성능을 측정한 결과가 아니다.

## 운영 반영 전 확인

실제 모델로 고정 사례의 target/action·부정문·정정·질문 중단 선호 분류를 평가하고 지연·비용을 기록한다. 이 단계의 평가 결과를 모의 실행 통과율과 분리한다. 배포 시 백엔드와 변경된 웹 버튼을 함께 반영하고 새 대화에서 회귀 확인한다. DB DDL 변경은 필요하지 않다. 이전 코드로의 복귀는 이전 배포 산출물을 사용하며 라우팅 플래그로 구형 코드를 재활성화하지 않는다.
