# 동의어 검색 실험 고정 조건 v1

2026-11-01. **80개 서로 다른 검색 조건을 고정했다. DB 스냅샷 추출·정답 ID 생성·4개 비교군 검색 실행은 아직 하지 않았다.**

## 규모

| 구분 | 조건 수 |
|---|---:|
| 기본 기술 태그 | 16 |
| 등록된 별칭·대소문자 | 16 |
| 기술명 경계·미등록 별칭·없는 기술 | 12 |
| AND 조합 | 16 |
| OR 조합 | 8 |
| 기술 + 지역 | 12 |
| 합계 | 80 |

80개를 4개 비교군(SQL 동의어 전/후, ES 동의어 전/후)에 동일하게 입력하면 검색 조건 실행은 총 320개다. 전체 ID를 수집하는 페이지 요청·준비 호출·반복 시간 측정은 별도 요청 수다. 80개의 독립 직무 분야를 평가한다는 뜻은 아니다. 표기 변형·조건 조합별 회귀를 위한 첫 고정 세트이며 운영 전체 품질이나 통계적 충분성을 보장하지 않는다. 필요 시 v1을 덮어쓰지 않고 미사용 조건을 v2로 추가한다.

## 파일

- app/backend/experiments/fixtures/synonym_search_v1/cases.json: 전체 검색 조건. SYN-001~080.
- 같은 폴더 cases.csv: 사람이 검토할 조건표.
- 같은 폴더 manifest.json: 버전·동의어·정답 규칙·해시.

## 입력 예

React / 리액트 / 리엑트 / React.js, Python / 파이썬, PostgreSQL / Postgres, React AND TypeScript / 리액트 AND TypeScript, React OR Vue.js / 리액트 OR Vue.js, React + 서울 / 리액트 + 서울.

SQL·C·C++·C#은 접두사나 구두점 제거로 합치지 않는다. 같은 공고가 C++와 C# 둘 다 명시하면 두 결과에 함께 등장할 수 있다. 결과 집합이 서로 완전히 겹치지 않아야 한다는 기준은 쓰지 않는다.

## 고정 동의어와 제한

현재 저장된 엔진 설정을 기준으로 React/react.js/리액트/리엑트, Python/파이썬, PostgreSQL/Postgres만 동의어로 고정했다. 모든 비교군은 대소문자를 동일하게 무시한다. MySQL/마이에스큐엘, VueJs/Vue.js, Go/Golang 등은 이번 사전에 자동 추가하지 않는다. 미등록 별칭 사례는 사전 누락/추가 후보를 드러내는 데 사용한다.

keyword는 전부 빈 문자열이다. 이번 실험은 기술 태그 검색에 한정하며 Nori 본문 분석·직무 문장 해석·BM25 관련성·Bedrock 추출을 평가하지 않는다. OR는 현재 서비스 SearchPlan과 별도로 평가 도구에서 구현할 명시적 연산이며 기존 AND 동작을 임의로 바꾸지 않는다.

## 정답 생성과 판정

정답 수와 ID는 아직 null/pending_snapshot이다. 같은 고정 DB 스냅샷의 tech_stacks를 독립 순회해 산출한다. 동의어 미적용군은 태그 소문자 정확 일치, 적용군은 위 동의어 그룹으로 입력·저장 태그 모두 정규화한다. 지역·마감·출처 상태·기준 시각은 4개군에 동일하게 적용한다. 식별자는 source+source_id로 묶는다.

각 군의 실제 전체 ID와 해당 군 정답 ID가 같은지 비교하고, 누락/과잉/예상 건수를 기록한다. SQL LIKE의 부분 문자열 매칭이나 ES 분석기의 잘못된 연결도 정답에 맞춰 숨기지 않고 차이로 보고한다. 등록 별칭은 동의어 적용군 안에서 canonical과 같은 정답 집합인지 확인한다. 두 없는 기술은 실제 스냅샷에 없음을 확인한 뒤에만 0건 정답으로 확정한다.

사람 관련성 평가(P@5/nDCG)와 보고서 점수 산출은 이번 범위에서 보류한다. 운영 검색 설정·DB·ES와 Bedrock은 이번 세트 작성으로 변경/호출하지 않았다.
