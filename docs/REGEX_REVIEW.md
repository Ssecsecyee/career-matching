# 정규식 유지·정리 현황

상태: 의도 판정 중복 제거 AWS 배포 완료 · 기준일: 2026-11-02

## 집계

app/backend/src의 Python AST에서 re 모듈 직접 호출 표현식을 집계한다. 실행 횟수·고유 패턴 수·전체 조건문 수와 다르며 re.escape 같은 보조 호출도 포함한다. 컴파일 객체의 메서드 호출과 문자열 비교는 이 숫자에 포함하지 않는다.

직전 소스 59개 → 현재 소스 32개. 이번에 제거한 27개는 기존 자유 입력 의도 판정이며 같은 기능을 문자열 if로 옮기지 않았다. 이전의 62 → 59 정리는 지역 필터 덮어쓰기와 문구 기반 확인 우회를 제거한 선행 변경이다.

## 필수성 재검토

32개 전체가 필수라는 결론은 아니다. 아래의 필수는 정규식 문법이 반드시 필요하다는 뜻이 아니라 해당 기능을 유지해야 한다는 의미다. 정규식을 다른 문자열 코드로 옮겨도 책임과 복잡성은 사라지지 않는다.

| 판정 | 호출 수 | 대상과 근거 |
|---|---:|---|
| 기능 유지 필요 | 16 | 입력·ID·경로·색인 형식 8, 기본 민감정보 가림 6, 원문 분리 2. 허용값 제한·기록 보호·원문 연결을 대체 없이 없애면 안 됨 |
| 선택 기능 | 9 | condition_display 5와 assessment_summary 경력 충돌 경고 4. 화면 분류/공백 정리와 좁은 경고는 필수 실행 검증이 아님. 경고는 부정문·가정 표현을 오해할 수 있어 검증된 사실로 쓰지 않음. 삭제 시 해당 표시·경고 기능이 줄어듦 |
| 대체 후 제거 검토 | 3 | respect_preferences의 문장 분리·역량 질문 필터. 정규식은 안전의 완전한 보장이 아니고 정상 설명 삭제/우회 질문 누락 가능. 문답 실행 중단은 서버가 별도로 강제하며 자연어 질문 억제 대체를 평가한 뒤 변경 |
| 호환/표시 의존 | 4 | model_search v1 보정 2 + topics_in 기술 별칭 2. 정규화 보정은 기존 handlers/chat.py → BedrockPlanner.plan 전용이고 운영 대화 라우터는 사용하지 않음. topics_in은 조건 표시에서도 사용하므로 구형 API만 없앤다고 두 호출 모두 제거할 수는 없음 |

구체적인 후속 선택지는 ① 구형 검색 핸들러·plan/v1 보정 폐기로 2개 제거, ② 화면 분류 단순화와 기술 별칭 사용처 제거 검토, ③ 경력 충돌 경고를 AI 상담 문맥과 연결한 별도 평가, ④ 질문 필터의 구조화된 출력 제어 대체다. 이번 배포에서는 32개를 추가 삭제하지 않았다.
