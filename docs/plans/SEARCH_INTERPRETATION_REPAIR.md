# 검색 해석·표기 통일·재검색
상태: 배포 / 2026-11-07 운영 검증 완료

## 확인한 기존 방식
일반 대화는 ContextRouter → BedrockPlanner.classify → 검증된 IntentDecision/SearchPlan → ES/MySQL 조회 1회였다. 조회 결과를 다시 모델에게 피드백해 보정하는 단계는 없었다. 카테고리 화면의 검색창은 AI 없이 text_query를 직접 전달했다. 경기도/경기 별칭과 깃/Git 표기 통일도 누락됐다. AgentCore 실험 경로는 별도 도구 루프(maxIterations 3)이며 이번 일반 경로 변경과 다르다.

## 개선
- 공고 검색창의 자유 입력은 기존 문맥 모델로 해석. 입력 원문과 선택된 카테고리는 분리하여 전달.
- 카테고리 버튼만 바꾸는 검색은 모델 호출 없이 실행.
- 지역 정식명·약칭, 기술 한글명·공식명은 모든 경로에서 같은 정규화 정책 사용. Git과 GitHub는 구분.
- 0건이며 text_query가 있는 AI 검색은 첫 검색 포함 최대 3회. 추가 모델 보정 최대 2회. 결과가 생기면 종료.
- 지역·직무·신입·필수/보유/선호 기술과 기존 공식 기술명은 보호. 검색어 비우기와 조건 삭제 제안은 거부. 같은 계획을 반복하지 않음.
- 재검색 모델 실패나 한도 도달은 기존 0건 응답을 유지. 한 채팅 모델 호출 12회 제한은 변경하지 않음.
- 각 시도 계획·건수·실패 종류를 search_context/search_attempts 및 intent_decisions.result_summary에 기록. 모델 호출 토큰은 기존 model_invocations에 저장.

## 한계
등록된 표기 별칭으로 해결되는 보정은 모델이 필요 없다. 재검색이 없는 데이터를 만들어내지는 않으며 조건 완화는 사용자 동의가 필요하다. 직무 의미 전체의 동등성을 자동으로 증명하지 않으므로 재검색에서 직무 필터는 변경하지 않는다.

## 검증 기록
백엔드 533개 검사 통과(31개 환경 의존 검사 제외), 프론트엔드 72개 통과. 운영 API에서 경기도 깃 / 경기 Git을 각각 입력해 두 요청 모두 regions=[경기], text_query=Git, Elasticsearch 후보 55건, 검색 1회로 동일함을 확인했다. 0건 재검색의 종료·조건 보호·모델 실패 처리는 자동 테스트로 확인했다. 운영에서 추가 보정이 실제 성공하는 비율은 후속 QA 대상이다. 배포 release: 20261107T042224Z. ENABLE_SEARCH_REPAIR=true 활성화.
