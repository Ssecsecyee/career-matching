# 고용24 개인 신청 범위 중심 활용 계획

상태: 방향 확정 · 실제 개인 API 승인/호출 범위 확인 전
기준일: 2026-11-04

## 범위 변경

기업/기관 권한이 필요한 고용24 채용정보 API 확보를 현재 진행의 선행조건에서 제외하고 보류한다. 승인 불가능이 확정됐다는 뜻은 아니다. 사용자가 개인 권한으로 이용하려는 국민내일배움카드 훈련과정, 훈련 공통코드/NCS 분류, 직업정보, 직무정보를 우선 검토한다. 공개 명세에 기능이 있다는 것과 현재 개인 키에 이용 권한이 있다는 것은 구분하며 승인 내역과 소량 실제 호출로 확정한다.

채용공고는 기존 점핏 원문→검증→MySQL→Outbox→ES 경로를 유지한다. 점핏 자료로 전체 노동시장·다직군의 대표성을 주장하지 않는다. 고용24 채용 API로 전체 출처를 교체하는 기존 일정은 현재 실행 범위가 아니다.

## 정보별 역할

| 정보 | 활용 | 확인할 한계 |
|---|---|---|
| 국민내일배움카드 훈련과정 | 실제 과정/회차·일정·지역·방식·비용·지원조건과 학습 루트 연결 | 개인 키의 목록/상세 권한, 모집 상태/접수일, 커리큘럼 실제 제공 범위 |
| 훈련 공통코드·NCS 분류 | 훈련 분야와 직무 분류를 공통 코드로 연결 | 분류 코드 자체가 세부 역량·능력단위나 사용자 숙련도를 뜻하지 않음 |
| 직업정보 | 직업 설명·진로 탐색의 참고 근거 | 현행 제공 세부 서비스·갱신 시점·코드 체계 |
| 직무정보 | 수행 업무·요구 역량 상담의 참고 자료 | 실제 응답에 있는 범위만 사용, 직업코드/NCS와 무조건 동일시하지 않음 |

NCS 능력단위/요소까지 필요하면 한국산업인력공단의 별도 NCS 기준정보 API를 검토한다. 고용24 개인 키로 자동 이용 가능하다고 가정하지 않는다. NCS/KECO/직업/직무 간 매핑은 제공된 공식 코드/매핑 또는 명시적인 검토 근거로 보관하며, 단순 문자열 일치로 확정하지 않는다.

## 우선 실행 순서

1. 개인 신청 승인 내역 확인: 엔드포인트별 권한·한도·이용/보관 범위와 필드 확인. 인증키는 비밀 설정으로만 관리.
2. 승인된 공통코드 소량 조회 후 필요한 분류/지역 기준을 보관. 전체 코드 응답은 문서/API 규칙에 맞춰 검증.
3. 승인 훈련 목록/상세 최대 10건 수집: 과정/기관/회차 복합 키·코드·일정·비용·상태·원문 확인.
4. training_offerings 공통 계약에 매핑하고 격리 DB에서 신규/수정/중복/빈값/오래된 응답을 시험.
5. 소량 AWS 적재와 교육용 ES 색인 동기화·검색·출처/버전·모집 정책 일치를 확인.
6. 사용자 미충족 기술→훈련의 실제 학습내용 연결과 추천 근거 확인. 모집 미확인/과거 과정은 학습 참고로 구분.
7. 직업·직무 정보는 별도 기준자료 어댑터/저장 구조를 설계해 연결. 채용공고나 교육과정 행으로 넣지 않음.
8. 주기 수집 자동화: Lambda→비공개 S3 원본→적재 전용 큐/소비자→MySQL/Outbox→교육 ES. 코드 기준정보와 과정 데이터의 갱신 주기는 별도 결정.

경력·학위·면허 미충족을 교육 수료로 대체하지 않는다. 모집 여부·자부담·수강 자격은 실제 제공 근거로 구분한다. NCS 분류 일치만으로 교육의 모든 부족 역량 해소를 단정하지 않는다.

## 현재 실험·에이전트 계획에 미치는 영향

현재 채용 QA·정식 평가·백업/알림은 고용24 채용 API를 기다리지 않고 진행한다. Harness 비교는 기존 점핏 채용과 고정 교육 표본으로 시작할 수 있다. 훈련 API 자료가 준비되면 데이터셋 버전을 새로 고정해 교육 전환/검색/추천 근거 평가를 추가한다. 데이터가 달라진 실험을 같은 조건의 A/B 결과로 합치지 않는다.

통계는 점핏의 관측 채용 표본과 확보 훈련 자료 간 비교로 한정하고 전국 기업 수요/교육 공급의 부족을 단정하지 않는다. 개인 API 연결과 임베딩·자동 역량평가·서버리스 전체 전환은 각각 별도 과업이다.

## 승인 목록의 세부 조사

추가 훈련·취업지원·강소기업을 포함한 10개 서비스의 실제 접근·필드 조사와 매핑은 [API 조사 계획](WORK24_API_DISCOVERY.md)을 따른다. 채용정보 접근 불가는 사용자 확인이며, 나머지는 승인 표기와 실제 하위 API 성공을 분리해 검증한다.
