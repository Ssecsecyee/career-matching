## 사용자 경험

상단에 채용공고·교육과정·AI 상담을 두되, 시작할 때 직무 선택을 강요하지 않는다. AI 상담에서 방향을 찾거나 직접 검색·목록·상세 화면에서 탐색할 수 있다. 상세 옆 AI 패널은 현재 선택 대상을 표시하고 설명·조건 확인·보완 상담을 지원한다. 모바일은 하단 패널로 연다.

공고를 선택하는 것과 자기평가를 시작하는 것을 분리한다. 채용 상세를 읽는 것만으로 조건 문답을 자동 실행하지 않는다. 희망 직무·직접 진술한 경험·조건 자기평가·원문 사실을 구분한다. 교육 검색은 요청한 AND/OR를 보존하며 원문 미확인을 충족으로 처리하지 않는다.

실제로 독립 적용 가능한 크기로만 커밋한다. 서로 의존하는 변경은 순서를 문서화하고 같은 묶음으로 되돌린다. 실행하지 않은 테스트·미구현 화면을 완료로 표시하지 않는다. 현재 Router의 App key가 hash에 연결돼 주소 변경 시 대화가 재생성될 수 있으므로 1단계에서 먼저 해결한다.

## Git와 배포 원칙

각 단계는 범위를 설명하는 별도 커밋과 검증 기록을 남긴다. 단계 완료 시 해당 커밋을 가리키는 ux-workspace-stage-N-YYYYMMDD 태그를 추가하고 원격으로 보관한다. 단계 중간 수정은 단계 번호·범위가 드러나는 이름으로 구분한다. 태그는 새 커밋을 추가해도 개편 전 기준을 계속 가리킨다.

main에 기능을 반영할 때는 검증된 커밋 범위를 확인하고 단계별로 반영한다. 사용 중인 main 기록을 reset --hard·강제 푸시로 지우지 않는다. 공유된 변경 취소는 git revert로 역순 적용하며 의존성 있는 서버·화면 변경은 함께 확인한다. 미커밋 작업을 먼저 보존하고 복구한다.

Git 태그는 실행 중 AWS를 자동으로 되돌리지 않는다. 웹만 변경한 단계는 복구 커밋을 빌드하고 기존 hosting.py publish 절차로 재게시해야 한다. 백엔드 단계는 복구 코드를 update_backend.py build/apply 절차로 다시 배포하고 결과를 검증한다. 기존 API 계약을 즉시 제거하지 않아 이전 웹과의 호환 기간을 둔다.

이번 UI 단계에 DB 데이터 삭제·테이블 제거를 포함하지 않는다. 추후 DB 변경이 필요하면 별도 마이그레이션·백업·복구 계획으로 분리한다. Git 소스 원복으로 운영 DB 기록이 복구되는 것으로 설명하지 않는다.

각 배포 기록에는 source commit, 웹 산출물 또는 백엔드 release, 배포 결과, 검증 결과, 직전 정상 버전을 적는다. AgentCore 전환과 이번 UX 개편은 독립 작업으로 유지한다.

## 현재 단계

1단계 구현: main 진입점에서 AppRouter와 CareerApp을 분리했다. 일반 사용자 #chat·#jobs·#training은 동일한 CareerApp 인스턴스를 사용한다. 관리자 대시보드는 별도 컴포넌트, 관리자 채팅은 별도 상태 키로 일반 사용자 인증·대화를 재사용하지 않는다.

AI 상담·채용공고·교육과정 메뉴를 제공한다. 첫 단계 채용·교육 화면은 대화에서 실제 검색·확인한 최근 목록을 읽기 전용으로 보여준다. 새 목록 API나 전체 DB 탐색 기능이 이미 만들어진 것처럼 표시하지 않는다. 목록 선택은 프론트 표시 대상만 바꾸며 서버 select·모델 호출·문답을 자동 실행하지 않는다. 상세 지원조건은 이 단계에서는 원문 링크로 확인한다.

사용자 화면들은 탭 전환 시 언마운트하지 않아 채팅 입력·문답 초안·목록 선택을 보존한다. 새 대화·잠금·관리자 전환·브라우저 새로고침의 기존 초기화 범위는 다르며, 새로고침 이후 복원을 추가한 것은 아니다. 브랜드 링크도 일반 사용자 내부 화면 이동으로 변경했다.

확인 전 교육 후보를 탐색 화면에 노출하지 않는다. 최근 교육 검색이 빈 결과이면 과거 목록을 대신 부활시키지 않는다. 화면은 최근 검색 목록이라는 범위를 명시한다.

검증: 프론트엔드 전체 53건 통과·웹 빌드 통과. 실제 React DOM을 모의 서버에 연결하여 탭 왕복 시 동일 textarea·대화·입력 초안·목록 선택·미저장 조건 선택·보충 설명 보존과 추가 요청 0건, 관리자 채팅 전환 시 빈 접속 코드 재입력을 확인했다. happy-dom은 개발 테스트 전용이다. 실제 Bedrock·운영 DB 호출은 테스트에서 실행하지 않았다.

다음 단계는 2단계 인증된 채용 탐색 읽기 API다. 화면 옆 AI 패널과 채팅 없는 전체 검색은 아직 구현하지 않았다.
