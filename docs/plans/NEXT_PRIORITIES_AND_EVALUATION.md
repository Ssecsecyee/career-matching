# 후속 우선순위와 전체 품질 평가

상태: 후속 계획 / 이 문서의 자동화·정식 평가·사람인 전환은 미실행
기준일: 2026-11-04

## 현재 기준

- 고용24 훈련 4종의 목록 수집과 초회 운영 반영 완료. 고용24 138,484건과 기존 부트텐트 7건을 기존 교육 테이블·교육 ES에서 관리한다.
- 실제 운영 검색에서 React·Python·회계의 교육 결과를 확인했다. 이는 연결 smoke 검사이며 정식 정확도 결과가 아니다.
- 상위 후보 100건씩 최대 1,000건 범위에서 최신 DB와 검증하고 화면에는 최대 3건을 반환한다. 전체 결과 수가 많다는 이유만으로 오류를 내지 않는다.
- 교육 시작일 기준 노출 정책은 적용했다. 모집 상태·신청 가능은 별도 근거 없으면 미확인이다.
- 고용24 자료는 목록 중심이라 교육명 검색 비중이 크다. 상세 커리큘럼·수강방식·지원 대상 보완과 NCS 분류 검색 연결은 후속이다.
- 채용공고는 기존 점핏 경로 유지. 사람인 API는 사용자가 신청한 상태이며 승인·실제 호출·제공 필드는 확인 전이다. 고용24 채용 API 전환은 보류한다.

초회 반영 증거: [배포·검색 확인](../deployments/WORK24_INITIAL_IMPORT.md).

| 순서 | 과업 | 완료 기준 |

| 1 | 고용24 일일 갱신 자동화 | 예약 실행부터 목록·DB inventory 비교·신규/변경 검증·MySQL/Outbox·교육 ES 반영까지 한 번 이어짐. 실패 재개·중복 실행 방지·알림 확인 |

| 3 | 전체 품질 수치화 | 고정 평가셋·판정 기준·데이터/모델/프롬프트 버전으로 검색·대화·추천·운영 결과를 분리 산출 |

1~2를 진행하면서 3의 평가셋과 정답 기준은 먼저 준비한다. 데이터가 보완될 때마다 같은 평가셋으로 회귀를 확인한다. 사람인 승인은 외부 일정이므로 다른 작업을 막는 선행조건으로 두지 않는다.

## 1. 일일 수집·반영

기존 EC2의 별도 작업자와 예약을 우선 검토한다. 개인 PC나 SSM 터널을 항상 켜두는 운영 방식은 피한다. 서버용 API 키는 비밀 저장소에서 읽고 Git·출력·수집 원본에 포함하지 않는다.

목록 재조회 → 서비스/과정/회차/기관 식별 → 실제 DB inventory 비교 → 신규·변경·재확인 큐 → 검증 → 교육 upsert와 같은 트랜잭션 Outbox → ES 반영 순서다.

- 목록 조회까지 신규만 가져올 수 있다고 가정하지 않는다. 변경일 이후 조회 계약은 아직 확인되지 않았으므로 목록으로 차이를 판정하고 상세 호출·DB 쓰기를 줄인다.
- 기본 수집 범위는 오늘-7일~오늘+90일이며 새 실행은 7일 구간으로 나눈다. 이 범위 밖 과거 전체 자료를 갱신했다는 의미는 아니다.
- 상세 기본 20건은 시험 제한이다. 운영 처리량은 실제 API 한도·큐 유입량·처리 시간을 보고 정한다.
- 시작일 도래·미확인 자료는 신청 후보에서 제외하고 원본은 보존한다. 실제 모집 마감으로 바꾸지 않는다.
- 중복 실행 방지, 단계별 체크포인트, 제한된 재시도, 429 대응, 실패 알림, 마지막 성공 및 동기화 지연 관측을 검증한다.
- 초회 배포용 신규 전용 적재기는 내용이 다른 기존 행을 덮지 않는다. 자동화에서는 검증된 변경 전용 갱신과 버전 증가·Outbox를 추가해야 한다.

상세 명령·설정: [수집 운영 절차](WORK24_BULK_INCREMENTAL_PIPELINE.md).

## 2. 교육 상세와 NCS

목록 title/contents만으로 세부 기술 교육·개인 지원 자격·비용을 만들어내지 않는다. API가 제공하는 사실을 원본 경로와 연결하고 미제공·미확인·명시적 0을 구분한다. 기관 장비를 해당 과정 커리큘럼으로 사용하지 않는다.

NCS는 공식 코드·개념·계층·버전을 확인한 사전과 교육의 연결로 관리한다. 직업 코드와 NCS는 다른 체계이며 공식 대응 관계 없이 묶지 않는다. 같은 NCS가 사용자 부족 역량을 실제로 가르친다는 보증은 아니다. NCS가 없는 기존 교육도 제목·주제로 검색할 수 있게 유지한다.

전용 분류 테이블은 아직 미적용이며 현재 원본 메타데이터에 NCS를 보존한다. [저장 구조 계획](WORK24_TRAINING_NCS_MODEL.md)을 구현·검증한 뒤 검색 필터와 가중치에 연결한다.

## 3. 전체 품질 평가 계약

하나의 종합 정확도 숫자로 서로 다른 실패를 숨기지 않는다. 아래 지표를 단계별로 분리하고 성공률의 분모·실패 사례·미확인 자료 비율도 함께 보고한다.

| 영역 | 판정 질문 | 지표 후보 |
|---|---|---|
| 의도 분류 | 채용/교육/상담/다음 결과/정정/질문 중단을 문맥에 맞게 골랐는가 | 정확도, 클래스별 precision/recall/F1, 혼동행렬, 잘못된 행동 실행률 |
| 검색 | 관련 자료를 상위에서 찾고 불필요한 필터로 누락시키지 않는가 | Precision@3/5, 라벨 범위 내 Recall@k, nDCG@k, 기대 결과가 있는 사례의 0건 비율, 다음 결과 중복률 |
| 근거·기억 | 사용자 선택·보충 설명·원문 조건을 보존하고 올바르게 인용하는가 | 근거 일치율, 근거 없는 주장률, 답변 누락/잘못된 승계율, 미확인→미충족 오판율 |
| 교육 추천 | 미충족 역량과 실제 교육 내용·대상·일정이 연결되는가 | 사람 판정 적합률, 근거 커리큘럼 확보율, 시작일/지원 조건 위반률, 신청 가능 오표시율 |
| 운영 | 요청이 정상 완료되고 데이터가 갱신되는가 | 오류·JSON 형식 오류율, p50/p95 지연, 요청당 호출·입출력 토큰·비용, 수집 성공률, Outbox/ES 지연 |

### 평가셋과 정답

기존 문맥 분류 120건 계획과 검색 실험 자료를 재사용 가능한지 먼저 확인한다. 통합 대화는 30~50개의 고정 시나리오로 시작하는 안이며 실제 작성·실행 완료를 의미하지 않는다. 정상 경로와 아래 실패 경로를 함께 포함한다.

- 인사 뒤 채용·교육 전환, 짧은 ‘딴거’, 여러 지역/기술 OR·AND, 검색 조건 변경.
- 문답 중 질문 중단·재개·선택 정정, 저장 답변 요약·추천 이유, 이전 공고와 현재 공고의 근거 혼동.
- 미확인/미답변 처리, 경력·학위·면허를 교육 수료로 대체하지 않기.
- 상세 부재, 시작일 도래·미확인 교육, 모집 미확인을 신청 가능으로 안내하지 않기.
- 1,000건 초과 검색 총수, 상위 검증 범위 제한, 다음 결과 중복, ES 장애·DB 대체, 응답 형식 오류.

각 사례에 ID·입력·필요한 이전 대화·현재 상태·기대 의도/행동·정답 문서 ID/원문 근거·금지 주장·판정 이유를 보관한다. 검색 정답은 고정 DB/ES 스냅샷에서 사람이 후보와 원문을 대조해 만든다. LLM의 자체 답변을 그대로 정답으로 쓰지 않는다. 평가에 사용하지 않은 표현·사례로 별도 확인한다.

일부 후보만 라벨링했다면 Recall을 전체 데이터의 전역 Recall이라고 부르지 않는다. 미판정 자료와 실제 무관 자료도 구분한다. 1,000건 상한과 실제 검증 건수, 반환 개수는 별도 기록한다.

### 재현성과 실행 구분

- 데이터 스냅샷·평가 시각/시간대·필터·정답셋 버전을 고정한다. 날짜가 지나 교육이 제외되는 효과를 검색 개선으로 오해하지 않도록 한다.
- 분석기·동의어·가중치·모델·프롬프트·스키마·코드 버전을 기록한다.
- ES/SQL 검색 실험은 Bedrock 없이 가능하다. 문맥 분류·상담은 실제 모델 평가가 별도 필요하며 예산·호출 범위를 정한 뒤 실행한다.
- 이전/개선안을 같은 조건에서 비교하고 사례별 오답·누락·지연·비용을 보관한다.
- 통과 임계값과 사람 검수 표본은 실행 전에 합의한다. 현재 임계값 달성이나 정식 정확도 산출을 주장하지 않는다.
- 첫 평가로 기준선을 만들고 배포 전 고정 회귀 검사로 반복한다. 단순 연결 smoke와 단위 테스트 통과 수는 추천 정확도가 아니다.

## 4. 사람인 API 승인 후

현재는 신청 상태만 확인됐다. 목록·상세 API 제공 여부, 실제 응답 필드, ID·수정/등록일, 모집 상태·마감일 의미, 페이지/일일 한도와 이용 범위를 소량으로 검증한다. 아직 구체 엔드포인트나 사용 가능 필드를 확정하지 않는다.

사람인 어댑터로 기존 공통 채용 모델에 변환한 뒤 MySQL·Outbox·채용 ES 동기화를 재사용한다. source와 source_id는 점핏과 구분한다. 제목·회사명이 비슷하다고 기존 점핏 행을 덮거나 자동 병합하지 않는다. 중복 노출 정책과 출처 간 대응은 검증 근거가 있는 경우에만 정한다.

소량 멱등 적재·변경·마감·삭제/미노출·원문 링크·검색 회귀를 확인하고 범위를 늘린다. 실제 제공 필드가 다르면 스키마/매핑을 조정하며 API 주소만 바꿔 전환 완료로 보지 않는다. 전환 전까지 점핏 채용 경로를 유지한다.

## 완료·계획 구분

초회 고용24 교육 적재와 검색 연결은 완료했다. 매일 API→운영 DB 자동 반영, 상세/NCS 강화, 정식 전체 품질 평가와 사람인 전환은 후속 계획이다. 이 문서는 계획 정리이며 새 호출·예약·DB 변경·배포를 실행하지 않는다.
