# 번호형 자격·우대요건 분리

상태: 구현·AWS 배포·운영 원문 읽기 검증 완료
기준일: 2026-11-04

## 문제와 원인

아인잡 프론트엔드 공고(55376222) 문답에서 여러 번호 요건이 한 질문으로 표시되었다. condition-split-v2는 번호 뒤 공백을 요구해 `1.프런트엔드`, `2.React` 형태를 새 항목으로 인식하지 못했다. AI 검수 입력도 이 분리 결과를 사용하므로 묶음 단위 분류가 질문 단위를 바로잡지 못했다.

## 수정

condition-split-v3는 번호 뒤 공백이 없어도 번호 목록을 인식한다. 한 줄의 번호 목록은 괄호 밖에서 1부터 연속되는 명확한 번호열만 분리한다. 소수·버전 숫자와 괄호 안 예시는 경계로 삼지 않으며, 또는 등 대안 관계와 중첩·기술 모음의 보수적인 처리도 유지한다. 이는 의미 추론용 프롬프트 추가가 아니라 원문 목록 경계 파싱 수정이다.

원문 문자열은 수정하지 않고 Unicode 위치 범위를 저장한다. 분리 후 원문 누락·중복·변조 검증을 그대로 수행한다. 파서 버전은 질문 ID와 조건 해시에 포함되므로 이전 묶음 캐시를 새 질문으로 재사용하지 않는다. 이미 열린 대화와 저장 답변은 소급 변경하지 않으며, 새로 공고를 선택해 다시 문답한다. 묶음의 미충족 답변을 각 항목 미충족으로 복사하지 않는다.

## 검증

보고된 형태의 10개 번호 요건을 줄바꿈·CRLF·한 줄 공백 연결의 세 형태로 재현하고 모두 10개로 분리되는지 검증했다. 버전 번호, 괄호 안 번호 예시, 대안 관계 보호도 검사했다. 전체 백엔드 475건 중 444 통과, 31 건너뜀. 원문 DB 스키마·공고 원본은 변경하지 않는다.

임의의 비번호 문단을 의미 단위로 모두 나누는 기능은 이번 변경 범위가 아니다.

AWS release 20261104T123035Z 반영 완료. 운영 DB의 공고 55376222 버전 2 원문을 읽어 필수 10개·우대 7개로 분리됨을 확인했고 두 섹션 모두 원문 범위 검증을 통과했다. 이 확인은 모델 의미 분류 품질 평가와는 별개다.
