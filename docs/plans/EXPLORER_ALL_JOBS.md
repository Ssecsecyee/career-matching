# 전체 목록에서 상담으로 좁히기

상태: 구현 · 별도 미리보기 배포

공고 탐색 페이지에서 인증 직후 세션이 없으면 기존 구조화 search API로 노출 가능한 전체 공고 중 첫 20건을 조회한다. 자연어 분류나 모델 생성은 하지 않는다. 모집상태·마감일 제한은 기존 저장소 정책을 따른다. 전체 DB의 마감 공고까지 보여주는 기능이 아니다.

공고 탐색 중 자연어 검색은 기존 문맥 분류와 검색 계획을 재사용한다. search_review 성공 시 반환된 search_id와 session_id로 confirm_search를 실행해 목록을 바로 반영한다. 기준 변경·원문 버전 검증은 서버에서 그대로 수행한다. 채팅 전용 화면과 교육 검색은 기존 확인 흐름을 유지한다. 확인 적용 실패 시 기준 화면을 남겨 수동 재시도할 수 있다.

현재 적용 조건과 관련성 순위 기준을 목록 위에 표시한다. 다음 공고는 서버의 기존 shown_ids 제외 방식이다. 이때 표시 건수는 이미 본 공고를 제외한 남은 후보 수임을 알린다. 전체 공고 초기화는 새 검색으로 처리하므로 현재 선택한 공고 및 문답 진행을 초기화한다. 기존 DB 저장 기록은 삭제하지 않는다.

초기 전체 목록은 20건 단위, 이후 자연어 검색은 기존 계획의 limit을 따른다. 탐색 한도는 기존 세션당 1000개이며 그 이상은 조건을 좁혀야 한다. 검색창과 지역 선택은 여전히 현재 페이지 내 필터이며 전체 검색은 상담을 사용한다. 개별 조건 칩 해제·이전 페이지·교육 전체 목록은 후속 작업이다.

검증: 프론트엔드 55개 통과, 프로덕션 빌드 통과. 실제 화면 컴포넌트 합성 API 테스트로 인증 후 전체 조회 1회, limit=20, 자연어 검색 후 동일 세션 자동 확인, 결과 목록과 적용 조건 표시를 검증했다. 기존 팝업·미저장 문답 유지와 관리자 인증 분리도 통과. 운영 모델을 호출한 실제 검색 품질 평가는 별도이다.

## 스크롤 누적 조회

탐색 화면 search 요청에 page_size=20을 명시한다. 서버는 이 허용값만 검증하여 탐색 세션의 페이지 크기를 20건으로 적용하며 기존 채팅 기본값은 유지한다. IntersectionObserver로 목록 하단 접근 시 다음 결과를 조회하고, 중복 ID를 제거해 기존 목록에 누적한다. 숨겨진 교육/공고 탭, 처리 중·재시도 대기·현재 목록 필터 사용 중에는 자동 로딩하지 않는다. 다음 버튼은 수동 대안으로 유지한다. 이미 본 공고도 같은 세션 shown_ids에 속하면 선택 가능하며 선택 시 현재 모집 상태·마감·원문은 기존 검증을 적용한다. 세션 탐색 한도 1000건은 유지하며 한도 도달 시 자동 로딩을 종료한다.

검증: 백엔드 498개 통과(31개 환경 의존 검사 건너뜀). 프론트엔드에 페이지 누적·ID 중복 제거·종료·새 검색 교체 검증 추가.

## 컴팩트 목록과 상세 읽기

큰 화면(1200px 이상)은 상담 폭 300px, 공고 3열로 표시한다. 카드 최소 높이 185px, 배지 46px로 축소하고 모바일은 기존 2열·1열 대응을 유지한다. 오른쪽 패널은 저장된 주요업무·자격요건·우대사항·복지·채용절차·유의사항·서비스 소개를 표시한다.

view_job은 인증된 세션에서 현재 후보 또는 이미 노출한 ID만 허용한다. 저장소에서 다시 읽고 모집상태·마감일 검증 후 제한된 상세 필드만 반환한다. 선택·문답·사용자 답변 상태를 수정하거나 Bedrock을 호출하지 않는다. 사용자가 지원조건 확인을 누르면 기존 선택 검증 및 문답을 진행한다. 누락된 원문은 생성하지 않는다.

검증: 프론트엔드 56개 통과, 백엔드 498개 통과(31개 환경 의존 검사 생략). 합성 API 화면 검증에서 상세 원문 표시 및 문답 분리 확인.

배포 확인: 코드 764b783, backend 20261105T065202Z Success, frontend index-D10LorU-.js / index-C0cwMX5I.css 기본 주소 HTTP 200 및 자산 일치 확인. DB 스키마 변경 없음.

## 초기 조회 로딩 화면

초기 공고·교육 조회 중에는 빈 결과와 0건 대신 반응형 6개 스켈레톤 카드·로딩 안내를 표시한다. 실제 결과가 빈 경우에만 기존 빈 결과를 표시한다. 추가 페이지 조회에서는 기존 카드를 유지한다. aria-busy·상태 안내 및 동작 줄이기 환경의 애니메이션 비활성화를 지원한다. 프론트엔드 59개 검사 통과.
