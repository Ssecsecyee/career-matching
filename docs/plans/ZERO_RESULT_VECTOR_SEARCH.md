# AND 검색 0건의 벡터 유사 후보 연결

상태: 2026-11-14 운영 적용·공개 API 검증 완료. 최종 릴리스 20261114T052654Z.

## 실행 순서

사용자 검색 → Bedrock AND 계획 파싱 또는 직접 필터 요청 → 기존 ES/SQL AND 검색 → 1건 이상이면 기존 결과 → 0건이면 같은 계획의 직무·기술·검색 문구를 로컬 모델로 임베딩 → 별도 공고 섹션 벡터 색인 검색 → MySQL 원문·버전·마감·모집 상태 대조 → 유지할 필터 확인 → 최대 20개 유사 후보 표시 → 공고 선택·기존 역량 문답.

Bedrock에 OR 계획을 다시 만들게 하지 않는다. 이 경로는 추가 Bedrock 호출 없이 임베딩으로 실행하며, 벡터 전환이 시도되면 기존 AI 검색어 재보정 루프도 멈춘다. 일반 전체 목록 조회처럼 임베딩할 직무·기술·검색 문구가 없으면 실행하지 않는다. 다음 페이지가 끝난 상황도 새로운 유사 검색으로 자동 전환하지 않는다.

## 보존하는 조건과 구분

- 지역은 기존 AND 조건과 표기 보정을 유지한다.
- 명시적 필수 기술은 실제 저장 태그와 대조해 모두 요구한다.
- 기존 신입 원문 확인 필터를 유지한다. 주니어·경력 연수의 자동 판정은 기존 미구현 범위를 그대로 가진다.
- 회사명 필드 지정 검색은 지정한 회사명을 유지한다.
- 이미 제외한 공고 ID, 모집 종료·마감, 버전·원문 해시 불일치는 제외한다.
- 직무·자연어 검색 문구와 보유/선호 경험은 벡터 관련성으로 비교한다. 원래 AND 문구를 모두 충족했다고 주장하지 않는다.

원래 AND 계획·조회 시각·0건 결과를 search_context와 응답 이력에 남기고, vector_fallback에 별도 후보 수·유사도 기준·제외 건수·실패 코드를 기록한다. 기존 선택 공고와 문답은 전환만으로 삭제하지 않는다. UI는 AND 정확 일치 수와 유사 후보 수를 혼동하지 않도록 표시한다.

## 한계와 실패 처리

현재 벡터 색인은 채용만 지원한다. 교육 0건은 기존 AND 0건 안내를 유지한다. 벡터 상위 20개를 조회한 뒤 MySQL 및 유지 필터를 적용하므로 20개보다 적거나 0개일 수 있으며, 하위 순위 전체를 탐색해 유효 후보가 없음을 입증한 것은 아니다. 시험 색인의 자동 갱신은 별도 작업이다. 모델 입력 초과·메모리 부족·검색 장애 시 원래 AND 0건 결과와 유사 검색 불가 안내를 반환한다. 조용히 조건을 자르거나 필터를 빼지 않는다.

## 운영 설정과 검증

ENABLE_ZERO_RESULT_VECTOR_FALLBACK=true와 기존 ENABLE_TXT_VECTOR_SEARCH=true가 필요하다. 새 AWS 리소스·임베딩 API·DB 테이블은 추가하지 않는다. 549개 백엔드 테스트 통과(31개 선택 실행 제외), 프론트엔드 76개 테스트 통과 및 빌드 완료. 신규 검증은 0건 전환, 원래 AND 기록·선택 보존, 지역·필수 기술·신입 필터, 기능 비활성·빈 목록 임베딩 방지, 양성 결과 미전환, 모델 재검색 중단을 포함한다. 실제 모델의 정답셋 정확도 평가는 별도다.

운영 검증: AND 일치 0건에서 유사 후보 20건 반환(가상 입력, 8.24초). 존재하지 않는 필수 기술 추가 시 0건 유지. 최종 코드에서는 원문 변경 제외 0건, 필수 조건 제외 20건으로 구분 기록했다. 프론트엔드 자산 index-CVxuNFXe.js.
