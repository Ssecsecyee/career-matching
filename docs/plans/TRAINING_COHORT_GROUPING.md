# 교육 회차 묶음과 다른 과정 탐색

기준일: 2026-11-05
상태: 구현·로컬 검증 완료 / AWS 반영 예정

## 목적

같은 기관·과정의 회차만 바뀐 결과가 여러 카드를 차지하는 문제를 줄인다. 채용 검색, 교육 상태 분리, Vue 표기 수정은 유지한다.

## 묶음 기준

고용24 출처, course_key(서비스+과정 ID), collection_metadata.institution_id, 수강 방식, 저장 주소가 모두 같을 때만 묶는다. 제목만 같은 과정이나 다른 기관·지역은 합치지 않는다. 기관 ID·과정 식별자가 없거나 다른 출처이면 회차 단위로 유지한다. DB 원문·회차 행·ES 문서는 합치거나 삭제하지 않는다.

## 검색과 화면

- 기준 MySQL에서 검증한 검색 후보를 묶은 뒤 서로 다른 과정 최대 3개를 반환한다.
- 각 카드의 cohorts에는 이번 검색에서 확인한 회차를 최대 5개 보관한다. 더 관측했으면 cohorts_truncated를 표시한다. 기관 전체 회차 수라는 뜻은 아니다.
- 회차별 일정·모집 상태·비용·출처 링크·버전·해시는 따로 유지한다. 대표 회차의 비용을 다른 회차에 적용하지 않는다.
- 검색 기준 후보 수는 ES의 회차 문서 건수다. 서로 다른 과정 수가 아님을 안내한다.
- 확인 버튼은 표시할 모든 회차의 버전·해시를 재확인한다. 하나라도 바뀌면 기존 기준 확인 정책에 따라 다시 확인한다.
- 다른 교육 요청은 training_navigation.shown_groups에 기록한 묶음을 제외한다. 아직 표시하지 않은 같은 과정 회차로 목록을 다시 채우지 않는다. shown_ids도 기존대로 유지한다.
- ES는 다른 과정 3개를 채울 때까지 최대 10페이지·1000개 후보를 조회한다. MySQL 복귀도 최대 1000개 후보에서 묶는다. 한도에 닿으면 추가 과정이 있을 수 있다는 안내를 붙인다. 무제한 전체 회차 조회·정확한 고유 과정 총수 집계는 하지 않는다.
- 교육 상담에서 묶음과 회차 정보를 함께 전달하고, 각 회차 날짜 상태를 갱신한다. 개별 교육 설명 뒤 기존 목록을 다시 표시하는 문제는 별도 후속 작업이다.

## 검증

기관·과정·주소 구분, 같은 과정 회차 묶음, 표시하지 않은 후속 회차까지 다음 목록에서 제외, 식별자 없는 동명 과정 분리, 회차 상한과 정보 보존, 모든 표시 회차의 확인 서명, 100개 동일 회차 다음 검색 페이지의 다른 과정 수집을 검증했다. 실제 회차 컴포넌트에서 회차별 날짜·비용·링크 보존도 검사했다.

백엔드 전체 486건 중 455 통과·31 건너뜀, 프론트엔드 44건 통과·웹 빌드 통과. 모델 품질 정확도 평가나 전체 부하 검증은 아니다. DB 마이그레이션·재색인·추가 모델 호출은 필요하지 않다.
