# 교육 검색 AND·OR 관계 보존

기준일: 2026-11-05
상태: 구현·로컬 검증 완료 / AWS 반영·실제 모델 검증 예정

## 정정

직전 v6에서 데이터분석과 포트폴리오 동시 요청을 분야와 목표로 분리해 포트폴리오를 검색에서 뺀 것은 요구를 충족하지 못했다. 사용자가 함께 필요한 것으로 말한 조건은 검색 조건으로 보존한다. 직전 목표 분리 문서의 동시 요청 예시는 이 문서로 대체한다.

## 계약과 실행

context-intent-v7은 교육 topics와 topic_operator(and/or)를 사용한다. 데이터분석 교육을 듣고 포트폴리오도 만들고 싶다는 요청은 데이터분석 AND 포트폴리오, 둘 중 아무거나는 OR이다. 실제 문맥 관계는 모델이 판단한다. 여러 조건의 새 검색에서 연산자를 누락하면 스키마 검증으로 실행을 차단하며 임의 OR로 처리하지 않는다. 혼합 관계를 한 연산자로 표현할 수 없으면 확인 질문으로 관계를 확정한다. 중첩 Boolean 트리 도입은 이번 범위가 아니다.

ES는 주제별 검색 절의 minimum_should_match를 AND에서 전체 개수, OR에서 1로 설정한다. MySQL은 기존 주제별 태그 일치 절을 AND 또는 OR로 연결한다. 두 엔진의 텍스트 분석 범위는 기존대로 다르며 동일 결과 건수를 보장하지 않는다. 원본·색인·DB 스키마는 변경하지 않는다.

검색 기준에 모두 포함 AND 또는 하나 이상 OR를 표시한다. 세션의 검색 기준·확인 후 탐색·다음 결과·상담 문맥·검색 기록에 관계를 유지한다. ES 장애 시 MySQL에도 관계를 전달한다. 0건을 피하려고 조건을 삭제하거나 AND를 OR로 바꾸는 재검색은 하지 않는다. 사용자가 명시적으로 조건을 변경해야 한다.

learning_goals는 진짜 참고 희망만 보관하며 필수 조건을 검색에서 제거하는 용도로 쓰지 않는다. 이전 저장 요청·확인 화면은 소급 수정하지 않는다. 새 검색으로 확인한다. 저장 문서에 두 조건이 검색됐다는 사실은 해당 과정의 포트폴리오 제작 지원을 독립 검증했다는 뜻이 아니다.

## 검증

ES AND/OR 절, MySQL 매개변수·주제 그룹 연결, 확인·다음 결과의 연산자 유지, 0건 자동 완화 금지, 명시 OR 변경, 장애 복귀 관계 유지, 모델 연산자 누락 차단을 검증했다. 백엔드 전체 498건 중 467 통과·31 건너뜀. 실제 모델 정확도는 별도 소량 smoke 및 고정 평가셋으로 확인한다.
