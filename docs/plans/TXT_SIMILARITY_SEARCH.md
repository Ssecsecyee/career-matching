# TXT 조건 기반 유사 공고 검색

상태: 2026-11-14 공개 배포·기능 활성화 및 공개 API 가상 입력 검증 완료.

## 이번 범위

- 채팅 입력창의 + 버튼에서 UTF-8 TXT를 첨부하고 전송한다. 입력한 채팅 문구가 있으면 추가 조건으로 함께 검색한다. 별도 공고 업로드 패널은 제거했다. 20KB 이하, 모델 입력 2,048토큰 이하로 제한하며 초과 입력은 자동으로 자르지 않는다.
- 여러 경험·기술·희망 조건의 의미적 관련성을 기준으로 최대 20개 공고를 제시한다. 파일의 모든 조건을 AND 필수 필터로 해석하지 않는다. 지역·경력 등 엄격한 필터와의 결합은 후속 범위다.
- 자격요건·우대요건 전체 섹션 벡터의 최대 코사인 값이 초기 순위 기준이다. 전체 일치 건수·지원 자격 충족률이 아니다.
- MySQL에서 모집 상태·마감·버전·두 원문 해시를 다시 확인하고 바뀐 후보를 제외한다. 자동으로 다른 검색 방식으로 대체하지 않는다.
- 기존 공고 선택·역량 문답을 재사용한다. 이미 선택한 공고와 답변은 새 공고를 선택하기 전까지 유지한다.

## 보관과 실행

파일명은 서버로 보내지 않는다. 텍스트는 기존 비동기 요청 저장소에서 만료 기준 24시간으로 임시 처리되며 실제 TTL 삭제 시점은 지연될 수 있다. 대화 MySQL에는 원문 대신 SHA256·바이트 크기와 검색 결과를 남긴다. 공고 벡터 색인과 공용 벡터 캐시에 사용자 입력을 넣지 않는다. 추론용 RAM 임시 파일은 처리 후 삭제한다. 개인정보 입력은 제외하도록 안내한다.

별도 모델 환경의 txt_query.py를 고정 경로로 호출한다. 외부 임베딩 API와 Bedrock 분류·답변 호출은 사용하지 않는다. 모델 프로세스는 요청마다 실행되며, 메모리 여유 1,200MiB 미만이면 거부하고 90초 시간 제한을 둔다. 기존 단일 작업자 큐에서 순차 처리하므로 실시간 대화 지연 영향은 공개 활성화 전 확인해야 한다.

## 연결 범위와 후속 검증

1. EC2 /opt/career/vector-pilot-20261114/txt_query.py를 배치하고 테스트한다.
2. 백엔드·API 검증 코드와 프론트엔드를 함께 배포한다. ENABLE_TXT_VECTOR_SEARCH=true는 서버 검증 후 활성화한다. 코드 기본값은 비활성이며 이번 서버에서는 명시적으로 활성화했다.
3. 실제 길이 TXT의 입력 초과·실패·재시도와 기존 문답을 운영 연결에서 검증한다.
4. 벡터 색인의 자동 갱신은 아직 별도 작업이다. 현재 시험 색인 시점 이후 신규 공고가 모두 포함된다고 안내하지 않는다.

## 검증

신규 테스트 6개: 원문 변경·버전 변경·마감 제외, 선택 공고 보존, 원문 기록 제거, 입력 검증, 비활성 상태 모델 미호출. 기존 테스트와 UI 빌드 결과는 작업 결과에서 별도 보고한다. 정식 검색 정확도 수치는 아직 없다.

검증 결과: AWS_project 환경 백엔드 540개 테스트 통과(31개 선택 실행 제외), 프론트엔드 72개 통과 및 빌드 성공. 공개 API 가상 경험 검색은 3.71초에 20건 반환했다. 긴 입력·다중 사용자 부하 성능이나 정식 정확도 수치는 아니다.
