# 자격요건·우대요건 섹션 벡터 검색 시험

상태: 2026-11-14 별도 시험 색인 구축·검색 검증 완료. 638건·1,276개 섹션 벡터. 일반 사용자 검색 경로 전환 전.

## 고정한 범위

- 입력 범위는 운영 `career-jobs-read`에서 현재 노출 정책을 통과하는 공고다. 전체 MySQL 공고나 교육을 일괄 벡터화하지 않는다.
- 공고마다 자격요건 전체 1개, 우대요건 전체 1개의 벡터를 생성한다. 문장별 분리나 AI 요약은 하지 않는다.
- MySQL 원문과 기존 Elasticsearch 키워드 색인·동의어·별칭은 유지한다. 별도 `career-job-vectors-pilot-*` 시험 색인에만 기록한다.
- 자소서는 같은 임베딩 모델의 검색 벡터로 사용한다. 공용 공고 색인과 섹션 캐시에 자소서 원문·벡터를 넣지 않는다.
- 벡터 유사도는 관련 후보 탐색에만 사용한다. 공고 선택 후 기존 필수·우대조건 문답으로 자기보고 역량을 확인하는 흐름을 재사용한다.

## EC2 로컬 모델

외부 임베딩 API 대신 `Alibaba-NLP/gte-multilingual-base`의 고정 ONNX 변환본을 EC2 CPU에서 실행한다. ONNX 저장소는 `onnx-community/gte-multilingual-base`, 고정 revision은 `2edbf5e672aab465f9ed4c154a8b61791c082c69`다. int8 모델 파일을 사용하고 임의의 원격 Python 코드는 실행하지 않는다. 원본 모델 카드의 CLS pooling 및 L2 normalization을 따르며 출력은 768차원이다.

모델 자체의 최대 입력은 8,192토큰이지만, 공유 EC2 시험에서는 2,048토큰으로 제한한다. 이 한도는 자동 자르기가 아니라 명시적인 입력 거부 한도다. 공고 섹션 중 하나라도 초과하면 전체 색인 전 검사에서 중단한다. 긴 자소서도 조용히 잘라내지 않는다. 더 긴 입력 지원은 별도 자원·품질 검증 후 결정한다.

별도 Python 가상환경과 모델 캐시를 `/opt/career/vector-pilot-20261114`에 둔다. 기존 worker Python 환경에 패키지를 설치하지 않는다. 시험은 `MemoryMax=1000M`, `CPUQuota=50%`, `Nice=10`을 적용한다. 서버 증설·새 유료 AWS 리소스·외부 임베딩 API 호출은 이 시험 범위에 없다. 기존 EC2 고정비와 CPU·네트워크 사용 자체는 계속 존재한다.

## 연결 계약과 검색

기존 ES 문서 ID를 유지하고 `source`, 문자열 `source_id`, `source_version`, 두 섹션 원문·SHA256, 모델 지문을 보관한다. 현재 운영 ES에는 내부 MySQL `job_id`가 없으므로 이를 임의로 만들지 않고 `(source, source_id)`로 연결한다.

검색은 자격요건·우대요건 필드를 각각 정확 코사인 검색하고 공고 ID로 합친다. 초기 기준은 두 섹션 점수 중 큰 값을 사용하며, 튜닝된 가중치나 지원 가능 점수라고 주장하지 않는다. 실제 화면 연결 전 MySQL 원문·버전·현재 상태 재조회와 소유권·입력 보호·사용량 제한을 기존 서비스 경계에 연결해야 한다.

시험 검색에서는 현재 운영 ES 사본과 버전·섹션 원문을 다시 비교해 변경·삭제된 후보를 제외한다. 날짜와 모집 상태 필터도 유지한다. 과거 원문을 검색 색인만으로 복원할 수 있다고 가정하지 않는다.

## 검증과 후속 단계

1. 원문 섹션 보존, 빈 섹션, 캐시 무효화, 차원·정규화, 오래된 후보 제외, 무단 자르기 방지의 오프라인 테스트.
2. EC2에서 20건 표본 색인과 자원 사용 관찰.
3. 현재 ES 노출 공고 전체 색인, 문서·벡터 필드 수 대조.
4. 개인정보 없는 가상 자소서의 검색·모델 계약·근거 연결 확인. 이는 정식 정확도 평가가 아니다.
5. 고정 정답셋으로 키워드·벡터·하이브리드를 비교하고 별도 통합 결정.
6. 검증 후 사용자 입력 UI, 선택 공고 문답 연계, outbox 기반 변경·마감·삭제 동기화를 구현한다. 현재 키워드 outbox가 벡터까지 자동 갱신한다고 표현하지 않는다.

운영 배포 전에는 자소서에 포함될 수 있는 개인정보의 입력 안내·전송·로그·보관 정책, 공개 시험 남용 제한, 최장 입력의 메모리·지연을 추가 검증한다. 이번 시험만으로 일반 사용자에게 벡터 검색이 활성화되지는 않는다.
