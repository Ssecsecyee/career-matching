# 검색 조건 AND 고정 정책

상태: 2026-11-14 구현·검증·운영 적용 완료. 릴리스 20261114T045936Z. 운영 worker 정상, AND 쿼리 생성과 모델 OR 출력 거부를 추가 확인했다.

## 현재 정책

- Bedrock은 검색할 서로 다른 조건을 AND로만 추출한다. 교육 topic_operator는 and만 허용하는 스키마를 사용한다. 대안 중 하나만 원하는 사용자 발언이면 우선 조건을 확인하고 임의의 OR 검색을 실행하지 않는다.
- 채용의 지역·직무 목록과 필수 기술은 각 조건 그룹을 모두 만족해야 한다. 예를 들어 지역을 부산과 경남 모두 지정하면 둘을 포함한 저장 공고만 검색하므로 0건일 수 있다.
- 역할·지역·기술의 동의어/표기는 한 조건 안에서 대체 표기로 인식한다. 깃/Git, 경기/경기도를 서로 다른 필수 조건으로 누적하지 않는다. 상태·마감의 정상적인 노출 정책 내부 대안 역시 검색 조건의 OR 선택 기능과 구분한다.
- 단순 보유 경험은 기존처럼 순위 참고 정보다. 직무·필수 기술 없이 보유 기술만으로 검색을 시작하는 경우에는 해당 기술 앵커를 모두 요구한다. 명시적으로 선택적인 선호 기술은 순위에만 반영한다.
- 교육의 서로 다른 주제는 모두 포함한다. ES·MySQL 및 장애 시 복귀 경로가 같은 AND 정책을 사용한다. 이전 세션의 or 설정은 새 조회 시 and로 정규화한다.
- 0건일 때 조건 삭제나 OR 완화를 자동으로 수행하지 않는다. 적용 조건을 보여주고 사용자가 변경하게 한다.

## 변경하지 않는 부분

공고 원문 자격요건의 Python 또는 Java 같은 AND/OR 관계는 변경하지 않는다. 조건 문답은 원문을 보존한다. TXT 벡터 검색은 여전히 전체 텍스트 의미의 관련 후보 탐색이며, 이 변경으로 모든 키워드를 충족하는 AND 필터가 되지는 않는다. TXT에서 엄격한 조건을 별도 추출해 결합하는 기능은 후속 범위다.
