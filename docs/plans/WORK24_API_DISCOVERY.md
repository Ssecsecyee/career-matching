# 고용24 서비스별 접근·응답·매핑 조사

상태: 서비스별 목록 표본 및 훈련 4종 상세·일정 표본 조회 완료 / 최종 매핑・구현 전
기준일: 2026-11-04

화면의 승인 상태와 실제 API 호출 성공을 분리한다. 채용정보는 사용자 확인상 현재 접근 불가이며 이번 연결 대상에서 보류한다. 다른 서비스는 목록 표본을 조회했고 훈련 4종은 상세·일정 표본도 확인했다. 모든 하위 API나 전체 데이터의 검증 완료를 뜻하지 않는다. 최신 통합 범위와 NCS 연결은 [훈련 통합·NCS 설계](WORK24_TRAINING_NCS_MODEL.md)를 기준으로 한다. 구직자 취업역량 강화프로그램은 이번 통합 대상에서 제외한다. 화면의 인증값은 문서/코드/로그에 복사하지 않는다.

## 엔드포인트 단위 조사 계약

서비스별 목록·상세·기관·일정·하위 코드 API를 각각 행으로 관리한다. 서비스 이름 하나로 모두 성공 처리하지 않는다.

- 식별: service_code, endpoint_code, official_doc_url, endpoint_url(인증값 없음), method, format, schema_version.
- 접근: status=not_tested/success/empty/denied/invalid_request/transient_failure/discontinued, HTTP 상태, 제공자 결과 코드, 관측 시각, 매개변수 형태(비밀 제외).
- 응답: root/배열 경로, 목록 수/총수/페이지, 단일 객체/배열 변동, 타입·빈 값, 식별 키/회차/기관 키, 코드·날짜·상태·비용·본문 제공 범위.
- 매핑: 원본 경로, 공통 필드, 변환 규칙, 정밀도/단위, NULL 처리, 매핑 근거, 미지원 사유.
- 결과: raw 스냅샷 경로·해시, 스키마 지문, 검사 결과, 권한·이용 범위 확인, 다음 조치.

HTTP 200만으로 성공 판정하지 않는다. XML/JSON 본문의 오류를 파싱하고, 0건 정상 응답을 인증 실패와 구분한다. 요청 조건 오류·권한 오류·일시 장애도 분리한다. 로그에는 인증키·전체 인증 URL·인증 헤더·원문 오류의 민감정보를 출력하지 않는다.

## 수집과 검증 단계

1. 공식 명세에서 각 endpoint와 필수 매개변수를 확인한다. 문서 예제의 과거 날짜를 그대로 사용하지 않는다.
2. 실제 허용 키는 Git 제외 로컬 비밀 설정에서 읽는다. 엔드포인트별 키/권한을 구분하고 한 서비스 키를 전체에 재사용한다고 가정하지 않는다.
3. 최초 목록 1페이지에서 1~3건만 조회한다. 목록에서 얻은 실제 식별자로 상세/기관/일정을 조회하고 서비스당 초기 최대 10건으로 제한한다. 전체 수집과 운영 DB 반영은 이 단계에서 하지 않는다.
4. 응답 원문을 비공개 staging에 보관하고 필드·타입·오류·권한 행렬을 작성한다. 재시도는 호출 제한을 확인한 뒤 제한적으로 허용한다.
5. 출처별 어댑터를 작성한다. training_offerings는 공통 목적 모델로 사용하되 모든 서비스 원문을 억지로 같은 필드에 넣지 않는다. 기준정보/기업정보/프로그램은 별도 모델 적합성을 검토한다.
6. 격리 DB에서 식별·중복·빈 값 보존·기간·비용·지원 자격·이전 스냅샷 재적재·트랜잭션/Outbox를 검증한다.
7. 승인 표본만 백업 후 AWS에 반영하고 교육 ES와 검색/조건/근거 연결을 검증한다. 직업/직무 기준자료 색인은 별도 필요성 결정 후 만든다.
8. 그 후 주기 갱신·중단/재개·실패 알림을 연결한다. 원본 응답 스키마 변화는 경보/격리 대상으로 한다.

## 공통 모델 주의점

원본 필드명은 raw_detail에 유지하고 별도 어댑터가 공통 필드로 변환한다. 최종 식별자는 API 실제 고유성 검증 후 출처+과정/회차/기관 등을 조합한다. 같은 과정이 여러 API에 나타날 수 있어 API 구분자로 무조건 별도 과정을 만들지 않으며 출처 관측과 실제 과정 정체성을 나눠 검토한다.

훈련 시작/종료일은 접수기간이 아니다. 총훈련비·지원금·개인 자부담을 구분하고, 빈 값을 0원/무료로 바꾸지 않는다. 기술 키워드가 제목에 있다는 이유만으로 상세 커리큘럼 충족으로 판정하지 않는다. NCS/KECO/직업/직무 코드는 별도 체계이며 분류 일치가 세부 역량 충족을 보증하지 않는다.

각 필드는 원본 사실·코드명 변환·AI 추론을 구분한다. AI 매핑이 필요하면 모델/변환 버전과 근거·미확인 상태를 저장한다. 코드 기준자료는 바로 현재 공고의 강제 필터나 사용자 숙련도 점수로 사용하지 않는다.

## 1차 표본 결과 (2026-11-04)

서비스 코드와 실행 결과를 기존 서비스 밖 `C:/AWS_project/고용24_API_검증`에 분리했다. 서비스별 주석이 달린 .env를 사용자가 입력했고 실제 인증값은 문서/코드/로그에 복사하지 않았다. 채용정보는 재호출하지 않았다.

- 실제 조회13회: 9개 서비스가 최소 한 하위 API에서 데이터 반환. 데이터 응답12회, 긴 표준직무 문장의 빈 result1회. 짧은 '소프트웨어 개발' 조건은 별도3건 반환.
- 훈련4종: 각 목록3건, 식별/기관/회차/기간/NCS 필드 확인. 이번 표본 contents는 비어 있어 상세 커리큘럼 확보로 볼 수 없음.
- 공통코드: NCS대분류24, 지역21, KECO대분류35개. NCS/KECO 표본은 useYn 미제공이며 코드 선행0 보존.

- 취업지원 프로그램3건과 강소기업3건 확인. 각각 프로그램/기업 기준자료이며 채용공고 또는 기술교육으로 취급하지 않음.
- 직무사전3건: 능력단위 정의·지식기술태도 배열 제공. 코드처럼 보이는 필드의 실제 값이 URI인 사례와 키워드의 다른 도메인 결과를 확인.
- 단위검사14개 통과, .env 외 일반 산출물의 실제 인증값 잔존0건 확인. DB/ES/AWS 변경·실제 모델 호출 없음.
