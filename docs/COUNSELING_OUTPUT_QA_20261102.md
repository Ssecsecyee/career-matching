# 상담 출력 상한 확대와 후속 QA 결과

기준일: 2026-11-02. 사용자가 QA 시점의 출력 제한 확대를 요청하여 이전 ‘출력 제한 변경 보류’ 결정을 해제했다. 릴리스 `20261102T051944Z`로 기존 Lambda·EC2 백엔드에 배포 완료했다. 웹 변경과 새 인프라/DB 마이그레이션은 없다.

## 적용한 설정

- BedrockPlanner.route의 대화·의도 분기 출력 상한을 **1,024 → 4,096토큰**으로 변경. prompts.py의 CONVERSATION_MAX_TOKENS로 관리한다.
- 별도 plan()의 기본 출력 512와 개별 조건 questioner의 1,024, 일반 사용자 세션 모델 호출 횟수 12회 제한은 유지한다.
- JSON 단일 객체·정해진 출력 계약·reply 최대 4,000자 검증은 유지한다. 프롬프트는 답변을 3,000자 이내로 완결하도록 안내한다.
- 스트리밍 reply 접두부 최대 4,000자, 진행 전달 5,000자, 원시 JSON 20,000자/65초 보호는 유지한다. 무제한 생성이나 형식 검사 해제는 하지 않는다.
- 제공자가 max_tokens로 종료한 경우 ModelOutputTruncatedError로 구분해 기존 사용량·오류 코드에 남기고 대화 보존/짧은 재요청 안내를 반환한다. 자동 유료 재호출은 하지 않는다.
- 버전: conversation-qa-budget-v8. 실제 비용은 생성 토큰 수에 따라 증가할 수 있고 maxTokens 증가는 예약 쿼터에도 영향을 줄 수 있다. 단순히 상한을 올렸다고 매번 4,096토큰을 생성했다는 뜻은 아니다.

## 실제 QA — 전체 해결로 표현하지 않음

별도 QA 세션에서 합성 자기평가 답변으로 문답을 마친 뒤 실제 상담을 호출했다. 기존 사용자 대화는 수정하지 않았고 검증 대화·호출 사용량은 기존 DB에 기록했다.

| 사례 | 관측 |
|---|---|
| 이력서·포트폴리오 연결 | 정상 conversation 응답, 1,129자, 약 11.92초 |
| 보완 방향 정리 | 출력 1,136토큰에서 ModelOutputFormatError. 새 4,096 상한 도달 아님 |
| 보완 방향 추가 진단 1회 | 입력 7,931 / 출력 1,758토큰, 종료 end_turn, 원시 응답 1,778자, 허용 JSON 객체 검사 실패 |

총 실제 모델 호출은 최초 QA 2회와 추가 진단 1회다. 원시 모델/사용자 텍스트를 진단 결과에 기록하거나 출력하지 않고 종료 사유·길이·JSON 구조 통계만 보관했다.

이전 1,024토큰 상한은 실패 가능성이었지만 모든 형식 오류의 확정 원인은 아니었다. 확대 후에도 end_turn에서 JSON 형식 실패가 재현돼 **출력 예산과 출력 형식 준수 문제를 분리해야 함**을 확인했다. 상한 확대만으로 두 후속 상담이 모두 정상화됐다고 주장하지 않는다.

## 다음 QA 항목

1. 보완 상담이 대화용 JSON 외의 형태를 반환하는 원인을 확인하고 출력 계약 준수를 보강한다. 원문에서 임의 JSON 조각을 긁어 실행하거나 형식 검사를 무작정 해제하지 않는다.
2. 학습을 명시적으로 요청하지 않았거나 연결할 기술 주제가 없는 문답 결과에서 need_topic 교육 안내를 자동 노출하는 흐름을 별도 QA한다.
3. 더 큰 출력의 지연·스트리밍 시간 보호·쿼터·실제 토큰 비용을 관측한다. 추가 상한 확대보다 실패 원인에 맞는 처리를 우선한다.

## 후속 설계: 검색과 상담 경로 분리

[분리 개선 계획](SEARCH_CONSULTATION_SEPARATION_PLAN.md)을 작성했다. 실패한 route 응답을 곧바로 Elasticsearch 검색 실행 증거로 해석하지 않는다. 목적이 정해진 상담 버튼은 별도 상담 경로와 자연어 어댑터를 사용하고 서버가 응답 JSON을 구성하도록 개선한다. 검색 계획 검증을 느슨하게 하거나 모든 형식 오류를 토큰 부족으로 처리하는 방향은 아니다. 현재는 문서 단계다.
