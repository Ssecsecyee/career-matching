# 채용 수요·역량강화 훈련 공급 통계 활용 계획

작성일: 2026-11-02. 사용자 제안에 따른 **후속 분석·정책 보고 활용 계획**이다. 현재 통계를 산출하거나 교육 공급 부족·인력 부족을 확인한 결과가 아니다. 고용24 API 연동·공통 DB 적재·출처/날짜/중복 검증을 먼저 끝낸 뒤 수행한다.

## 1. 목적과 보고 대상

채용공고에서 기업이 요구하는 역량과 교육·훈련 커리큘럼에서 실제로 가르치는 역량을 같은 기준으로 연결한다. 교육부·훈련기관 등 교육 정책/과정 설계 담당자가 '수집 범위에서 어떤 역량의 요구 비중이 높고, 어느 분야 훈련의 보완을 검토할 수 있는가'를 수치와 원문 근거로 볼 수 있게 하는 방향이다. 정부 제출·협약·공식 통계 승인 또는 특정 기관의 확정된 요구가 있다는 뜻은 아니다.

예상 보고 흐름: 기업 요구 역량 집계 → 직종·지역·경력별 비교 → 훈련 학습내용 매핑 → 수요/교육 커버리지의 상대적 공백 검토 → 과정 개선 후보 제안. 구직자 개인의 자기평가 부족과 시장 전체의 수요/공급 공백은 별개다.

## 2. SQL 정규화의 역할

검색 실험에서 사용한 정규화 아이디어를 통계용 전처리·공통 역량 ID·집계에 활용한다. **끝의 을/를을 무조건 제거한 실험 규칙을 전 분야에 그대로 적용하지 않는다.**

- 대소문자·공백 표준화와 검증된 별칭 매핑으로 같은 역량의 중복 집계를 줄인다.
- 공통 skill_id와 원문 표현을 함께 보관한다. React/react.js/리액트처럼 확인한 별칭만 연결한다. C/C++/C#, 서로 다른 면허·직종을 구두점 제거나 접두사로 합치지 않는다.
- 직종·지역·학력·경력·공식 코드와 자유 서술 역량을 구분한다. 실제 명세가 제공하는 코드/분류를 검증한 후 연결하며 공통코드나 NCS와의 대응을 추정 확정하지 않는다.
- 채용은 필수·우대·주요업무·단순 소개를 구분한다. '경험 불필요/무관'와 '필수'를 같은 요구로 세지 않는다.
- 훈련은 가르치는 내용과 입학 선수조건을 구분한다. 'React 경험자 지원 가능'을 React 교육 공급으로 세지 않는다. 제목에만 있는 홍보 문구와 실제 커리큘럼 근거도 구분한다.
- Nori/규칙/모델로 추출을 보조할 수 있지만 원문 인용·필드·출처 ID/버전·관측 시각·분류 규칙 버전과 검증 상태를 남긴다. 문자열 포함만으로 의미·필수성·교육 성과를 확정하지 않는다.
- 원본은 보존하고 수집/갱신 시점에 정규화한 분석용 사실과 집계 스냅샷을 만든다. 사용자가 볼 때마다 모든 본문에 정규식을 적용하지 않는다. SQL GROUP BY/JOIN 등으로 집계하며 검색 엔진 운영과 통계 계산을 분리한다.

## 3. 분석 단위와 분모

- 채용 기본 단위는 공고(source+ID)이며 기업 수·채용 인원 수와 같지 않다. 한 공고의 동일 역량 반복 언급은 1회로 센다. 필수/우대 동시 언급의 중복 처리 정책은 먼저 고정하고 각각도 보고한다.
- 재수집·버전 갱신을 새 공고로 중복 계산하지 않는다. 재게시·다른 출처의 같은 공고·채용대행 중복은 별도 중복 판정과 근거를 관리하며 임의 회사명 병합을 하지 않는다.
- 훈련 과정과 모집 회차를 구분한다. 고유 과정 수·해당 기간 실제 개설 회차·기관 수를 각각 집계한다. 제목이 같은 여러 기수를 독립 신규 교육과정으로 과대 집계하지 않는다.
- 동일 직종·지역·경력·관측 기간과 포함 기준을 명시한다. 월별 변화는 같은 수집 범위·관측 창·규칙 버전에서 비교한다. 등록일 미확인 자료는 관측 시점을 등록 시점으로 둔갑시키지 않는다.
- 결측 커리큘럼·모집 상태 unknown·모집 마감/훈련 기간을 분리하고 분석 가능 비율을 함께 제시한다. 자료가 없다는 이유로 해당 역량을 가르치지 않는다고 확정하지 않는다.

## 4. 제안 지표

| 지표 | 산식·단위 | 해석 |
|---|---|---|
| 역량 요구 공고 수 | 해당 역량의 검증된 요구가 있는 고유 공고 수 | 기업 수나 채용 인원 수가 아님 |
| 역량 요구 비중 | 해당 역량 요구 공고 / 같은 직종·지역·기간의 기준 공고 | 필수/우대·원문 확보 여부를 나눠 보고 |
| 요구 기업 수 | 해당 역량 요구 공고의 검증된 고유 기업 수 | 기업 ID 미제공 시 중복 처리·결측을 명시 |
| 교육 과정 커버리지 | 실제 커리큘럼에 해당 역량 근거가 있는 고유 과정 / 커리큘럼 확보 과정 | 입학 선수조건은 제외. 전체 과정 중 자료 확보 비율도 병기 |
| 실제 개설 회차 수 | 기간·일정이 확인된 해당 역량 과정의 모집/개설 회차 | 현재 모집 가능한 회차와 과거 회차 구분 |
| 학습 깊이 | 기초·심화·프로젝트 등 명시된 학습 내용 분류 | 키워드 출현만으로 숙련도·교육 품질을 추정하지 않음 |
| 시간·정원 공급 | 검증된 학습시간·정원·개설 회차가 제공될 때 별도 집계 | 미제공 값은0이 아니라 미확인. 전체 과정 시간을 역량별 시간으로 복제하지 않음 |
| 기간별 변화 | 같은 범위의 요구 비중·과정 커버리지·모집 회차의 변화 | 수집 범위/분류 규칙 변경 효과와 구분 |

수요 비중과 교육 커버리지를 함께 보는 분포/매트릭스로 '보완 검토 후보'를 찾는다. 공고 수/과정 수는 단위가 다르므로 나눈 값이나 단순 비중 차이를 '부족 인원·부족률'로 명명하지 않는다. 단일 공백 점수·가중치·상위 선정 기준은 아직 미정이다. 기업수·정원·지역 접근성·훈련 수준·학습성과가 확보돼야 교육 확대의 실질적 필요를 추가 검토할 수 있다.

## 5. 보고 형식 예시 (실측 아님)

> 분석 기간과 수집한 직종 범위에서 역량 A의 요구 공고 비중은 D%, 학습내용이 확인된 과정 중 해당 역량을 다루는 비중은 T%였다. 다만 상세 커리큘럼 확보율은 C%이며 정원/학습 깊이는 별도 확인이 필요하다. 이 결과를 바탕으로 해당 역량의 훈련 보완 여부를 검토한다.

D/T/C는 형식 설명용 변수이며 실제 값을 만들지 않았다. '요즘 모든 기업이 A 인재를 원한다', '교육부 훈련이 부족하다', '이 과정을 늘리면 취업률이 오른다'로 확장하지 않는다. 확보한 공고·과정은 관측 표본이며 전국 전체 기업/교육의 대표 표본이라는 보장은 없다.

## 6. 검증과 산출물

1. 고용24 채용·훈련 API 승인/적재/동기화와 실제 필드 확보.
2. 분석 기간·직종·지역·기업/공고/과정/회차 단위·중복 정책 확정.
3. 공통 역량 사전과 별칭/품사/의미 분류 규칙 작성. 다른 분야·미사용 표현 표본 검증.
4. 사람이 확인한 채용 요구/교육 커리큘럼 추출 표본으로 정확성·누락·필수/우대·선수조건 혼동을 평가.
5. SQL 정규화 사실·기간별 집계 생성. 단순 태그 검색 실험의 높은 점수를 이 통계 추출 정확도로 재사용하지 않음.
6. 수요표·교육 커버리지표·교차표·추세 그래프·원문 근거·결측/수집 범위와 한계 보고서 작성.
7. 기관 검토와 실제 교육 내용/정원/성과 확인 후 과정 개선 제안. 개인 대화 기록을 시장 수요 통계로 섞지 않음.

스키마는 후속 확정 사항이다. 필요 시 공통 역량 사전, 채용 역량 근거, 훈련 학습내용 근거, 집계 실행/버전/스냅샷을 별도 분석 구조로 검토한다. 이번에는 테이블 생성·DDL·기존 고객 DB 변경·자동 통계를 구현하지 않는다. 원문 데이터 이용/보관 범위와 개인정보를 확인하고 기관·지역별 작은 집계의 공개 기준도 정한다.

분석 코드는 서비스 밖 C:/AWS_project/역량통계_분석/<실행 ID>/code에 두는 방향이며 실제 디렉터리/실행기는 분석 착수 시 만든다. 발표·정책 검토용 MD/CSV/그래프는 C:/AWS_project/발표용_진행정리/<분석 ID>/에 보관한다. API 키·임시 URL·고객 원문은 공개 자료에 포함하지 않는다.
