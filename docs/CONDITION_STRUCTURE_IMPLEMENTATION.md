# 원문 보존 조건 분리 1차 구현 기록

기준일: 2026-11-02. **로컬 코드·회귀 검사·화면 빌드 및 AWS 배포 완료**. 최신 결과는 [실서비스 배포 검증](CONDITION_STRUCTURE_DEPLOYMENT_20261102.md)을 따른다. 아래 미배포 표현은 구현 당시 기록이다. 실제 Bedrock 호출·운영 DB 쓰기·테이블 변경·출력 제한 변경은 하지 않았다.

## 변경 내용

- `services/condition_structure.py`에 원문 연결 분리기와 검증기를 분리했다. 기존 `memory.split_conditions`는 이 구현을 사용한다.
- `ㆍ`를 포함한 글머리표·번호를 인식하고 같은 수준의 항목을 나눈다. 들여쓴 하위 목록, 괄호 설명, ‘또는/혹은/및/AND/OR’로 시작하는 이어지는 조건은 보수적으로 묶는다.
- 추가 기술스택 목록은 개별 필수/우대 능력으로 재해석하지 않고 원문 묶음으로 유지한다. 개별 기술을 모두 검증한 것이 아니며 일부 해당 시 미확인과 보충 설명을 이용하도록 문답·요약 화면에서 안내한다.
- 표시용 요약에서 `ㆍ`를 제거하되 실제 quote와 저장 원문은 변경하지 않는다. 원문의 들여쓰기·내부 줄바꿈·CRLF를 보존한다.

## 원문 연결과 검증

각 조건에 parser_version, section_hash, source_spans, offset_unit, parse_status, parse_notes를 연결한다. 공고/원문 버전과 파서·섹션 해시로 식별자를 생성하여 같은 위치 번호가 새 분리 규칙의 조건으로 오인되지 않도록 한다.

- 문자 위치는 Python Unicode 코드포인트 기준 시작 포함·끝 제외다. UTF-8 바이트 위치나 브라우저 UTF-16 위치와 혼용하지 않는다.
- 항목 원문은 저장 섹션의 정확한 부분 문자열에서 가져온다. 제목 문맥을 반복 연결할 때는 비연속 구간 목록으로 표현하고 단어를 생성하지 않는다.
- 섹션 UTF-8 해시·인용 일치·본문 구간 중복·설명되지 않은 비공백 원문 누락을 검사한다. 제목 문맥의 공유와 본문 중복은 구분한다.
- 끝에 본문 없는 제목이 남는 등 검증이 실패하면 전체 섹션을 검토 필요 묶음으로 보존한다. 40개 항목 초과는 기존 제한대로 명시적 오류로 처리하고 일부를 버리지 않는다.
- `validated_boundaries`는 원문 경계의 기계적 검증 상태다. 사용자 역량 검증이나 의미상 올바른 분리의 사람 평가를 뜻하지 않는다.

## 답변·이전 세션과의 호환

- 새 답변/근거는 조건 ID·파서 버전·섹션 해시·원문 위치와 함께 저장한다. 기존 recommendation_evidence.requirement_snapshot JSON에 source_binding을 추가하며 DDL은 변경하지 않는다.
- 새 분리 규칙으로 공고를 다시 선택했을 때 예전 묶음 답변을 새 항목에 자동 배분하지 않는다. 같은 문구라도 구형 파서에서 받은 답변을 새 규칙의 확인으로 자동 승계하지 않는다.
- 동일한 새 파서·공고 버전·섹션·원문으로 확인했던 답변은 기존 조건 재사용 정책 안에서 유지할 수 있다. unknown은 자동 재사용하지 않는다.
- 이미 열린 구형 세션의 conditions/checks는 도중에 재분리하지 않는다. 기존 질문과 당시 원문으로 마칠 수 있으며 새 선택부터 새 규칙을 사용한다. 오래된 question_id로 새 문답에 답하면 차단한다.
- 선택값과 ‘일부만 해당’ 같은 보충 설명을 함께 보존한다. unknown을 unmet으로 바꾸거나 기술 목록 전체를 개별 충족으로 추정하지 않는다. 묶음 안내는 후속 상담 문맥에도 전달한다.

## 아직 하지 않은 부분

- 파싱 시점은 현재 공고 선택 단계다. 전체 수집·정제 파이프라인에서 공통 조건 세트를 미리 생성·저장하는 기능은 다음 단계다.
- 별도 공통 조건 테이블/JSON 저장 계약·원문 이력 보관·운영 일괄 재정제는 미실행이다. 기존 세션 JSON에 문답 원문과 연결 메타데이터를 저장하는 것과 구분한다.
- 모든 중첩·암묵적 대안·표 형태를 의미적으로 분석하지 않는다. 애매한 구조를 묶음으로 유지하고 QA 대상으로 표시하는 보수적 구현이다.
- 상담 출력 제한과 형식 오류 대응, 학습 루트 추천 고도화는 이번에 수정하지 않았다.
- 구현 코드와 회귀 테스트의 Git 커밋은 `122a018a03caa7ba5351812d196ae2d2999fdfe7`다. 이후 AWS 배포와 모델 호출 없는 실서비스 검증까지 완료했다. 상세 결과는 배포 기록을 따른다. 배포 후 새 선택과 기존 세션의 호환을 실제 서비스에서 확인해야 한다.
