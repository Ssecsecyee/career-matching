# 조건 분류 실제 모델 소량 검증

실행일: 2026-11-03 / 상태: 운영 활성화 보류

## 범위와 방법
운영 DB의 공개 공고 55186723, 55406955, 55407438의 조건 32개를 읽고 기존 condition-review-v1 분류기로 Sonnet을 호출했다. 모델 결과를 보기 전에 에이전트가 ask/reference/review 비교 라벨을 로컬 파일에 고정했다. 독립적인 사람 정답셋이 아니므로 정확도 입증이나 최종 평가로 해석하지 않는다. 원문·예측·토큰 집계는 Git 제외 경로 infra/.build/condition-live-qa-20261103에 저장했다. 사용자 대화나 비밀값은 포함하지 않았다.

## 결과
- 첫 실행: 3개 공고 중 2개 형식·ID·원문 근거 검증 통과, 1개 출력 검증 실패.
- 통과한 조건 22개: ask 16개, reference 6개. 사전 에이전트 라벨과 20/22 일치. 실패 공고의 10개 조건은 일치율 분모에서 빠지므로 이 수치를 전체 정확도로 제시하지 않는다.
- 학력무관은 reference, 명시적 경력·학위·기술 조건은 ask로 유지했다.
- 실패 공고를 진단 목적으로 1회 반복했지만 다시 실패했다. 반복 응답은 JSONDecodeError로 차단됐다. 첫 실패 원시 응답은 저장하지 않았으므로 첫 실패까지 같은 원인이라고 단정하지 않는다.
- 총 4회 호출, 입력 8005토큰·출력 9606토큰. 이 사용량은 로컬 QA 기록이며 운영 채팅 model_invocations 집계에 포함되지 않는다.

## 발견한 문제와 수정 방향
1. 엑셀, 파워포인트를 any로 해석했다. 쉼표·슬래시·예시 나열만으로 OR를 단정하지 않고, 명시적 논리 근거가 없으면 unresolved로 남기는 정책과 평가가 필요하다.
2. 추가 기술스택 13개를 any의 8개 atom으로 만들었다. 현재 children 상한 8과 모델 의미 추정이 결합해 파생 논리에서 5개가 누락됐다. 원문은 그대로 보존됐지만 검색 파생값의 완전성은 보장되지 않는다. 긴 목록의 분할·참조 방식과 누락 검증이 필요하다.
3. 성향과 강의 경험이 혼합된 항목은 사전 review 라벨과 달리 ask였다. 객관적 경험을 유지한 점은 타당할 수 있으므로 사람 정책 합의가 필요하다.
4. JSON 출력 안정성이 부족하다. 실제 오류 원인을 안전한 코드로 구분하고 출력 계약을 강화해야 한다. 무한 재시도나 출력 제한 해제로 성공을 만들지 않는다.

## 운영 영향과 다음 단계
DB 분류 저장·Outbox 이벤트·ES 분류 반영은 이번 검증에서 실행하지 않았다. 원본 수정은 없으며 질문 선정·순위 보강 플래그는 false를 유지한다. 다음은 출력 계약과 논리 보존을 개선하고, 동일 개발 표본 재검증 후 별도 사람 정답셋으로 평가하는 것이다. 이번 표본은 이후 미사용 최종 평가셋에 섞지 않는다.
