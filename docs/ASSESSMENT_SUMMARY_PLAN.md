# 조건 문답 후 사용자 답변 정리 개선안

작성일: 2026-10-31. 상태: **사용자 요청에 따른 후속 수정안 문서화**. 코드·DB·API·AWS에는 아직 적용하지 않았다.

## 1. 바꿀 흐름

현재 순차 조건 문답 → 묶음별 저장 → 모든 문답이 끝나면 **사용자 답변 정리** → 사용자가 원하는 다음 행동 선택 → 후속 대화.

마지막 답변 저장 직후 조건 원문과 동일한 설명을 길게 반복하기보다, 해당 공고 기준으로 무엇을 충족한다고 답했는지·무엇이 부족하다고 답했는지·무엇을 아직 확인하지 못했는지 먼저 정리한다. 모든 조건을 충족으로 선택해도 이 정리 단계는 제공한다.

## 2. 현재 코드와 개선할 부분

- 현재 make_check는 사용자 선택을 met/unmet/unknown으로 저장한다. 비율·가중치·합격 점수로 취업 역량을 평가하지 않는다.
- 현재 필수 unmet가 하나라도 있으면 gap_guidance, 그렇지 않으면 completed다. 따라서 필수 unknown만 있어도 completed가 될 수 있다. 이는 문답 종료를 뜻하며 필수 자격 충족을 입증한 것이 아니다.
- 현재 미충족 조건이 있으면 교육을 조회할 수 있으나, 전부 충족이면 결과 이후의 다음 행동 제안이 없다. 후속 자유 입력은 가능하다.
- 이번 수정 목표는 완료/보완 안내의 표시를 답변 정리 중심으로 바꾸는 것이다. 서버 stage 이름 변경 여부는 구현 시 정하며, 새 단계가 이미 배포된 것으로 기록하지 않는다.

## 3. 정리 화면 구성

1. 선택 공고의 회사·직무·출처 링크와 확인한 원본 버전을 표시한다.
2. **필수 자격요건**을 충족/미충족/미확인 개수로 구분한다.
3. **우대조건**도 같은 세 상태로 별도 구분한다. 필수와 우대를 합산해 취업 점수나 합격 확률로 표현하지 않는다.
4. 충족한다고 답한 조건은 '사용자가 충족한다고 답한 내용', 미충족은 '보완이 필요하다고 답한 내용', unknown은 '아직 확인하지 못한 내용'으로 짧게 정리한다.
5. 사용자가 남긴 보충 설명을 관련 조건과 함께 반영한다. 원문/답변/근거는 펼쳐서 볼 수 있게 해 다시 긴 목록을 한꺼번에 표시하지 않는다.
6. 다음 행동은 2~3개 선택 컴포넌트와 자유 입력으로 제공한다. 기본 문답을 자동으로 다시 시작하지 않는다.

표시 예시(실제 사용자 평가 결과가 아닌 형식 예시):

> 이 공고의 필수조건에서는 React 경험을 충족한다고 답하셨고, 실무 경력은 미충족, Git 협업 경험은 미확인으로 남겼습니다. 우대조건에서 테스트 작성 경험을 충족한다고 답하셨습니다. 확인된 답변을 기준으로 실무 경력 보완과 Git 경험 확인을 구분해서 준비할 수 있습니다.

'필수조건을 모두 충족했습니다'와 '모든 질문에 답했습니다'를 혼용하지 않는다. 사용자 자기 진술을 실무 역량 검증 완료로 바꾸지 않는다.

## 4. 답변 조합별 처리

| 조합 | 먼저 정리할 내용 | 다음 선택 제안 |
|---|---|---|
| 필수 미충족 있음 | 미충족 필수조건과 충족한다고 답한 조건을 함께 정리. 취업 불가능으로 단정하지 않음 | 보완할 학습 순서 / 관련 교육 / 다른 공고 비교 |
| 필수 미충족은 없지만 필수 미확인 있음 | 확인되지 않은 필수조건을 별도로 표시. 자격 충족 완료로 표시하지 않음 | 모르는 조건 설명 / 나중에 확인 / 이미 답한 내용으로 준비 방향 |
| 필수 모두 충족·우대 일부 미충족/미확인 | 필수 자기 진술과 우대 보완·미확인을 분리 | 이력서·포트폴리오 준비 / 우대 역량 학습 / 유사 공고 |
| 필수·우대 전부 충족 | 사용자 진술상 충족한 조건과 보충 설명을 정리. 추가 부족 역량을 만들어내지 않음 | 이력서에 연결 / 면접 준비 / 다른 공고 비교 |
| 전부 미확인 | 확인 가능한 역량이 부족한 상태임을 설명. 미충족/취업 불가능으로 바꾸지 않음 | 용어 설명 / 경험 예시로 확인 / 질문 없이 공고 보기 |
| 우대조건 원문 없음 | 우대조건 자료가 없음을 표시. 우대 0개를 100% 충족으로 계산하지 않음 | 필수 답변 정리와 다음 행동 |
| 문답 중단 | 답변한 항목만 부분 정리하고 미답변을 별도 표시 | 질문 중단 유지 / 정리 보기 / 다른 공고 |

unknown은 충족·미충족 어느 쪽에도 합산하지 않으며 교육 추천의 부족 기술로 자동 변환하지 않는다. 여러 조합이 동시에 성립하면 필수 미충족·필수 미확인을 각각 보여 준다. AND/OR 원문 복합 조건은 임의로 나눠 새 점수를 만들지 않는다.

질문을 거절한 세션에서는 unknown이 있어도 자동 재질문하지 않는다. 설명이나 추가 확인은 사용자가 선택할 때만 진행한다. 전부 충족한 경우에도 새 역량 질문을 강제로 만들지 않는다.

## 5. 정리의 근거·기억·저장

- 기준 데이터는 해당 세션에서 저장한 체크리스트의 조건 ID/필수·우대 유형/선택/보충 설명, 선택 공고의 source_id/source_version, 관련 사용자 진술이다. 현재 최신 검색 결과로 과거 문답의 근거를 몰래 교체하지 않는다.
- 조건 개수·상태 분류는 서버에서 결정적으로 계산한다. 이전 말과 체크 선택이 충돌하면 불일치/추가 확인 대상으로 남기고 한쪽을 임의로 사실 확정하지 않는다.
- 우선 구조화 정리와 짧은 템플릿으로 제공해 별도 모델 호출 없이 만들 수 있는 방향을 제안한다. 자연어 다듬기를 위한 추가 Bedrock 호출은 필수로 확정하지 않았으며, 도입 시 호출량·비용·사실 대조를 별도로 검토한다.
- 새 테이블을 바로 만들 필요는 없다. 기존 chat_sessions 상태와 chat_messages.structured_content의 최종 응답, recommendation_evidence의 조건별 근거를 우선 재사용한다. 새 summary 필드·버전 키는 실제 API/캐시 계약 검토 후 확정한다.
- 정리 결과는 마지막 답변 처리와 일관되게 저장하고 요청 재시도/응답 캐시에서 같은 정리 결과를 재현한다. 저장 실패 때 성공 요약을 먼저 보여주지 않는다.
- 후속 '내가 뭐가 부족해?', '왜 그렇게 정리했어?', '다 충족했는데 다음에는?' 질문에는 저장한 정리와 근거를 모델 문맥으로 넣는다. 조건 문답 전체를 기억하지 못한 것처럼 기술 스택을 처음부터 반복해서 묻지 않는다.
- 사용자 경험 정정/답변 변경·공고 버전 변경 시 기존 정리의 유효성을 재검토하고 이전 요약을 현재 결과처럼 재사용하지 않는다. 사용자 범위·만료·질문 중단 설정은 계속 적용한다.

## 6. 구현 순서와 완료 기준

1. 서버 정리 계약/집계 함수: 필수·우대별 세 상태와 근거 연결을 정의한다. 전부 충족·전부 모름·혼합·원문 없음·부분 종료·정정 사례를 테스트한다.
2. 종료 응답 변경: 현재 completed/gap_guidance에 정리와 선택지를 연결한다. 상태명 변경이 필요하면 구 클라이언트/세션 호환을 검토한다.
3. 프론트 정리 카드: 짧은 핵심 정리, 분리 집계, 원문/답변 펼침, 다음 행동 선택을 제공한다. 긴 카드 자동 스크롤 문제가 다시 생기지 않게 확인한다.
4. 후속 문맥/캐시: 같은 공고·조건 답변·이유를 계속 참조하는지, 실패/재시도·사용자 격리·만료·정정 후 재계산을 확인한다.
5. 표본 브라우저/격리 DB 검증 후 별도 배포·기록한다. 이번에는 문서만 수정한다.

통과 기준: 미확인을 충족/미충족으로 바꾸지 않음, 사용자 진술 밖 역량이나 합격 가능성 생성 없음, 모든 조합에서 답변 정리 제공, 전부 충족해도 다음 선택 제공, 거절 시 재질문 없음, 후속 답변이 저장된 근거와 일치함.
