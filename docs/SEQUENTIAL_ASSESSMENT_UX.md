# 조건 문답 순차 표시·일괄 저장 UX 계획

작성일: 2026-10-31. 상태: 구현·운영 웹 반영 완료. 최초 계획은 38e2e14에서 구현 전에 별도 푸시했고, 아래 완료 기록은 이후 구현 커밋의 내용이다.

## 문제

기존 지원 자격/우대조건은 서버가 최대 5개씩 반환하고 웹이 모든 질문을 동시에 표시했다. 새 메시지의 맨 아래로 자동 스크롤하면서 첫 질문이 시야 밖으로 밀리고 선택해야 할 항목이 한꺼번에 많아졌다.

## 적용한 동작

1. 현재 묶음 안에서 조건 카드 하나만 표시한다. 지원 자격/우대조건 구분과 전체 확인 진행률, 현재 묶음의 순서를 함께 보여 준다.
2. 충족/미충족/모름 및 보충 설명은 웹 메모리에 임시 보관한다. 이전/다음 이동으로 서버나 Bedrock을 호출하지 않는다.
3. 이전 조건으로 돌아가 답변을 수정할 수 있다. 답하지 않은 조건을 충족/미충족으로 추정하지 않는다. 모름을 명시적으로 선택해 넘어갈 수 있게 한다.
4. 현재 묶음의 마지막 조건에서 모은 답변을 기존 answer_batch 요청 한 번으로 저장한다. 저장 전에는 DB 반영 완료로 표시하지 않는다.
5. 서버의 묶음 크기와 자격→우대 순서는 유지한다. 이번 변경은 전체 자격·우대 조건을 한 요청으로 합치는 서버 구조 변경이 아니다. 묶음이 5개를 넘으면 저장 후 다음 묶음으로 진행한다.
6. 문항 선택·이동 시 대화 하단으로 스크롤하지 않는다. 다음 문항 제목에 접근성 포커스만 옮겨 위치를 안정적으로 유지한다.
7. 과거 문답 카드는 접힌 요약으로 남기고 원할 때 답변 내역을 확인한다. 조건 원문과 출처는 펼쳐 볼 수 있게 보존한다. 협업 조건도 카드 하나씩 표시하며 원문 항목을 삭제하지 않는다.
8. 질문 그만하기와 자유 입력은 유지한다. 아직 제출하지 않은 답변은 브라우저 메모리에만 있으므로 새로고침/새 대화/다른 단계 전환 시 보존을 보장하지 않는다. 미저장 상태를 분명하게 안내한다.

## 구현·검증 순서

- 먼저 이 기록과 기존 대시보드 개선 완료 기록을 커밋·푸시한다.
- 이후 순차 카드 컴포넌트·임시 답변/제출 변환·스타일을 구현한다. 세션·API·DB 스키마는 변경하지 않는다.
- 문항 이동 시 네트워크 요청 없음, 이전 답변 보존, 모름/보충 설명/원문 유지, 마지막 한 번만 제출, 비활성 과거 카드·중복 클릭 보호를 검증한다.
- 프론트 테스트·프로덕션 빌드와 실제 모델/DB를 쓰지 않는 표본 브라우저 시나리오를 확인한다. 기존 백엔드 answer_batch 계약은 유지한다.
- 검증 결과와 배포 여부를 이 문서에 추가하고 UX 구현을 별도 두 번째 커밋으로 푸시한다.

## 함께 기록한 대시보드 변경 (이미 반영 완료)

관리자 페이지 헤더와 채팅용 sticky 헤더 CSS를 분리해 제목/카드 겹침을 없앴다. 호출당 입력·출력·합계 토큰과 성공/실패별 평균 및 추정 USD를 표시했다. 프론트 테스트 13개와 빌드, 표본 화면 시각 확인, CloudFront 공개 JS/CSS 해시 대조를 완료했다. 구현 커밋은 9a44aca이며 AWS에도 게시했다.

비용은 DB에 남은 사용량 기록과 확인한 모델 단가로 계산한 추정치다. 실패 사용량 미기록·보존 삭제·세금·환율·크레딧·서버 비용의 한계를 유지한다. 상세 내용은 [ADMIN_DASHBOARD.md](ADMIN_DASHBOARD.md)를 따른다.

## 구현·검증·배포 결과

- AssessmentStepper.jsx와 assessmentDraft.js로 표시와 임시 답변/제출 변환을 분리했다. 질문 ID 묶음별로 초기화하며, 이전/다음에 기존 선택과 보충 설명을 유지한다. 답변이 없으면 다음/제출을 차단하고 명시적 모름 선택을 제공한다.
- 현재 문항 하나만 표시한다. 원문/보충 설명/저장 전 안내는 펼치기로 두고, 문답 중에도 자유 입력을 유지하되 입력창 높이를 줄였다. 과거 카드는 접힌 내역으로 표시한다. 미저장 상태를 표시하며 완료된 DB 저장이라고 가정하지 않는다.
- 마지막에 기존 answer_batch만 호출한다. 연속 제출 ref 및 busy/active 가드, 기존 send의 in-flight 가드를 함께 유지한다. 대화 오류 재시도는 기존 요청 처리 구조를 사용한다.
- 새 질문 묶음은 카드 시작 위치로 스크롤하고, 묶음 내 이동은 preventScroll 포커스를 사용한다. 기본 카드 이동 시험에서 scrollY 128 → 128로 유지됐다. 원문/설명 펼침이나 사용자의 직접 스크롤은 허용한다.
- 프론트 18개 테스트·Vite 프로덕션 빌드 통과. 자동 검증은 미답변 제출 거부, 이전 답변 수정/설명 보존, 원문 순서 payload, 명시적 unknown, 새 묶음 초기화, 한 문항 묶음과 기존 관리자/채팅 기능을 포함한다.
- 로컬 표본 브라우저에서 자격요건 5개·우대조건 2개를 조작했다. 마지막 저장 전 batch 요청 0회, 저장 후 두 묶음 각각 1회(총 2회), 이전 선택·Git 보충 설명·모름 보존을 확인했다. 새 묶음은 선택 0개로 시작했고 질문 그만하기는 추가 batch 요청 없이 중단 응답으로 전환했다.
- 위 브라우저 검증은 실제 DB/Bedrock 없는 표본이다. API·DB·모델 정책/데이터는 수정하지 않았다. 운영에서 실제 사용자 대화 저장까지 새로 호출해 검증한 것은 아니다.
- 기존 S3/CloudFront 웹 게시 완료. 공개 HTML의 JS index-DQYMceVK.js / CSS index-DnXaCavX.css 참조와 파일 SHA256이 로컬 빌드와 일치했다. 강력 새로고침 후 새 흐름을 사용할 수 있다.
- 작은 화면 대응 CSS를 추가했으며 실제 기기별/매우 긴 원문 펼침 상태의 수동 검증은 후속이다. 브라우저 새로고침 후 임시 답변 복구, 전체 자격·우대 조건을 한 요청으로 합치는 API는 이번 범위가 아니다.
