# 구현 현황과 다음 작업

기준일: 2026-11-20. 코드·배포 기록을 정리한 인계 문서이며 현재 DB 건수·AWS 비용·실제 AI 정확도를 새로 측정한 자료가 아니다.

## 현재 구현·배포
- React 화면을 S3/CloudFront에서 제공한다. API Gateway/Lambda → SQS → EC2 worker가 요청을 처리하며 MySQL은 원문·세션·답변·근거의 기준 저장소, Elasticsearch는 검색 사본이다.
- 공고/교육 검색, 카테고리, 무한 스크롤, 상세, 최근 본 항목·스크랩을 제공한다. 최근 본 항목·스크랩은 브라우저 보관이며 회원 기능과 구분한다.
- 공고 자격/우대조건 문답, 자기보고 답변 저장·정정, 보완 상담과 교육 탐색을 연결한다.
- 자격/우대 섹션 벡터를 ES에 저장하고 TXT 경험 유사 검색과 0건 대체 경로를 연결했다. 일반 검색과 자격 충족 판정은 별개이며 유사도는 충족률이 아니다.
- 평가 이후 추천 버튼은 충족 답변을 참고하는 새 검색을 요청한다. 선택 공고 제외와 기존 문답 보존을 적용했다. 실제 모델이 항상 적절한 검색 계획을 만든다는 보장은 아직 없다.
- 상담 후 우대조건 재개 시 모델이 jobs 대상을 반환한 오류를 selected로 정규화한다. 계약 context-intent-v10.
- PC 좌우 크기 조절, 모바일 상담/결과/내 페이지, 첫 방문 3단계 안내를 제공한다. 안내에서 대화 기록·개인정보 주의 문구를 표시하고 채팅 헤더의 중복 안내는 제거했다.
- 공고 목록 자동 로딩·직접 검색은 채팅 안내·스크롤을 보존한다. 요청 처리 중 입력을 잠그고 사용 방법은 열 수 있다. 첨부/전송은 같은 줄이며 기본 투명·hover 원형이다.

## 다음 개선 순서
1. 실사용 검증: 필수 문답 → 역량 기반 새 공고 → 기존 답변 유지, 상담 → 우대 문답, 0건 → 유사 후보를 같은 고정 시나리오로 검사한다. 개인정보는 보고서에 복제하지 않는다.
2. 검색 품질: SQL/ES 동의어 전후/벡터를 동일 정답지로 비교한다. 관련성·필수조건 위반·근거 정확성·지연·비용을 분리 측정한다.
3. 데이터 운영: 공고 종료·원문 버전·ES/벡터 동기화와 교육 증분 수집을 점검한 뒤 일일 자동화 여부를 결정한다. 이번 정리에서 자동 수집 예약을 확인하거나 생성하지 않았다.
4. 사용자 관리·보안: 계정/동의/보존기간/삭제, 개인정보 최소 수집 및 접근 통제를 먼저 설계한다. 현재 브라우저 저장을 회원 관리로 설명하지 않는다.
5. 코드 구조: CareerApp·context_router 책임을 작게 나누되 검색/문답/선택 보존 회귀 검사를 먼저 유지한다.
