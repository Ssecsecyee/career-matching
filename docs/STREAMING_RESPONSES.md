# 생성 중 답변 순차 표시 (2026-10-28)

배포 릴리스: 20261028T061510Z. 웹도 기존 S3·CloudFront에 게시했습니다.

## 용어와 구현 범위
생성된 답변을 완성 전에 나누어 전달하는 것은 스트리밍입니다. 동기/비동기와 별도 개념입니다.
현재 요청은 기존처럼 SQS 기반 비동기 작업이며, 모델→워커는 Bedrock ConverseStream을 사용합니다.
워커는 생성 중인 답변 초안을 기존 DynamoDB 작업 행에 최대 약 0.8초에 한 번 기록합니다.
브라우저는 기존 인증된 /api/jobs/{id}를 약 1.5초 간격으로 조회해 새 텍스트를 받고 타이핑 표시로 이어 붙입니다.
브라우저까지 하나의 SSE/WebSocket 연결을 유지하는 구조는 아닙니다. 완성된 답변을 전부 받은 후 애니메이션만 재생하는 방식과도 구분합니다.

## 내용과 오류 처리
- 라우터 JSON의 최상위 intent=chat, reply 텍스트만 초안으로 추출합니다. 검색 계획 JSON·필터·reasoning 블록은 표시하지 않습니다.
- 한글·줄바꿈·따옴표·분할 Unicode escape와 surrogate pair를 처리합니다.
- 초안은 최종 JSON 검증 전 내용입니다. 최종 응답이 검증된 경우에만 대화·근거·응답 캐시가 확정됩니다.
- 중간 저장 장애는 진행 표시만 중단하고 모델을 재호출하지 않습니다. 최종 답변 저장 경로는 유지합니다.
- 최종 오류/통신 실패 때 화면의 미완성 초안을 제거하고 오류와 재확인 동작을 제공합니다. 완성 답변으로 취급하지 않습니다.
- 완료 시 DynamoDB에서 partial_text/partial_version을 제거합니다. 작업 TTL·소유자 인증은 기존 정책을 유지합니다.
- 체크리스트·공고 카드·교육 카드는 완성 후 검증된 구조화 결과로 표시합니다. 일반 상담 답변이 실제 모델 스트리밍 대상입니다.
- 동작 줄이기 접근성 설정에서는 글자 애니메이션을 생략합니다. 이전 대화와 캐시 응답은 즉시 표시합니다.

## 권한과 리소스
기존 CloudFormation WorkerRole의 Sonnet 리소스 범위에 bedrock:InvokeModelWithResponseStream 한 개만 추가했습니다.
변경 세트는 WorkerRole Modify/Replacement=False 한 건으로 검토했고 스택 UPDATE_COMPLETE를 확인했습니다.
새 서버·DB·엔드포인트·포트·테이블은 만들지 않았습니다. DB 내용과 기존 호출 상한은 유지합니다.
모델 호출 수를 늘리는 구현은 아니지만 초안 저장과 상태 조회 횟수는 늘어납니다.
AWS 공식 API: https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ConverseStream.html
