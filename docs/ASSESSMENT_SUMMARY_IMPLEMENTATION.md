# 조건 문답 후 답변 정리 구현 기록

작성일: 2026-10-31. **로컬 구현·빌드·검증 완료, 이번 변경의 운영 배포와 Git 커밋·푸시는 아직 하지 않음.**

## 동작 흐름

순차 문답 → 기존 answer_batch로 묶음 저장 → 마지막 조건 저장 시 서버 집계 → 답변 정리 카드 → 사용자가 다음 행동 선택 또는 자유 입력.

기존 completed/gap_guidance stage는 호환을 위해 유지하고, 응답에 answer_summary를 추가했다. completed는 문답 종료이지 합격이나 필수조건 충족 판정이 아니다. 문답 중단 시에는 부분 정리와 미답변 수를 보여 주고 중단 설정을 유지한다.

## 집계와 표현

- services/assessment_summary.py의 build_summary가 조건 ID·유형·원문과 저장된 선택을 대조한다. 중복 ID, 알 수 없는 선택, 원문 불일치는 정상 요약으로 통과시키지 않는다.
- 필수와 우대를 각각 met/unmet/unknown/unanswered/total로 집계한다. unknown과 미답변은 서로 구분하며 미충족으로 합산하지 않는다. 합격 점수·확률·역량 비율은 만들지 않는다.
- 전체 충족, 필수 미충족, 필수 미확인, 우대 보완, 전체 미확인, 우대 원문 없음, 부분 종료 등을 구분한다. 원문이 없는 우대조건 0개를 100% 충족으로 계산하지 않는다.
- 충족/미충족/미확인별 핵심 조건은 두 개씩 먼저 표시한다. 전체 선택·보충 설명·원문은 펼침 영역에서 확인한다. 공고 ID·당시 버전과 출처를 함께 유지한다.
- 경력 연수 조건을 충족으로 선택했지만 보충 설명 또는 보존된 최근 경력 진술에 명시적으로 '경력이 없다/0년'고 적힌 경우 확인 경고를 붙인다. 선택을 강제로 바꾸지 않는다. **명시적 경력 충돌에 대한 제한적 규칙이며 모든 의미적 모순을 감지하는 기능은 아니다.**

## 다음 대화

| 답변 상태 | 선택지 |
|---|---|
| 미충족 조건 있음 | 보완 방향 정리 / 이력서에 연결 / 다른 공고 찾기 |
| 미확인·부분 종료 | 미확인 조건 설명 / 나중에 확인 / 다른 공고 찾기 |
| 전부 충족·확인한 필수 충족 | 이력서에 연결 / 면접 준비 / 다른 공고 찾기 |

버튼은 새 API 대신 기존 search action에 해당 자연어 메시지를 보낸다. 사용자가 선택할 때만 상담·검색으로 이어진다. 문답을 자동 재개하지 않는다. 기존 교육 조회는 유지하되 모름을 부족 기술로 바꾸거나 경력·학위를 교육 수료로 대체하지 않는다.

'내가 뭐가 부족해?', '왜 그렇게 정리했어?', '지금까지 답변을 정리해줘'처럼 요약을 다시 요청하면 저장한 답변으로 서버가 재구성한다. 학습·이력서·면접 상담은 이 조회 분기로 가로채지 않고 모델 상담으로 이어진다. summary_requested는 제한된 표현 규칙이므로 모든 자연어 의도를 완벽하게 분류한다는 의미는 아니다.

## 저장과 비용

- **새 테이블이나 DDL을 추가하지 않았다.** chat_sessions의 기존 상태 JSON에 answer_summary, chat_messages.structured_content에 요약이 포함된 최종 응답, response_cache에 동일 응답을 저장한다. recommendation_evidence에는 기존 조건별 원문·선택·설명을 유지한다.
- 요약 items는 조건 ID로 원문 근거와 연결한다. 원문 전체를 요약에 중복 복제하지 않는다. 화면은 응답 checks의 원문과 보충 설명을 결합해 표시한다.
- version=answer-summary-v1과 요약 ID를 부여한다. 공고 버전·조건·답변·설명·부분 상태·충돌 근거가 바뀌면 ID도 바뀐다. 새 검색·공고 선택·경험 정정 시 이전 요약을 지운다.
- 마지막 답변과 요약은 기존 저장 트랜잭션으로 처리한다. 재요청은 기존 캐시를 재사용한다. 캐시 저장 실패를 주입했을 때 최종 assistant·evidence·summary가 함께 롤백되고 동일 요청으로 재시도 가능한지 격리 MySQL에서 확인했다.
- 요약 생성·다시 보기에는 **추가 Bedrock 호출이 없다.** 버튼 이후 자유 상담은 기존 호출 예산·사용량 기록을 그대로 적용한다.
- memory.consultation_context는 저장 요약의 집계·공고 버전·충돌 정보와 기존 전체 조건 답변을 함께 모델에 전달한다. 프롬프트 버전 conversation-answer-summary-v6는 미확인 구분·사용자 진술 기준·전부 충족 시 준비 방향·경험 날조 금지를 명시한다. 기존 문맥 크기·세션 보존 한도 안에서 기억하며 무제한 기억을 보장하지 않는다.

## 검증 결과

- 백엔드 전체: **209개 검사, 9개 환경 의존 검사 건너뜀, 실패 0**. 신규 순수 집계·흐름 검사는 13개.
- 별도 실제 MySQL 검증: **2개 통과**. state/assistant/cache 동일 요약, 소유자·만료 격리, 중복 없는 재요청, 요약 재조회 모델 호출 0, 저장 실패 롤백·재시도를 확인했다. 임시 검증 DB는 제거했고 운영 공고 **959건 유지**를 확인했다.
- 프론트 기존 검사 **18개 통과**, 프로덕션 빌드 성공.
- 실제 브라우저에서는 합성 표본으로 전부 충족 집계·접힌 원문·다음 행동 메시지 전달·전체 미확인 표시를 확인했다. 실제 고객 대화/모델 응답 품질 평가나 모바일 전 기종 검증을 대신하지 않는다.

- app/frontend/src/AssessmentSummary.jsx: 정리 카드·집계표·원문 펼침·선택 버튼.
- app/frontend/src/main.jsx, style.css: 기존 화면 연결·카드 시작 위치 스크롤·작은 입력창.
