## B. 고용24 승인 후 최우선

1. **채용/국민내일배움카드 훈련 API 승인·명세 확인**: 서비스 종류·권한·필드·호출/보관/이용 범위, 비밀 설정 준비.
2. **최대10건 실제 응답 확인**: 목록/상세·ID·공식 코드·시간/상태·빈 값·페이지/오류 검증.
3. **공통 어댑터/출처 식별**: source+ID, 공고/과정/회차, 직종/지역/학력/경력, 원문·버전·정밀도 매핑. 점핏 고정 SELECT·숫자 ID·검색/선택/세션/캐시 가정도 수정.
4. **격리 DB 시험 후 AWS 소량 적재**: 신규/동일/변경/빈 값/오래된 응답·재시도·실패 롤백, 백업과 전용 권한.
5. **DB→Outbox→ES 확인**: 채용/교육 분리, ID·버전·날짜/노출 일치. 기존 대화용 큐와 적재 큐 구분.
6. **반복 수집 자동화**: 원본S3→적재 전용 메시지/소비자→DB, 예약·증분 범위·중단 재개·실패 복구·관측/알림.

채용과 훈련은 승인/응답에 따라 각각 검증한다. API 주소만 바꿔 연결 완료로 하지 않는다. 실제 상세 커리큘럼이 부족하면 교육 추천·통계의 자료 확보 범위도 제한해 표시한다.

## 현재 결론

ES를 검색 계층으로 유지하고 MySQL은 원본·상태·대화·근거, SQL은 분석용 정규화·통계에 활용한다. SQL 불가능/ES 필수라고 주장하지 않는다. 현재 검색 구성은 운영 중이며 고용24 연결과 분야 확장 효과·동시 사용자 한도는 아직 검증 전이다.
