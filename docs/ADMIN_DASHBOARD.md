# 관리자 대시보드 구현·배포 현황

## 구현 및 운영 반영 완료 (2026-10-31)
- 별도 ADMIN_API_TOKEN 인증을 서버에서 검증한다. 일반 CHAT_API_TOKEN으로 관리자 API를 사용할 수 없다. 클라이언트가 role을 지정하지 못하며 큐 작업의 권한은 인증 결과로 저장한다.
- 관리자 채팅만 세션 모델 호출 횟수 한도를 해제한다. 요청 크기·모델 출력·AWS 쿼터·세션 만료·동시 처리 보호는 유지한다. 호출/토큰/실패 기록은 유지한다.
- MySQL 테이블 탐색, 컬럼 타입, 대화별 필터, 모델 사용량과 캐시 토큰, Outbox 적체를 React 관리자 화면에 구현했다. 임의 SQL·비밀키·원본 인증 데이터 조회는 제공하지 않는다.
- 공고 숨김/복구는 관리자 변경 사유·이전/이후 상태를 admin_audit에 저장하고 source_version 증가와 Outbox를 같은 트랜잭션에서 기록한다. 숨김은 unavailable로 관리하며 원문·날짜·원본 파일은 삭제하지 않는다. 이는 출처에서 모집 종료를 확인했다는 뜻이 아니다.
- 복구는 마지막 관리자 숨김 버전과 현재 버전이 같을 때만 허용한다. 만료 공고는 복구해도 검색 노출되지 않는다. 재수집으로 상태가 바뀐 경우 최신 상태 검토가 필요하다.
- DB 관리용 계정은 일반 채팅 계정과 분리한다. 관리자 토큰은 기존 AuthSecret의 admin_token 필드에 저장한다. 별도 DB 계정의 비밀번호는 서버의 /opt/career/admin-db.json(작업자 소유, 0600)에 저장하며 값을 Git/응답/문서에 남기지 않는다.

## 반영 완료
- 마감 판정 충돌 수정: 정확한 날짜와 date_only 중 하나라도 경과했으면 제외한다. 실제 사례 55407438의 11/25와 10/27 충돌을 확인해 검색에서 제외했고 DB 노출 대상과 ES 각 775건으로 일치했다. 날짜 충돌은 추후 최신 원문 근거 우선 정책으로 개선한다.
- 위 마감 수정은 로컬과 AWS 작업자/검색 동기화에 반영했고 187개 테스트 중 환경 조건 7개 제외 후 통과했다.
- 관리자 대시보드는 아래 검증과 운영 배포를 완료했다. 후속 기능과 구분한다.

## 운영 경로·사용 방법
- /#admin: 관리자 대시보드. 토큰은 현재 화면 메모리에만 보관한다.
- /#admin-chat: 관리자 토큰으로 일반 채팅 사용. 일반 토큰의 호출 한도는 그대로다.
- 기존 POST /api/chat의 action=admin을 사용해 기존 큐/폴링 경로로 처리한다. 관리자 DB 작업은 Bedrock을 호출하지 않는다. 작업 결과와 큐 임시 데이터는 기존 24시간 만료를 적용한다.
- admin_migration.sql은 admin_audit만 추가한다. 운영 적용 전 SQL 백업을 만들고 기존 공고·대화 수가 유지되는지 확인한다. 신규 일반 인프라·공개 DB 포트는 만들지 않는다.

- 테이블 탐색은 표시용 미리보기이며 긴 필드는 잘릴 수 있다. _truncated_columns에 잘린 컬럼을 표시한다. 원본 데이터는 변경하지 않는다.

## 검증·배포 기록
- 백엔드 194개 테스트 통과(환경 조건 7개 제외), 프론트 테스트 9개 및 Vite 프로덕션 빌드 통과.
- 실제 MySQL 임시 DB에서 숨김/복구·Outbox/감사 기록, 같은 요청 중복 방지, 모든 테이블 조회, 일반 12회 제한과 관리자 13회 초과 호출 기록을 검증했다. Bedrock 실제 호출은 0건이다. 임시 DB는 제거했다.
- 첫 격리 검증은 구버전 MySQLChatStore를 불러와 TypeError로 실패했다. 운영 변경 전에 중단했으며 새 저장소 코드를 패키지에 포함해 재검증했다. 실패 상태 파일은 보존했다.
- 운영 SQL gzip 백업: /opt/career/backups/before-admin-20261031T101335Z.sql.gz. 압축 무결성을 확인했으며 복원 훈련을 뜻하지 않는다.
- 기존 공고 959건 유지. admin_audit 추가, 관리 전용 최소 권한 DB 계정과 서버 보호 파일 준비. 일반 채팅 계정 권한은 확대하지 않았다. 관리자 토큰은 기존 AuthSecret의 admin_token 필드에 별도로 생성했다.
- 백엔드 코드 릴리스 20261031T101406Z 반영 성공. 검색 소비자의 unavailable 제거 처리도 적용했다. React 게시 JS: index-Cl5vwSOV.js.
- 실제 CloudFront 경로에서 일반 토큰 관리자 요청 403, 관리자 집계와 9개 테이블 페이지 조회 200을 확인했다. 모델 사용량 집계는 검증 전후 동일했다. 운영 공고 숨김/복구는 시험 목적으로 실행하지 않았으며 해당 변경 검증은 격리 DB에서 수행했다.
- 배포 직후 공고 959, 교육 7, 세션 31, 메시지 290, 근거 117, 모델 호출 121, 응답 캐시 145, Outbox 1250, 관리자 변경 감사 0건이었다. 이는 시점 스냅샷이며 관리자 조회 자체는 MySQL 대화/모델 기록을 늘리지 않는다.

## 접속과 재배포
- 관리자 화면: https://d1elpjlek4sj83.cloudfront.net/#admin
- 관리자 채팅: https://d1elpjlek4sj83.cloudfront.net/#admin-chat
- AWS 콘솔 서울 리전 → Secrets Manager → 현재 백엔드 스택 AuthSecret → 보안 암호 값 → admin_token 값을 관리자 화면에 입력한다. 기존 token은 일반 사용자 접속 코드다. 둘의 값을 서로 같게 설정하지 않는다.
- 토큰을 변경하면 Lambda의 비밀 캐시(최대 60초)와 작업자 재시작을 고려한다. 이미 만든 관리자 큐 결과는 이전 소유 범위에 속하므로 새 토큰으로 이어 읽을 수 없다. 이전 관리자 세션도 새 토큰으로 승계되지 않는다.
- 신규 환경 준비: python infra/admin_setup.py prepare → result. 준비 성공 시에만 관리자 토큰 필드를 만든다. 기존 상태 파일이 있으면 먼저 결과를 확인한다. 실패 후 재시도는 실패 이력을 보존하고 원인을 수정한 뒤 새 실행으로 수행한다.
- 코드 수정: 기존 update_backend.py build/apply/result, 웹 수정: hosting.py publish. 관리자 테이블 초기화나 DB 재적재는 코드 배포 때 반복하지 않는다.
- 로컬 테스트는 별도 ADMIN_API_TOKEN·ADMIN_MYSQL_USER·ADMIN_MYSQL_PASSWORD 설정이 필요하다. 운영 비밀을 예제 파일에 복사하지 않는다.

## 진행 예정·현재 제한

- 현재 토큰 기반 공동 관리자 인증을 개인별 로그인·권한으로 확장하고 브라우저 수동 UX 검증 범위를 늘린다.
- 백업의 실제 복원 훈련, 관리자 토큰 회전 절차 자동화, 변경 요청 실패/감사 기록 보존 정책을 추가한다.
- 임의 SQL/일괄 삭제/스키마 편집/날짜 직접 수정은 이번 범위 밖. 영구 숨김 오버라이드와 수집 덮어쓰기 정책, 개인별 관리자 계정·감사 보존/삭제 정책, 비용 청구 조회, CPU/메모리/ES 전용 그래프는 후속이다.
- 관리자 토큰을 공유하면 개인별 책임 추적이 안 된다. actor_scope는 토큰+클라이언트에서 유도한 범위이며 실제 개인 신원 인증이 아니다.
- 사용량 집계는 애플리케이션 DB 기록이며 AWS 청구 비용을 의미하지 않는다. 캐시 본문과 세션 내부 상태는 목록에 노출하지 않고 대화 본문은 인증한 관리자만 조회한다.
