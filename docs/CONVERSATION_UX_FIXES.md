# 2026-10-30 대화 의도·질문 거절·조건 가독성 수정

## 상태

로컬 소스와 회귀 테스트 수정. 이번 UX 변경은 AWS·CloudFront에 배포하지 않았고 실제 Bedrock 호출도 하지 않았다. AWS의 Elasticsearch 검색·자동 동기화는 이전 배포 상태를 유지한다. 후속 배포에서는 백엔드와 프런트엔드를 함께 반영해야 한다.

## 재현된 원인

1. 교육 조회 전에 공고/채용 문자열을 우선하는 경로가 있고, 교육 검색의 짧은 후속 주제가 명확한 상태로 보존되지 않았다. 모델이 chat을 반환하면 이전 체크리스트를 다시 응답에 붙였다.
2. 질문 중단이 별도 세션 설정이 아니었다. checking_required/preferred 단계에서는 일반 대화 이후에도 카드가 자동 재표시됐고, 단일 질문 화면은 자유 입력 전송을 막았다.
3. 소제목과 실제 조건이 동일하게 분리되고, 한 섹션의 전체 원문을 펼쳐 놓았다. 긴 소통·업무 태도 문장과 직무 조건이 섞여 읽기 어려웠다.

## 변경

- 명시적 채용/교육 전환과 교육 대화의 짧은 기술 후속 입력은 서버 규칙으로 구분한다. 교육 공고는 채용으로 취급하지 않는다. 둘 다 요청한 모호한 경우 무엇을 먼저 볼지 확인한다. 일반 대화의 의미 해석은 기존 모델을 사용하며 모든 문장에 대한 완전한 분류를 보장하지 않는다.
- profile.assistant_preferences.ask_assessment에 질문 허용 여부를 저장한다. 거절 시 즉시 카드를 중단하고 다음 턴·다른 공고 선택·실패 재시도에서도 현재 세션의 거절을 유지한다. 새로운 세션으로 자동 승계하지 않는다. 다시 허용하는 표현이나 재개 버튼으로만 재개한다.
- 거절 후 남아 있는 답변 요청도 서버가 체크 결과로 저장하지 않는다. 모델 문맥에 거절 상태를 전달하고 후처리로 역량 재질문을 억제한다. 거절 상태에서는 후처리 전 모델 부분 응답이 먼저 노출되지 않게 한다.
- 교육 상담 중 이전 역량 카드를 다시 붙이지 않는다. 교육 저장소 연결이 없으면 교육 요청으로 유지하고 채용 검색으로 대체하지 않는다.
- 소제목을 뒤따르는 원문 조건의 문맥으로 묶는다. 조건은 최대 5개씩 확인한다. 각 문항에 최대 180자 원문 기반 요약·분류를 표시하고 전체 원문은 펼쳐 볼 수 있게 보존한다. LLM이 지원조건을 임의 재작성하거나 삭제하지 않는다.
- 협업·업무 방식 조건은 별도 펼치기 영역으로 모은다. 기술이 함께 명시된 조건은 직무 조건으로 우선 분류한다. 접힌 문항도 답변 대상에 남고, 미답변은 미확인으로 저장하며 충족/미충족으로 추정하지 않는다.
- 자유 입력을 질문 중에도 열어두고 질문 그만하기·재개 버튼을 추가한다. 확인 완료 결과의 긴 원문도 요약과 펼치기로 바꾼다. 짧은 요약만으로 학위·경력 연수·또는/및 조건을 충족했다고 판단하지 않는다.

원문을 불필요하다고 간주해 영구 제거하지 않는다. 이미 답변한 기존 세션의 조건 ID·근거도 임의로 재작성하지 않으며 새 분리 방식은 새 공고 선택부터 적용된다. 긴 요약은 생략 표시가 있으므로 정확한 조건은 원문에서 확인한다. 세션·DB 구조 변경은 없다. 라우팅 프롬프트 버전은 conversation-preferences-v5로 기록한다.

## 검증

교육 공고·UI/UX 후속 주제·채용으로 명시 전환·동시 요청 확인, 질문 거절·다음 턴 유지·다른 공고 선택·오래된 답변 차단·명시적 재개, 모델 재질문 후처리, 소제목/조건 분리, OR와 경력 수치·연속 줄 보존, 20개 조건을 5개 단위로 끝까지 확인하며 모델 호출을 추가하지 않는 경로를 테스트했다.

백엔드 전체 186개 중 환경 의존 7개 제외 통과. 프런트엔드 기존 테스트 9개와 생산 빌드 통과. 실제 AWS 대화 및 브라우저 화면 검증은 배포 전후 후속 확인이 필요하다. 자동 분류 규칙 밖의 자연어는 계속 개선 대상으로 기록한다.
