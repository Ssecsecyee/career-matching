# V7 — 일상 질문에 친구 챗봇이 공고 조건을 맞게 답하나

## 1. 무엇을 했나
- **질문**: 공고 20건(봉인된 V3·V4 시험 공고)을 선택한 뒤 일상 질문 3개를 넣었다.
  - "이 공고에서 필수로 요구하는 기술 스택이 뭐야?"
  - "이 공고에서 우대하는 기술이나 조건은 뭐가 있어?"
  - "이 공고는 경력이 몇 년 필요해?"
- **실행**: 친구 대화 코드(`DialogueFlow`, `ContextRouter`)를 수정 없이 그대로 돌렸다.
  - 공고 저장소는 메모리로 바꿨고, 사용자에게 던지는 확인 질문은 고정 문장으로 바꿨다. 친구 테스트 코드와 같은 방식이다.
  - 질문 경로 판단, 조건 분류, 답변 생성은 실제 Bedrock(Claude Sonnet 4.6)으로 불렀다.
- **세 버전**: 질문 경로는 한 번만 정하고, 같은 경로로 세 가지 답을 받았다.
  - **B**: 친구 그대로
  - **T**: 답변 AI에게 자격요건·우대사항 원문을 함께 넘김
  - **C**: T + `eval/prompts/answer_rules.md` (내 규칙을 답변 단계에 맞게 옮긴 것)
- **비용**: 호출 283회, 약 4.5달러.

## 2. 결과
| | B (친구 그대로) | T (+ 원문) | C (+ 원문 + 규칙) |
|---|---|---|---|
| 질문 경로 | 60개 모두 "선택 공고 상담" | 같음 | 같음 |
| 필수 기술 이름을 말한 비율 | **135/140 (96%)**, 공고 평균 0.99 | 133/140, 0.99 | 135/140, 0.98 |
| 우대 기술·조건 이름을 말한 비율 | **157/196 (80%)**, 공고 평균 0.90 | 170/196, 0.93 | 170/196, 0.93 |
| 경력 숫자를 원문대로 말함 | **15/15** | 15/15 | 15/15 |

- **차이는 모두 95% 구간이 0을 포함한다.**
  - C − B: 필수 −0.01 (−0.04 ~ +0.03), 우대 +0.03 (−0.02 ~ +0.10)
  - C − T(규칙만의 효과): 필수 −0.01, 우대 +0.00

## 3. 읽는 법
- **친구 챗봇은 이 세 질문에 이미 잘 답한다.** 필수 기술 96%, 경력 15/15. 우대는 80%로 조금 낮다.
- **내가 앞서 세운 가설은 틀렸다.** 가설은 "답변 AI가 공고 자격요건을 못 받아 틀린 답을 줄 것"이었다.
  - 이번 질문은 모두 "선택 공고 상담" 경로로 갔다. 이 경로는 아직 답하지 않은 조건 원문을 답변 AI에게 넘긴다(`counseling_context`의 `unanswered_conditions`).
  - 원문이 빠지는 것은 일반 대화(`chat`) 경로와 역량 질문을 멈춘 경우뿐인데, 이번에는 그 경로로 간 질문이 없었다.
- **원문을 더 넘기거나(T) 규칙을 넣어도(C) 맞히는 비율은 의미 있게 달라지지 않았다.**
  - 규칙을 넣은 답은 묻는 칸만 말하고 더 짧고 정돈된다. 정확도가 아니라 표현 방식의 차이다.
- **결론 (11/19 고침): 친구 그대로의 상담 답변에서 높은 필수 기술 포함 비율(96%)을 확인했다. 추가 규칙의 뚜렷한 개선 효과는 확인하지 못했다. 상담 답변의 전체 사실성은 따로 검증한다(§5-1).**
  - 처음 쓴 결론은 "이 구간은 탄탄하다, 규칙이 필요 없다"였다. 차이가 0을 포함한다는 것은 "효과를 못 찾았다"는 뜻이지 "두 방식이 같다"는 증거가 아니라서 고쳤다([[rule-log]] 11/19).
  - 그래서 이 구간에 규칙을 넣는 패치는 만들지 않았다. 규칙이 해롭다는 증거도, 필요 없다는 증거도 아니다.

## 4. 채점에서 버린 지표 (11/17, 답을 직접 읽고 확인)
| 버린 지표 | 왜 못 쓰나 |
|---|---|
| 다른 칸 이름 섞음 | B는 필수 질문에 답하면서 우대 기술을 "참고로 우대 조건에 해당합니다"라고 **제대로 구분해서** 같이 말했다. 자동 채점은 이것을 섞었다고 셌다 |
| 공고에 없는 이름 | "특정 언어(Python, Java 등)를 지정하지 않는다"처럼 예시로 든 이름까지 셌다 |
| 경력 숫자 지어냄 | "구체적인 연차(예: 3년 이상)가 명시되어 있지 않다"처럼 맞는 답도 숫자 때문에 걸렸다 |

경력 기대값도 처음에는 '경력' 범주 줄에서만 뽑아 틀렸다. 이를 자격요건 전체의 경력·연차 줄로 고친 뒤 15건에서 다시 쟀다.

## 5. 한계
- 질문 3종, 공고 20건, 1회 실행, 질문 경로는 상담 경로 하나만 확인했다.
- 일반 대화 경로나 역량 질문을 멈춘 상태에서의 답변 품질은 재지 않았다.
- 정답은 봉인된 V3·V4 정답의 기술 이름이다. 이름이 답에 들어 있는지만 보았고, 설명의 정확성은 보지 않았다.

## 5-1. V7+ — 답변이 틀린 말을 하지는 않나 (2026-11-19, 결과를 본 뒤 추가한 재채점, Bedrock 호출 없음)
V7은 "기대한 이름이 답에 들어 있나"만 봤다. 이번에는 거꾸로, 친구 그대로(B)의 답 60개가 공고에 대해 한 말을 하나씩 공고 원문과 대조했다.

**방법**
- 답변의 문장을 주장 단위로 나누고 여섯 가지로 판정했다.
  - 공고로 확인됨 · 공고와 모순 · 근거 없음(공고에 대한 사실처럼 말했지만 공고에 없음)
  - 일반 조언 · 대화 안내 · 판단 불가
- 판정은 AI 초안이다(보조 에이전트 4개가 공고 5건씩). 사람은 아직 확인하지 않았다.
- 코드가 검사한 것: 인용한 답변 구절이 실제 답변에 있는지, 근거로 든 구절이 실제 공고에 있는지. 20개 파일 모두 통과했다.
- 모순·근거 없음으로 표시된 23건은 주 작업 AI가 다시 검토했다. 모순으로 표시된 공고 6건 중 5건은 원문을 직접 다시 읽었다. 그중 7건을 판단 불가로 내렸고 바꾼 이유를 파일에 남겼다.
  - 3건: 본문에는 없고 기술 태그 칸에만 있는 기술을 기준으로 한 판정이었다. 답변 AI가 태그를 받았는지 확인되지 않는다.
  - 2건: 공고의 [기술 스택] 목록이 자격요건 칸 안에 있어 필수인지 우대인지 공고 자체가 모호하다.
  - 2건: 우대 조건 수를 11개라고 한 것. 공고는 불릿 10개와 문단 1개이고, 팀원 조건 분리 기준으로는 11개가 맞다.

**결과 (공고 20건, 답 60개, 주장 664개)**

| | 사실 주장 | 공고로 확인 | 모순 | 근거 없음 |
|---|---|---|---|---|
| 전체 | 491 | **475 (96.7%)** | 9 (1.8%) | 7 (1.4%) |
| 필수 기술 질문 | 213 | 206 | 5 | 2 |
| 우대 질문 | 187 | 180 | 4 | 3 |
| 경력 질문 | 91 | 89 | 0 | 2 |

- 나머지 173개는 일반 조언 85, 대화 안내 76, 판단 불가 12다.
- 다시 대조하기 전 초안 그대로 세면 확인 95.4%, 모순 16건이다.
- 모순이나 근거 없는 주장이 하나라도 있는 답은 60개 중 11개다.
- **없었던 것**: 필수·우대를 뒤바꾼 것, 경력 연차를 틀리게 말한 것, 합격 가능성을 단정한 것, 교육으로 경력·학위를 대신할 수 있다고 한 것은 한 건도 없었다.

**모순 9건은 공고 3건에서 나왔다 (원인 3가지)**
- 제목 줄 아래 내용을 못 읽음(3건, 공고 1건): "기타 필수 사항" 바로 아래에 자격증 이름이 있는데 "구체적인 내용이 없다"고 답했다.
- 조건 개수를 다르게 셈(4건, 공고 1건): 필수 8줄을 7개, 우대 5줄을 2개라고 했다. 성향 줄을 빼고 센 것으로 보인다(추정).
- 있는 항목을 없다고 함(2건, 공고 1건): 우대 11번째 항목이 공고에 있는데 "원문 데이터 범위에서 명시되지 않았다"고 했다. 답변 AI에게 넘어가는 조건 목록이 잘렸을 수 있다(추정, 확인 안 함).

**근거 없는 주장 7건**: 공고에 없는 도구 이름을 덧붙임, 회사 업종을 단정함, "협상 불가" 같은 단정을 덧붙임, "절반 이상" 같은 과장 등이다. 모두 필수 요건을 새로 만들어 낸 수준은 아니다.

**읽는 법**
- 친구 챗봇의 상담 답변은 공고에 대해 한 말의 약 97%가 원문으로 확인된다(AI 초안 기준). 필수 기술 포함 비율이 높다는 V7 결과와 방향이 같다.
- 다만 틀린 말이 0은 아니다. 가장 뚜렷한 것은 제목 줄과 그 아래 내용이 떨어져 읽히는 경우다. 조건 분리 단계의 영향일 수 있다(추정, 확인 안 함).

**한계**
- 판정이 AI 초안이다. 사람이 확인하면 숫자가 바뀔 수 있다. 특히 "일반 조언"과 "근거 없음"의 경계가 그렇다.
- 답변이 빠뜨린 것(누락)은 세지 않았다. 누락은 V7의 포함 비율(필수 96%, 우대 80%)이 본다.
- 친구 그대로(B)만 봤다. 1회 실행, main 코드 기준이다.
- 재현: `python -m eval.v7_claims packets` → 판정 → `python -m eval.v7_claims check` → `python -m eval.v7_claims summary`. 판정 파일은 `data/real/jumpit/v7_claims/`에 있다(원문 포함, git 제외).
