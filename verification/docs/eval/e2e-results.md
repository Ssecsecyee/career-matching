### 2-1. 최초 오류 지점 (외부 검토 §14.4, 11/19 기록에서 정리 — 사후)

- 실패 3건의 최초 오류 단계가 모두 다르다(3·4·8). 한 구성요소만 고쳐서는 E2E 통과율이 크게 오르지 않는다는 뜻이다.

- **E03의 C2는 경계 사례다.** 원문 표기가 "Java/Kotlin"(슬래시)이다. 사람은 보통 "둘 중 하나"로 읽지만 공고가 밝힌 것은 아니다. 다만 사용자가 "Java만 한다"고 적었는데도 Kotlin을 필수 보완으로 제시했으므로 실패로 둔다.

## 3. 시나리오를 넘어 보인 것
**검색 조건이 말없이 빠진다**
- 실제로 필터로 적용된 것은 직무·지역·신입뿐이었다.
- 빠진 조건: E02 "Java", E03 "Java 또는 Kotlin", E06 "경력 3년 이상", E09 "경력 5년 이상".
- E06만 접힌 안내에 "경력 자동 필터는 적용하지 않았다"고 적혀 있었다. E09는 어디에도 안내가 없었다.
- 교육 검색(V6)의 "주말·입문·기초 미적용, 안내 없음"과 같은 패턴이다.

**"백엔드"가 글자로만 맞춰진다**
- 백엔드가 아닌 공고가 섞였다: 모바일 앱, AI 컴파일러, 인프라 운영(E01), 게임 개발(E08 부산 상위 3건), Java/Spring 공고(E04 Python 검색).

**간헐적 오류 응답**
- "요청을 처리하는 중 답변 구성을 확인하지 못했습니다"와 함께 버튼 2개만 나왔다.
- 2번 났다: E02의 교육 요청, E03의 첫 메시지. E03은 새 대화에서 같은 메시지를 다시 보내 진행했고, 재시도는 기록에 남겼다.

**조건 분해가 거칠다 (E04)**
- 자격요건 6개가 문항 1개로 묶였다.
- 라벨도 틀렸다: 필수는 "협업·업무 방식", 우대는 "경력"으로 붙었다.
- V3 실시간에서 잰 범주 라벨 문제가 실제 화면에서도 보인 사례다.

**화면 문제**
- 답변이 한 글자씩 매우 느리게 나오고, 40초 넘게 빈 화면인 경우도 있었다. "전체 보기"를 누르면 바로 보인다.
- 마크다운 오류: "~"가 취소선으로 처리돼 "5~7년"이 "57년"으로 보였고, "**"가 그대로 노출됐다.
  - 연차 숫자가 바뀌어 보이는 것은 사용자 판단에 직접 영향을 준다.

## 4. 잘 된 것 (치명 오류 없음)
- "모름"을 "미확인"으로 따로 세고, 미충족으로 처리하지 않는다고 밝힌다(E02·E05). V7에서 확인한 원칙이 대화 흐름에서도 지켜졌다.
- 우대 미충족이어도 지원 가능하다고 안내한다(E04).
- 교육으로 경력을 대신할 수 없다고 안내한다(E02·E06, V6 질의 19).
- 맞는 교육이 없으면 채우지 않는다(E07, V6 Kafka·Rust).
- 다른 사용자 정보 요청을 거절한다(E10).
