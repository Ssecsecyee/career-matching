# EDU-CARE 검증 통합 보고서 (2026-11-19, 종료)

## 0. 한 줄 요약
친구 챗봇(EDU-CARE)의 워크플로에서 검증이 필요한 7곳을 같은 모델·같은 데이터로 "친구 그대로 대 규칙·패치"로 쟀다. 그 결과는 세 가지다.
- 조건 라벨은 처음 보는 공고에서도 좋아졌다: 서비스 방식, 최종 패치로 +19.7%p.
- 우리 패치의 부작용(필수 조건 누락)을 배포 전에 잡아 코드 안전장치로 막았다.
- 운영 화면에서는 교육 추천이 자주 놓치고, OR 조건을 AND로 읽는 치명 오류가 1건 있었다.

**운영 서비스에 반영된 것은 아직 없다.**

## 5. 한계
- **평가자 한 명**: 범주 정답은 GPT 초안을 사용자가 검토해 만들었다(시험 27%, 새 공고 46% 수정). 초안에 끌리는 효과가 남는다. 팀원이 초안 없이 52줄을 따로 판정 중이다.
- **두 정답지의 기준 차이**: 새 공고 정답은 지침보다 "기술"을 좁게 잡았다. 그래서 화면 라벨을 주지표로 정했다([[labeling-guide]]).
- **표본**: 공고 20+20건, 점핏 한 출처, 백엔드만, 반복 3회. V6 20질의·E2E 10시나리오, 각 1회.
- **운영과 다를 수 있음**: 조건 라벨 파일은 GitHub 두 버전에서 같지만 운영 커밋은 모른다.
- **나눠 재지 않은 것**: 정답률 향상이 규칙 몫인지 짧은 번호 몫인지.
- **하지 않은 것**: 228줄 전체 처리 정답, V6 Hit@5·nDCG·검색 방식 비교, V4 논리 구조 정답, V4b 의도 분류, V5 동의어, V9 보안·공정성, 사용자 평가.
- **통계**: 공고 단위 짝 부트스트랩(4,000회)을 썼다. 줄 단위 McNemar 검정은 한 공고의 줄들이 함께 맞고 틀려 독립 가정이 깨지므로 쓰지 않았다(AI 판단).
- **사후 결정**: 시험 공고의 화면 라벨 채점, V6 0건 처리, 처리 정책 변경(소통 능력 줄)은 결과를 본 뒤였다. 각 문서에 사후로 표시했다.
