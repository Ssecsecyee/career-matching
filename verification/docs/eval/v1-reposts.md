# V1 — 같은 공고가 여러 번 들어가 있는가 (중복 공고 검증)

위치: 팀원 워크플로 **데이터 적재** 단계 ([[verification-handoff]] 검증 지도 V1)

## 1. 무엇을 막나
- 팀원 DB는 `UNIQUE (source, source_id)`만 막는다(`app/backend/database/schema.sql`). 점핏에서 **같은 공고를 새 번호로 다시 올리면** 다른 행이 된다.
- 팀원 검색(`repositories/elasticsearch_jobs.py`, `mysql_jobs.py`)에도 중복을 묶는 처리가 없다.
- 팀원 계획 문서(`docs/SKILL_DEMAND_TRAINING_STATISTICS_PLAN.md`)도 "재게시는 별도 중복 판정과 근거를 관리한다"고 적었지만 구현 전이다.
- 결과: ① 공고 건수·기술 수요 통계가 부풀려지고, ② 같은 공고가 검색에 동시에 여러 번 보인다.

## 2. 방법 (공통 검증 방식 [[verification]])
1. **코드가 제안**: 같은 회사 안에서 공고 쌍을 비교한다(`eval/v1_reposts.py`).
   - 본문 = 자격요건·우대사항 문장 집합. 겹침(Jaccard) ≥ 0.6이면 후보.
   - 종류: **repost**(제목 같음 = 다시 올림) / **career_variant**(제목이 신입·경력·연차 구간 말만 다름) / **location_variant**(지역 말만 다름) / **other_variant**(그 밖에 다름, 흔히 다른 직무에 본문을 복사).
   - 본문이 3문장 미만이면 제목이 완전히 같을 때만 repost.
2. **사람이 확인**: 확인 화면(`review_v1.py`)은 코드의 판단을 **보여 주지 않는다**. 사람의 답으로 코드 판단이 맞는지 잰다.
   - 본문이 조금 다른 repost 쌍: **전부**(9쌍)
   - 제목이 다른 묶음: 회사당 1묶음, 시드 20261113으로 **20묶음**
   - 시험용 정답셋 공고와 대화에서 이미 본 공고는 뺀다(블라인드 유지).
3. **채점**: 사람 답과 코드 판단의 일치율(종류별), "모르겠음"은 따로 센다. `python -m eval.v1_reposts --score`
4. **동시 노출**: 기준일에 마감 전(또는 마감일 없음)이고 closed가 아닌 공고를 "검색에 보임"으로 본다(팀원 마감 정책의 근사).

- 제목이 다른 묶음은 게시일이 있는 88묶음 중 **91%가 같은 날** 올라왔다. 한 회사가 같은 본문으로 연차 구간별 자리를 여러 개 낸 것이다(최대 10건 묶음).

**읽는 법**
- **묶는 것 자체는 맞다.** 코드가 같은 회사·같은 본문으로 묶은 29개 중 사람이 "다른 일자리"라고 한 것은 1개다. 제목이 다른 20묶음은 모두 "같은 일자리를 수준만 바꿔 낸 것"(경력 구간 19) 또는 "제목만 바꾼 같은 공고"(1)였다.
- **약한 곳은 종류 이름표.** 코드가 other_variant(다른 직무)라고 한 8묶음을 사람은 전부 같은 일자리로 봤다. 원인은 경력 단어 목록(`CAREER_WORDS`)이 좁은 것이다.

| 놓친 차이 | 묶음 수 | 단어 목록 보정으로 |
|---|---|---|
| 직급: 대리·과장, 대리급·과장급 | 2 | 고칠 수 있음 |
| 등급·직책: 중급·고급·팀장 | 1 | 고칠 수 있음 |
| 구간 끝말: "1~8년 미만" | 1 | 고칠 수 있음 |
| 학력: 학사↑·석사↑ | 1 | 고칠 수 있음 (사람은 '경력 구간'에 넣음 — 보기에 학력이 없었음) |
| 제목 말을 아예 바꿈: "Fullstack Developer" ↔ "개발PL", 제목에 "소프트웨어/" 추가 | 2 | 고칠 수 없음 — 본문·태그를 봐야 함 |
| 제목만 바꾼 같은 공고: "[대리급]" ↔ "실무경험자" | 1 | 고칠 수 없음 |

- **유일한 "다른 일자리"**: 같은 제목 뒤에 "전문연구요원"이 붙은 쌍. 코드는 꼬리만 붙은 제목을 같은 공고로 본다([[F-011]]의 남은 한계). 사용자 메모는 "다른 거라고 생각하긴 해야 할 듯..?"으로, **확정 전이다.**
- **사람 메모에서 나온 것**: 재게시 쌍의 옛 사본은 대부분 이미 마감된 공고였다. 그래서 검색 화면보다 **DB 건수·기술 수요 통계**가 부풀려지는 문제다. 3절의 판단과 같다.
- **주의**: 위 숫자는 단어 목록을 고치기 **전** 코드의 점수다. 같은 20묶음으로 고친 뒤 다시 재면 점수가 부풀려진다. 보정한 다음에는 아직 안 본 회사에서 새 표본을 뽑아 다시 확인한다.

### 4-3. 그래서 V1은 어디까지 하면 되나
팀원 서비스에 필요한 것은 **같은 일자리를 묶어 한 번 세는 것**이고, 이것은 47/49로 맞는다. 종류 이름표는 "통계에서 종류별로 다르게 셀 때"만 중요하다.

- **사용자 결정 (2026-11-20, [[rule-log]])**: 검색 화면은 수준(신입/경력/직급)·지역만 다른 공고를 **모두 따로 보여 준다**. 사용자에게는 다른 공고이고, 지역을 생략하면 정보 손실이다. **기술 통계에서만** 같은 본문 묶음을 한 번 센다.
  - 그래서 47/49의 "같은 일자리"는 "같은 본문으로 낸 같은 자리라서 통계에서 한 번 셀 대상"이라는 뜻이다. "지워도 되는 중복"이 아니다. 지워도 되는 중복은 재게시(259건)뿐이다.
  - **재게시(제목까지 같은 사본)는 검색에서 가장 최신 하나만 보여 준다** (사용자 결정 2026-11-20).
  - **지역별·수준별로 쪼갠 통계는 "같은 통계 범위 안에서 같은 본문은 한 번만 센다"** (사용자 결정 2026-11-20). 전체 통계는 1건, 서울·부산(신입·경력) 통계에는 각자 1건, 재게시는 어느 범위에서든 1건.
- **제목이 다른 묶음을 모두 한 번으로 센다면**: 이름표 오류는 결과에 영향이 거의 없다. 남는 위험은 진짜 다른 직무 2건(분석/설계 ↔ 개발, 전문연구요원)이 합쳐지는 것이다. → V1은 여기서 마무리한다.
- **"수준만 다름"만 한 번으로 세고 나머지는 따로 센다면**: other 판정이 대부분 틀리므로 지역 목록과 묶음 판정을 고친 뒤 3차 확인이 필요하다.

## 4-4. 중복이 기술 수요 그림을 바꾸나 (V1+, 2026-11-18, 모델 호출 없음)
같은 스냅샷(1,154건)에서 기술을 두 방식으로 세어 비교했다. 재현: `python -m eval.v1_demand`.

**결과를 보기 전에 정한 것** ([[rule-log]] 11/18)
- 기술 = 점핏 `tech_stacks` 태그. 앞뒤 공백을 지우고 대소문자를 무시한다. 추출 모델을 쓰지 않으므로 추출 오류가 섞이지 않는다.
- 묶음의 어느 한 공고에라도 태그가 있으면 그 묶음에 있는 것으로 센다.
- 대표 비교는 재게시(repost)만 묶는다. 제목이 다른 묶음까지 모두 묶는 것은 두 번째 비교로 둔다.

| | 행마다 셈 | 재게시만 묶음 | 제목 다른 묶음까지 묶음 |
|---|---|---|---|
| 세는 단위 수 | 1,154 | 895 (−259) | 739 (−415) |
| 상위 10개 기술 집합 | — | **같다** | **같다** |
| 상위 10개 중 순위가 바뀐 기술 | — | 2개 (Java 5위 ↔ AI/인공지능 6위) | 4개 (Java 5 → 8위, Git 8 → 6위 등) |
| 비중이 가장 크게 바뀐 폭 | — | 0.94%p (C 15.7 → 14.8%) | 2.15%p (Linux 21.7 → 23.8%) |

- **건수는 22.4% 부풀지만, 기술별 비중과 순위는 거의 그대로다.** 재게시된 공고의 기술 구성이 전체와 비슷하기 때문으로 보인다(추정).
- 그래서 중복 제거가 바꾸는 것은 "공고가 몇 건인가"와 "검색에 같은 공고가 겹쳐 보이는가"다. "어떤 기술이 많이 요구되는가"의 순위는 이 스냅샷에서는 거의 바뀌지 않는다.

## 7. 재현과 버전
- `python -m eval.v1_reposts`로 보고서와 쌍을 만든다.

- `python -m eval.v1_reposts --score --round N`으로 채점한다.
  - `at_review`: 뽑을 때의 코드 판단으로 채점. 공정한 점수다.

- 입력: 팀원 DB 스냅샷(읽기 전용 계정, `data/real/jumpit/snapshot.json`, git 제외). 사람 답: `eval/v1_review_labels_r{N}.json`(id와 답만).
